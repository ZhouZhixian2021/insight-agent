# @deepseek-ai/dsh-product-insight-source

[English](README.md) | 中文

## 概述

本包把获批计划转换为候选网页，获取完整正文并核对原文摘录。它对每个问题搜索一次、合并重复网址，在部分搜索或获取失败时保留成功结果；程序调用方还可显式发起补充搜索。产品预设提供公开搜索与网页读取服务。搜索摘要只用于发现网页，不作为证据；调用方负责持久化和模型使用。

<a id="use-this-package"></a>
## 使用本包

`discoverCandidatePages()` 在抓取前筛选候选来源、合并重复网址并保留逐查询失败。新计划以关注方向取代逐站白名单：官网仍是唯一固定域名，其余有效页面也入选并读取正文核对产品相关性，不再因域名未登记而被排除；历史计划仍按登记的发布方域名限制。单次搜索结果上限与最终候选数独立。`fetchProductPages()` 最多同时读取八个入选页面，先保存完整规范正文，再发布快照。计划未显式限制字符数时，清理后的 HTML 和 PDF 正文不再因 12000/48000 字符、16 MiB 或 200 页而被拒绝；历史显式字符额度仍生效。`splitProductPageText()` 保留用于历史固定窗口，新无字符额度计划由工作流按模型上下文容量处理。摘录与保存的全文核对，PDF 保留物理页码。传输资源保护仍可配置：默认响应 64 MiB、正文 16,777,216 字符；超出时记录失败，不静默截断后冒充完整。浏览器请求数和网络超时保护保留。

<a id="understand-the-implementation"></a>
## 实现说明

<details>
<summary>展开实现说明</summary>

首轮发现使用完整的获批候选页额度。获批发布方的搜索信息若提及产品名称开头的拉丁字母品牌，即使计划使用较长的描述性名称，也可进入有上限的正文检查；抓取后仍须通过来源与摘录核验。

[公开入口](src/index.ts)逐次搜索，某个提供方调用失败不会清空其他已结算结果。发现流程先筛选返回结果，再依次为入选和排除两组分配候选名额。首轮在每组内按获批问题顺序轮转，并沿用各提供方返回的排名。首轮查询由产品名称与该问题最显著的关键词组成，长度不超过 60 字符；计划范围不进入查询。达到候选页上限后，未接纳的新网址使对应查询标记为截断，已接纳的网址仍会关联所有匹配的问题。网址去重时移除片段和已知跟踪参数，保留可能影响页面内容的查询参数。缺口查询使用产品名称、原获批问题的关键词以及获批的版本和地区；关注方向计划在开放网络上检索并只接纳异站结果，历史计划仍针对网页最少的获批域名并只接纳该域名结果。数量相同时优先尝试尚未查询的域名。候选池满时，补搜入选页可以替换未入选页，也可以将同一网址提升为入选。已入选页无需重复获取。获批官网的页面进入有上限的正文检查。其他有效页面直接入选，用户点名站点带上该站点名称。未提及产品的有效网页也入选。搜索摘要和生成式回答都不是证据。[网页处理](src/page-content.ts)拒绝不完整和不支持的正文，将规范化文本绑定 SHA-256 内容身份，在不改写全文偏移的前提下拆分长页，为首轮提取按获批问题排列片段，提取长度受限的 HTML 发布方、发布日期、更新日期、地区和版本声明，并对照已保存全文逐条核对候选摘录。缺失或格式错误的声明保持未知；重复出现的摘录需要准确位置。[获取处理](src/page-fetch.ts)在获批的候选页范围内同时获取最多八个入选网页，被 403、405、429 或 503 拦下、或响应中没有可用内容类型的页面，会以浏览器式代理头经同一受限传输重试一次；仍被拦截则保留原始状态，仍无可用正文则报告最初的失败，并按候选顺序保存正文、记录成功或失败的快照。取消后停止派发，等待已开始的获取结束后返回。获取流程用 PDF.js 解析具有文本层的完整 PDF，在规范化正文中保存分页位置。已核验摘录保留准确偏移和物理页码。PDF 明确声明的发布方、产品版本、地区和来源日期沿用 HTML 的核验规则。HTML 初次提取超过获批正文上限时，获取流程按文档顺序保留完整的文章或主体区域，去掉导航、隐藏元素和媒体控件。抓取器返回的 Markdown 文本超限时，去掉行内链接和图片的目标地址，保留可见文字。转换后的文本仍超限时，可对同一个获批网址再读取一次原始网页。只有正文符合上限才保存，摘录偏移在这份规范化正文中核验。仍然超限的页面获取失败；`sameProductPageFacts()` 对比重新获取的正文与页面声明，不把新的获取时间和快照 ID 视为内容变化。

</details>

<a id="model-experience"></a>
## 模型体验

无直接模型体验：本包返回由调用方持有的来源记录和已核验摘录，不生成模型可见文本。

#### KV Cache effect

工作流可能把获取的正文交给模型；本包自身不构造模型请求。

## 已知限制与后续工作

<a id="known-limitations-and-deferred-work"></a>

- **文档提取限制** — PDF 需要可提取的文本层，并同时受 16 MiB、200 个物理页和获批正文字符数的限制。HTML 规范化覆盖常见语义标签和实体；复杂的动态页面需要浏览器或 DOM 提取适配器。超过获批正文上限的页面会获取失败。若不启用重叠，跨片段边界的摘录可能遗漏；产品工作流为最长 1,500 字符的摘录重复 1,499 个字符的上下文。
- **编排由调用方负责** — 调用方保存正文与记录、提供候选摘录，并记录模型请求。消费方将异站认定为独立发布方前，必须另行核实发布方归属。本包不运行产品工作流或生成报告。

<a id="dev-note"></a>
### 开发备注

<details>
<summary>展开维护说明</summary>

网页获取和摘录核对函数实现 C 在来源包中的交接；产品工作流和报告消费方仍需调用。

</details>

候选筛选只产生入选或排除两种结果。原先因相关性不明确而待核查的有效网页改为入选，历史待核查记录也可以读取正文；旧计划仍保留获批域名排除规则。产品相关性在取得正文后判断，不再要求搜索信息必须匹配产品全名。

计划前搜索得到的网址与计划中的具体官网页面先进入候选池，再合并后台搜索结果。指向站点导航的计划网址不入池，包括站点根路径、形如 `/sg/` 的纯地区前缀，以及支持、帮助、登录、账户、购物车、商店或搜索页。所有网址共用去重、来源筛选和获批候选页上限；交接网址关联全部获批问题，供后续正文取证判断。搜索摘要不作为证据。

搜索结果同样会带回站点导航，发现阶段在抓取前排除：账户、购物车与搜索页在任何主机上都排除；站点根路径、纯地区前缀与商店索引只在同一主机还有更深页面时排除，以免只有首页的产品失去唯一页面。商店索引之下的配置页保留，支持主机下的文章页同样保留。分配候选名额时入口页排在最后，内容页优先占用名额。
