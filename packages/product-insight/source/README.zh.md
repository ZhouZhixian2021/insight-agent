# @deepseek-ai/dsh-product-insight-source

[English](README.md) | 中文

## 概述

本包把获批计划转换为候选网页，获取完整正文并核对原文摘录。它按获批问题的检索目标分别搜索，汇总各来源的网址、去重并筛选，在部分搜索或获取失败时保留成功结果；程序调用方还可显式发起补充搜索。产品预设提供公开搜索与网页读取服务。搜索摘要只用于发现网页，不作为证据；调用方负责持久化和模型使用。

<a id="use-this-package"></a>
## 使用本包

计划获批后，`discoverCandidatePages()` 汇总官网地址、订阅源和网页检索返回的链接、标题与摘要。后台单条查询或单个订阅源最多提供 60 条线索，统一筛选后再按计划分配阅读名额。某个来源失败时，其他来源的结果继续参与筛选。`fetchProductPages()` 最多同时读取八个入选页面，先保存完整规范正文，再发布快照。计划未显式限制字符数时，清理后的 HTML 和 PDF 正文不再因 12000/48000 字符、16 MiB 或 200 页而被拒绝；历史显式字符额度仍生效。`splitProductPageText()` 保留用于历史固定窗口，新无字符额度计划由工作流按模型上下文容量处理。摘录与保存的全文核对，PDF 保留物理页码。传输资源保护仍可配置：默认响应 64 MiB、正文 16,777,216 字符；超出时记录失败，不静默截断后冒充完整。浏览器请求数和网络超时保护保留。

<a id="understand-the-implementation"></a>
## 实现说明

<details>
<summary>展开实现说明</summary>

新计划在 `searchQueries` 中为每个问题列出独立的短查询。多题共用同一查询时只请求一次。旧计划仍使用获批的 `searchTerms`，或由原问题生成查询。

[发现流程](src/index.ts)记录每条查询的结果。[候选池](src/candidate-pool.ts)按目标地址合并标题和摘要，排除登录页和重复的站点入口，再结合各题线索排序。各题轮流选择网页。同一道题里，产品相关网页的标题、摘要或网址路径点明了入选清单里还缺的材料时，该网页优先。多条查询共用的词和返回网址的查询本身都不足以判定匹配。一篇网页可兼顾多种材料，其余名额按相关性分配，每种材料不设配额。产品概览可以参与排序，无需预先关联所有问题。排除项只使用剩余位置记录诊断，不进入阅读。程序调用方明确发起的补搜沿用获批额度，可以替换排除项。推广位沿用自然结果的标记，[搜索解析](src/multi-search.ts)先按容器类名丢弃 Bing 与 Yahoo 的广告位，再读任何结果卡片。引擎连续失败达到阈值后按配置的冷却时长跳过，全部引擎都在冷却时恢复全量尝试，避免一轮调查失去唯一的来源。搜索摘要和生成式回答都不是证据。[网页处理](src/page-content.ts)拒绝不完整和不支持的正文，将规范化文本绑定 SHA-256 内容身份，在不改写全文偏移的前提下拆分长页，为首轮提取按获批问题排列片段，提取长度受限的 HTML 发布方、发布日期、更新日期、地区和版本声明，并对照已保存全文逐条核对候选摘录。缺失或格式错误的声明保持未知；重复出现的摘录需要准确位置。[获取处理](src/page-fetch.ts)在获批的候选页范围内同时获取最多八个入选网页，被 403、405、429 或 503 拦下、或响应中没有可用内容类型的页面，会以浏览器式代理头经同一受限传输重试一次；仍被拦截则保留原始状态，仍无可用正文则报告最初的失败。各页完成抓取后分别保存正文并释放名额。返回的快照、失败记录和图片按候选顺序排列。逐篇审核使用的 HTML 正文保留表格的行与单元格关系。恢复时也可识别旧快照的正文排版。取消后停止派发，等待已开始的获取结束后返回。获取流程用 PDF.js 解析具有文本层的完整 PDF，在规范化正文中保存分页位置。已核验摘录保留准确偏移和物理页码。PDF 明确声明的发布方、产品版本、地区和来源日期沿用 HTML 的核验规则。HTML 初次提取超过获批正文上限时，获取流程按文档顺序保留完整的文章或主体区域，去掉导航、隐藏元素和媒体控件。抓取器返回的 Markdown 文本超限时，去掉行内链接和图片的目标地址，保留可见文字。转换后的文本仍超限时，可对同一个获批网址再读取一次原始网页。只有正文符合上限才保存，摘录偏移在这份规范化正文中核验。仍然超限的页面获取失败；`sameProductPageFacts()` 对比重新获取的正文与页面声明，不把新的获取时间和快照 ID 视为内容变化。

</details>

<a id="model-experience"></a>
## 模型体验

无直接模型体验：本包返回由调用方持有的来源记录和已核验摘录，不生成模型可见文本。

#### KV Cache effect

工作流可能把获取的正文交给模型；本包自身不构造模型请求。

## 已知限制与后续工作

<a id="known-limitations-and-deferred-work"></a>

- **文档提取限制** — PDF 需要可提取的文本层，并同时受 16 MiB、200 个物理页和获批正文字符数的限制。HTML 规范化覆盖常见语义标签和实体；复杂的动态页面需要浏览器或 DOM 提取适配器。超过获批正文上限的页面会获取失败。若不启用重叠，跨片段边界的摘录可能遗漏；产品工作流为最长 1,500 字符的摘录重复 1,499 个字符的上下文。
- **编排由调用方负责** — 调用方保存正文与记录、提供候选摘录，并记录模型请求。消费方将异站认定为独立发布方前，必须另行核实发布方归属。本包不运行产品工作流或生成报告。

<a id="dev-note"></a>
### 开发备注

<details>
<summary>展开维护说明</summary>

网页获取和摘录核对函数实现 C 在来源包中的交接；产品工作流和报告消费方仍需调用。

</details>

关注方向计划对标题、摘要和路径统一判断产品和主题相关性。计划指定的具体官网页、资料稀少的官网或指定站点线索，以及这些站点上命中关注主题的页面，可进入正文检查。旧计划沿用获批来源名单。

历史会话的预搜链接与新结果一起筛选。订阅源和网页搜索发现同一目标地址时会合并，包括可识别的 Bing 新闻跳转链接。不同地区的路径和会影响内容的查询参数分别保留。

搜索结果同样会带回站点导航，发现阶段在抓取前排除：账户、购物车与搜索页在任何主机上都排除；站点根路径、纯地区前缀与商店索引只在同一主机还有更深页面时排除，以免只有首页的产品失去唯一页面。商店索引之下的配置页保留，支持主机下的文章页同样保留。分配候选名额时入口页排在最后，内容页优先占用名额。
