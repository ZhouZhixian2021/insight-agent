# @deepseek-ai/dsh-product-insight-workflow

模型输出未完成时记录结束类型。审核逐条接收有效判断；失败项保留诊断，不丢弃同批有效结论，也不单独阻止报告交付。

[English](README.md) | 中文

页面发布方、地区、版本、日期和来源变化只作限制披露；历史跨来源比较中的不确定或冲突同样不单独阻止交付。原文支持与引用完整性继续用于确定哪些陈述可以进入正文。

## 概述

失败操作保存在 Trace，报告披露逐次搜索结果、候选数量和覆盖边界。没有有效结论的问题标记未回答，缺少独立佐证不触发额外阶段或补搜。没有证据仍阻止生成报告；身份与引用错误、取消或报告生成失败仍影响交付。历史报告不会自动重新判定。

本包按获批的 `ProductPlan` 运行有界调查，串联网页发现、页面获取、原文摘录核验、语义支持审核、获批的问题缺口补搜和报告评估。产品预设宿主使用会话选定的模型与 Web 提供方启动会话所属后台任务。报告在带引用的结论旁披露实际搜索和网页获取范围。来源正文、完整阶段检查点、证据、比对、结论和报告结果写入会话。中断后再次明确调用启动工具，可从同一获批计划的最近检查点续跑；完成后由 `get_product_investigation` 读取结果。程序调用方也可提供自己的适配器。

<a id="use-this-package"></a>
## 使用本包

搜索结果识别和获批后台调查都使用会话选定的模型。模型调用重试仍使用原线路，不再切换备用模型。每次产品模型请求在 Session 请求事件中保存追踪 ID，并通过 `x-request-id` 发出；适配器诊断日志用同一个 ID 记录 HTTP 状态、响应及流首字节时间、流字节数和安全的错误码，不记录提示词或凭据。缺少追踪 ID 的旧请求事件仍可读取。

通过 `latestApprovedProductPlan()` 从持久化 Session 事件读取最新的原生或 PTC 明确批准结果，再用 `productPlanFromApproval()` 重建准确身份与获批计划；解析本身不授予执行权限。新计划最多允许 30 个候选网页，可不填写总耗时和每页正文字符上限；明确获批的额度仍须执行。未填写正文字符上限时，以模型容量、传输资源保护和取消信号处理完整的清理后正文。

<a id="understand-the-implementation"></a>
## 实现说明

<details>
<summary>展开实现说明</summary>

运行器先使用剩余获批补搜，再对已保存页面定点补读，使新抓取的页面也能使用补读额度。没有匹配片段时不消耗补读额度。模型给出的偏移错误时，只有摘录在所给片段中唯一出现才自动定位；重复或不存在的摘录仍被拒绝。

[审批交接](src/approved-plan.ts)复核已持久保存的明确批准。[运行器](src/index.ts)发现并获取网页，为新调查建立逐问题段落索引，由模型选择原文段落 ID；相邻上下文帮助理解条件，但不自动变为引用。证据保留全文偏移和补充摘录，旧检查点保留原有分段执行方式。传输失败按有界重试恢复，失败的模型输出可以拆分；有效子项独立保存。原文审核后仅为未回答问题使用获批补搜或补读额度，再进入报告综合，不执行独立佐证阶段。

[产品调查工具](src/session-tool.ts)在会话保存正文、证据、审核、结论、模型请求和检查点。恢复时重新检查网页，但页面变化或重新获取失败不会清除已保存材料；报告披露使用的是原始快照。取消仍会中断。匹配输入的已保存模型响应可以复用；重复启动已结算计划返回已保存结果。

</details>

<a id="model-experience"></a>
## 模型体验

### 产品证据提取

#### 模型看到什么

新调查的阅读模型接收按问题检索的原文段落 ID、原文及相邻上下文，选择支撑陈述的准确摘录；完整正文仍保存在会话中。语义审核检查陈述与摘录，综合写作使用核对后的材料，缺少材料时明确标记未回答。草稿与正式报告采用相同结构，正文引用必须对应提供的证据。

阅读保留机制、条件、版本和来源归属。写作解释实质内容，避免反复使用“某来源称”，同时保留厂商宣传的归属。段落提取遵守来源包的段落选择约束；不额外限制每题综合参考数及报告字节数。独立佐证不作为执行阶段。

#### Token 影响

每条查询请求最多 60 条合并搜索结果，最多保留 30 个获批候选网页。首轮提取没有每页固定证据数量上限；提取输出遵循所选模型线路容量，不再受产品专属 token 或响应字节上限约束。语义审核仍单独保留 8,192 token 和每批八条的限制。已知模型上下文容量时，序列化输入和预留输出均计入容量；线路未设置请求输出上限时，提取仅为这项检查预留 8,192 token，不把它设为请求上限。过大的提取、审核或综合任务会拆分；单项仍装不下时明确失败。搜索布局恢复中，每个引擎最多使用 1,024 输出 token。提供方超时、取消与有界重试继续生效。

网页段落证据提取不再设置额外的单次 60 秒截止时间。获批的整轮耗时上限、重试预算、提供方超时和明确取消仍然生效。

#### KV Cache effect

提取按问题选取网页段落，只发送选中的已保存原文；语义和跨来源审核每批最多处理八条记录。综合写作可按问题和证据批次拆分。每次请求与结果都保存计划身份供 Trace 关联；缺少身份的旧记录仍可读取，但不会猜测属于其他任务。

## 已知限制与后续工作

<a id="known-limitations-and-deferred-work"></a>

- **进程内任务** — 启动工具调用结束后，只要所属 Agent 仍在运行，任务会继续执行。进程重启后活动任务消失，已保存的任务记录显示为中断。同一获批计划可经再次明确调用，从已提交的检查点续跑；未成功落盘的模型响应可能需要重新调用。自动续跑和独立进度页面尚未实现。
- **复核范围** — 续跑重新获取已选网址，但来源变化或获取失败时仍保留原保存快照、证据和审核；报告注明依据历史内容，不代表网页当前状态。明确取消仍会中断续跑。
- **来源限制** — 域名未批准、地区/版本/日期不匹配和正文快照不一致只作报告披露，不单独判草稿。发现阶段仍在获取前筛选域名。没有语义支持或不能对应保存快照的陈述不进入已确认正文；没有支持结论的报告明确保留未回答问题。完全没有证据仍阻止报告生成。

<a id="dev-note"></a>
### 开发备注

<details>
<summary>展开维护说明</summary>

调用方须持久记录运行事实和模型请求，以便恢复调查决策。

</details>

产品模式自行注册后台任务控制器，不挂载通用任务完成通知。新计划批准后，在计划轮次结束时自动启动；拒绝或关闭审核不启动。`run_product_investigation` 保留用于用户明确要求续跑，`cancel_product_investigation` 用于明确要求取消；工具完成后结束本轮，不要求模型重写报告。重启服务并新建产品会话即可验证新预设。历史报告仍可读取，历史未完成计划不会被静默重启。

审核结果逐条接收，单条缺失或无效不丢弃同批有效结论，也不单独阻止交付；缺失记录在对应问题披露。审核可将证据关联到其他已批准问题，原始提取归属保留。综合模型在有依据的句子后给出证据标记，程序校验实际引用编号并生成编号脚注；聊天页面和 HTML 将其显示为可点击上标。旧报告的段尾引用不会自动重定位，需要重新生成。
