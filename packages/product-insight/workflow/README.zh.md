# @deepseek-ai/dsh-product-insight-workflow

[English](README.md) | 中文

## 概述

本包按获批的 `ProductPlan` 运行有界调查，串联网页发现、页面获取、原文摘录核验、语义支持审核、跨站结论比对、获批的问题缺口补搜和报告评估。产品预设工具使用会话选定的模型与 Web 提供方启动会话所属后台任务。报告在带引用的结论旁披露实际搜索和网页获取范围。来源正文、完整阶段检查点、证据、比对、结论和报告结果写入会话。中断后再次明确调用启动工具，可从同一获批计划的最近检查点续跑；完成后由 `get_product_investigation` 读取结果。程序调用方也可提供自己的适配器。

## 使用本包

先用 `latestApprovedProductPlan()` 从会话的持久事件中找出最新的原生或 PTC 明确批准结果，再将其准确 Markdown、身份和审核时间交给 `productPlanFromApproval()`。其中须有且只有一个 `product-insight-plan-json` 区块，包含产品名称、开发方、官网、范围、问题及明确的候选页与总耗时上限。新计划可批准 12,000 至 48,000 的 `maximumPageCharacters`，并分别批准不超过问题数量的 `maximumGapReads` 和 `maximumGapSearches`。省略某项缺口额度时跳过该操作。省略每页额度时仍按 12,000 字符执行。计划还可批准外部发布方的名称与域名，并要求地区、产品版本或最早来源日期。重放同一审批会得到稳定的产品和计划身份。也可调用 `runApprovedProductInvestigation()` 一步完成审批交接并启动运行器，同时提供单次搜索数量上限、提取方式身份、Web 搜索与获取、正文、网页、检查点、证据、结论和报告的持久存储、时钟、`proposeEvidence`、`reviewEvidence`、`compareClaim` 和 `saveVerification`。程序适配器可通过 `recoverEvidenceFailure` 返回 `'retry'`，将提取失败标记为可重试的临时错误，或返回 `true`，标记为可拆分的输出错误。`recoverReviewFailure` 和 `recoverComparisonFailure` 将输出错误标记为可拆成两个更小的请求。省略时跳过对应的恢复操作。可选检查点只对准确匹配的获批计划续跑；没有检查点则重新发现来源。适配器须在后续模型工作前保存完整检查点，并在所属会话记录模型可见请求。结果包含运行、发现和获取结果、已核验摘录、通过审核的来源限定结论、跨来源判断、待补问题、报告评估及阻止交付、草稿或正式交付决定。

<a id="understand-the-implementation"></a>
## 实现说明

<details>
<summary>展开实现说明</summary>

[审批交接](src/approved-plan.ts)从会话事件识别明确批准并校验结构化区块；仅解析待审计划不会授予审批。[运行入口](src/index.ts)复核审批，发现候选网页，获取入选页，将完整正文按 1,499 个代码单元的重叠设置切成有界片段，在全文偏移处核对候选摘录，去除相邻片段重复提出的同一证据，并在每段结束后保存已接受证据的检查点再进入审核。传输失败或单次请求超时可等待 500 毫秒，对同一窗口重试一次。符合条件的模型输出失败可把窗口拆成两个更短且重叠的范围。每个窗口在获批耗时内只走一种恢复路径。取消会终止重试等待，并在原检查点位置记录已用耗时。成功的子片段保留证据；无法恢复的范围使交付降为草稿。新调查按片段与获批问题的匹配程度安排每页的首轮提取。还没有核验摘录的问题优先轮到，未匹配的片段随后按原文顺序处理。版本 3 检查点记录未完成网页的派发顺序。版本 1 和 2 按原有片段布局和原文顺序续跑。[审核判定](src/claim-review.ts)要求每条摘录都有明确判断，只有 `supported` 才形成来源限定结论。失败的审核批次也可拆分一次；有效半批的判断和结论会保留，无法恢复的半批使交付降为草稿。若获批问题仍无准入结论，运行器可针对获批发布方域名为该问题补搜一次，在原页数与耗时上限内接纳新网页或新入选页，并提取和审核其证据。候选池满时，新入选页可以替换未入选页。[跨来源核对](src/claim-verification.ts)为每个问题选择一条关键结论，与该问题其他已准入陈述比对，并拒绝遗漏或虚构的判断。其他批次或半批失败时保留有效判断；核对未完成的问题仍交付草稿。[报告评估](src/report.ts)要求关键与支持来源来自不同网站和发布方，还检查搜索完成、引用有效、来源校验值及是否存在冲突或不确定比对。它呈现实际查询结果、候选及获取数量和截断情况，不把搜索摘要当作证据，也不暴露提供方错误原文。外部来源须符合用户批准的发布方域名及页面声明；计划明确要求的地区、版本和日期也须与页面声明相符，缺失值保持未知。有证据但未达标时保留带引用草稿。

[产品调查工具](src/session-tool.ts)只在明确批准的计划已持久保存后启动，并在所属会话记录规范化正文、网页身份与范围声明、已接受证据、准确的分段提取、审核及比对请求与响应、已准入结论、逐问题核验、完整检查点、草稿和运行结算。转换文本超限时，可通过已注册的 HTTP 提供方读取同一获批网址。[后台状态](src/background-run.ts)也随这些事实写入会话。中断后再次明确调用工具时，先核验已保存正文和证据，再重新获取每个入选网页。正文及发布方、日期、版本和地区声明均未变化时保留页面或片段游标；任何变化都会先清除依赖旧快照的证据、审核、结论与比对，再参与交付判断。重新获取失败会停止续跑，保留旧检查点供下次重试。相同输入的已落盘模型响应可以复用。获批耗时累计检查点记录的各次实际运行时间。重复执行已结算的获批计划会返回已保存结果；`get_product_investigation` 无需启动任务即可读取结果或最新状态。

</details>

<a id="model-experience"></a>
## 模型体验

### 产品证据提取

#### 模型看到什么

后台调查逐页发送规范化正文、来源网址及关联的获批问题。模型返回包含 `verbatimExcerpt`、`sourcedStatement` 和 `questionIds` 的 JSON 数组；摘录在输入片段内重复时还返回 `startHint`。工作流根据已保存的正文核对摘录，拒绝位置不明或不存在的文本。格式错误、超限或未正常完成的模型输出可在片段足够长时触发两个更小的请求。第二轮模型请求每批审核八条摘录及陈述，逐条返回 `evidenceId`、`verdict`、获支持的 `questionIds` 和 `rationale`。无效审核响应可触发两个更小的审核请求；只有 `supported` 且问题关联有效的陈述才成为低置信度 `ProductClaim`。缺口补搜前，获批的补读可从符合范围的已保存网页中选择与未回答问题词语最匹配的片段。新证据沿用原文核验和语义审核。检查点记录已结束的补读轮次并保留先前审核。获批的缺口补搜可为没有准入陈述的问题获取更多网页。跨来源核对后，关键结论缺少独立佐证时，可用剩余补搜额度查找另一获批发布方。新增网页沿用提取和审核流程。关键结论未变化时，工作流保留原有判断，只比对新准入的陈述。第三轮按每批八条比对各问题的关键结论与其他已准入陈述，逐条返回 `supports`、`contradicts`、`unrelated` 或 `uncertain` 及理由。无效比对输出可触发该批次的两个更小请求。网页正文和模型提议均是不可信资料。确定性交付检查通过时后台任务保存带引用的正式报告，否则保存草稿或阻止交付结果。启动工具返回任务 ID；Agent 可通过 `job_output` 查看进度，通过 `get_product_investigation` 读取结果。 报告通过交付检查后，会话工具向模型发送获批范围，以及每个问题的关键陈述、佐证陈述和相应原文摘录。模型为每个问题返回一段纯文本回答及两条证据 ID。工作流校验 JSON 和引用集合，并从已获取网页生成来源链接。输出无效时，使用相同证据和不含来源正文的诊断完整重生成一次。输出超限时要求缩短回答。派发或流式生成期间出现传输错误或超时时，等待 500 毫秒后重发同一份证据请求。三种恢复方式共用一次重试额度。用户取消或达到获批耗时上限时，停止等待和派发。综合失败时，报告保留带引用的调查记录作为草稿并说明原因。已判定为草稿或阻止交付时跳过综合。程序调用方可通过 `synthesizeReport` 启用综合。语义审核针对来源陈述，综合校验针对回答结构和引用。

阅读提示保留产品机制、部署与套餐条件、测试环境、例外和限制，并区分厂商宣称与测试证据。综合提示采用问题导向的连贯正文，不设每题 500 字限制，仍受完整响应的 token、字节和耗时预算约束。正文先回答问题；引用摘录、取证记录和原始交付诊断放在附录。草稿未执行综合时明确标注为来源陈述，不伪装成模型分析。现有审核、跨来源佐证和交付判定保持不变；每页八条摘录及每题两条综合证据的基线仍保留。

#### Token 影响

获批计划最多允许 12 个候选网页和 20 分钟。每个问题先搜索一次。获批的 `maximumGapSearches` 由无结论问题和缺少独立佐证的问题共用，每题最多补搜一次。无结论的问题优先使用额度。省略该额度的计划跳过补搜。每页正文按获批的 12,000 至 48,000 字符上限保存；旧计划未填写 `maximumPageCharacters` 时仍限制在 12,000。每次提取请求读取不超过 12,000 个 UTF-16 代码单元，并分配每页最多八条摘录的额度。新调查使用 1,499 个代码单元的重叠设置，因此 48,000 字符网页最多需要五次初始提取调用。排序沿用每个原文片段及其摘录额度。模型输出失败被分类后，原片段至少 3,000 个代码单元且有至少两个摘录名额时，可能再调用两个较小片段。重试沿用同一来源范围、问题和摘录额度。每页常规提取最多调用 12 次，包含重试和拆分后的请求。一次调查的补读调用最多为 `maximumGapReads` 次，包含重试。每个未回答问题最多选择一个已保存片段。遇到临时错误且仍有获批补读额度时，可对同一片段重试一次。每次发送不超过 3,000 个 UTF-16 代码单元，最多提出两条摘录，仍计入原有的每页八条摘录上限。每次调用最多输出 4,096 token 和 20,000 字节。每轮审核最多将 96 条已接受摘录分成 12 次初始语义审核；每个失败批次只拆分一次时，总审核调用不超过 36 次，每次最多输出 2,048 token。每轮最多五条关键结论可触发至多 60 次初始跨来源比对；失败批次各拆分一次时，总比对调用不超过 180 次，每次不超过 2,048 输出 token。每次模型调用限时 60 秒，获批总耗时上限可更早终止比对。请求和结果先写入会话，再用于后续判定。 综合生成在获批总耗时内最多调用两次，每次限制为 4,096 输出 token、20,000 字节和 60 秒。会话在派发前保存尝试序号，在使用结果前保存结算结果。续跑会复用匹配的已结算尝试，已记录的临时故障会直接进入第二次尝试。

#### KV Cache effect

提取请求按网页独立进行，语义审核与跨来源比对请求每批最多包含八条证据，均不重放会话对话。产品预设向 Agent 后续请求加入启动、读取结果和通用任务控制工具定义。 综合生成也使用独立请求，内容为获批范围、问题和选定摘录。

## 已知限制与后续工作

<a id="known-limitations-and-deferred-work"></a>

- **进程内任务** — 启动工具调用结束后，只要所属 Agent 仍在运行，任务会继续执行。进程重启后活动任务消失，已保存的任务记录显示为中断。同一获批计划可经再次明确调用，从已提交的检查点续跑；未成功落盘的模型响应可能需要重新调用。自动续跑和独立进度页面尚未实现。
- **复核范围** — 明确续跑会重新获取已选网址，保留匹配的来源快照及已核验的证据和审核。发生变化的来源重新提取，关键结论发生变化或候选证据新增时重新核对相应比对。新增产品、问题或网站须审核新计划；页面自报发布方仍不等于独立的归属证明。
- **页面声明不能证明归属** — 正式交付会核对获批域名、实际获取地址及页面自报发布方，但不能独立证明法律上的发布方归属、来源真实性或产品实际行为。Web 获取结果不含 HTTP 响应头；获取流程不读取 JavaScript 渲染的元数据。文本 PDF 的引用可跳转至物理页，缺失的 PDF 适用范围声明记为未知。专用报告页面仍需实现。
