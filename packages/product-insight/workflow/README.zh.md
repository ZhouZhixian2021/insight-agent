# @deepseek-ai/dsh-product-insight-workflow

模型输出未完成时记录具体结束类型。某批语义审核失败仍会影响交付，但不再阻止其他问题使用获批的缺口补读和补搜额度。缺少独立佐证只作披露，不再为此调用模型比对或补搜；原始来源资格检查仍保留。交付原因不重复列出同一未回答问题，跨站核对的一般局限保留在报告局限中。

[English](README.md) | 中文

页面发布方声明缺失或与登记名称不同，只在对应问题下提示，不排除来自已批准域名的证据。历史跨来源比较中的不确定或冲突同样只作披露；有原文支持的各方陈述仍可参与综合，并保留不同适用条件。原文支持、引用完整性、当前性、批准域名和明确范围检查继续保留。

## 概述

交付判断区分可用结论与调查完整性。失败操作继续保存在 Trace，报告按阶段汇总失败次数。检索披露保留逐次结果、返回与新增候选数量及已知停止原因；旧记录仅有截断标记而无细分原因时明确注明未知。没有有效结论的问题仍显示未回答。缺少独立佐证不再单独阻止交付，也不把官方声明当成独立实测。来源身份、语义支持、引用关联、内容过期、取消及报告生成失败仍影响交付。已保存的历史报告不会自动重新判定。

本包按获批的 `ProductPlan` 运行有界调查，串联网页发现、页面获取、原文摘录核验、语义支持审核、获批的问题缺口补搜和报告评估。产品预设宿主使用会话选定的模型与 Web 提供方启动会话所属后台任务。报告在带引用的结论旁披露实际搜索和网页获取范围。来源正文、完整阶段检查点、证据、比对、结论和报告结果写入会话。中断后再次明确调用启动工具，可从同一获批计划的最近检查点续跑；完成后由 `get_product_investigation` 读取结果。程序调用方也可提供自己的适配器。

## 使用本包

通过 `latestApprovedProductPlan()` 从持久化 Session 事件读取最新的原生或 PTC 明确批准结果，再用 `productPlanFromApproval()` 重建准确身份与获批计划；解析本身不授予执行权限。新计划允许最多 30 个候选网页，不填写总耗时与规范正文字符上限。历史计划中明确批准的额度继续生效。

<a id="understand-the-implementation"></a>
## 实现说明

<details>
<summary>展开实现说明</summary>

运行器先使用剩余获批补搜，再对已保存页面定点补读，使新抓取的页面也能使用补读额度。没有匹配片段时不消耗补读额度。模型给出的偏移错误时，只有摘录在所给片段中唯一出现才自动定位；重复或不存在的摘录仍被拒绝。

[审批交接](src/approved-plan.ts)从会话事件识别明确批准并校验结构化区块；仅解析待审计划不会授予审批。[运行入口](src/index.ts)复核审批，发现候选网页，获取入选页，将完整正文按 1,499 个代码单元的重叠设置切成有界片段，在全文偏移处核对候选摘录，去除相邻片段重复提出的同一证据，并在每段结束后保存已接受证据的检查点再进入审核。传输失败或单次请求超时可等待 500 毫秒，对同一窗口重试一次。符合条件的模型输出失败可把窗口拆成两个更短且重叠的范围。每个窗口在获批耗时内只走一种恢复路径。取消会终止重试等待，并在原检查点位置记录已用耗时。成功的子片段保留证据；无法恢复的范围作为限制披露，剩余有效材料仍可交付。新调查按片段与获批问题的匹配程度安排每页的首轮提取。还没有核验摘录的问题优先轮到，未匹配的片段随后按原文顺序处理。版本 3 检查点记录未完成网页的派发顺序。版本 1 和 2 按原有片段布局和原文顺序续跑。[审核判定](src/claim-review.ts)要求每条摘录都有明确判断，只有 `supported` 才形成来源限定结论。失败的审核批次也可拆分一次；有效半批的判断和结论会保留，无法恢复的半批使交付降为草稿。若获批问题仍无准入结论，运行器可针对获批发布方域名为该问题补搜一次，在原页数与耗时上限内接纳新网页或新入选页，并提取和审核其证据。候选池满时，新入选页可以替换未入选页。原文支持审核及获批的未回答问题补查后直接进入综合写作，不执行独立佐证调用或佐证补搜；恢复时仍可读取历史比对记录。[报告评估](src/report.ts)检查来源资格、引用有效、来源校验值及是否存在冲突或不确定比对。操作失败、检索受限、未回答问题和缺少独立佐证改为限制披露，不单独判为草稿。它呈现实际查询结果、候选及获取数量和截断情况，不把搜索摘要当作证据，也不暴露提供方错误原文。外部来源须符合用户批准的发布方域名及页面声明；计划明确要求的地区、版本和日期也须与页面声明相符，缺失值保持未知。有证据但未达标时保留带引用草稿。

[产品调查工具](src/session-tool.ts)只在明确批准的计划已持久保存后启动，并在所属会话记录规范化正文、网页身份与范围声明、已接受证据、准确的分段提取、审核及比对请求与响应、已准入结论、逐问题核验、完整检查点、草稿和运行结算。转换文本超限时，可通过已注册的 HTTP 提供方读取同一获批网址。[后台状态](src/background-run.ts)也随这些事实写入会话。中断后再次明确调用工具时，先核验已保存正文和证据，再重新获取每个入选网页。正文及发布方、日期、版本和地区声明均未变化时保留页面或片段游标；任何变化都会先清除依赖旧快照的证据、审核、结论与比对，再参与交付判断。重新获取失败会停止续跑，保留旧检查点供下次重试。相同输入的已落盘模型响应可以复用。获批耗时累计检查点记录的各次实际运行时间。重复执行已结算的获批计划会返回已保存结果；`get_product_investigation` 无需启动任务即可读取结果或最新状态。

</details>

<a id="model-experience"></a>
## 模型体验

搜索恢复使用当前会话模型，从实际渲染页面的链接中选择数字编号，每个来源最多 1,024 输出 token，并受搜索操作期限约束。使用结果前记录完整提示、页面观察、响应和失败。模型不能引入页面中不存在的网址。搜索摘要不会成为证据，选中的目标页面仍走正常获取与核验流程；发现阶段尚未保存检查点时，恢复运行可能重复识别。

### 产品证据提取

#### 模型看到什么

后台将完整规范正文、网址和获批问题交给阅读模型；能装入配置的上下文时整篇发送，超出时分段覆盖全部正文并保留全文偏移。原文摘录先与已保存正文核对，再进行语义审核。综合写作可以使用每题全部来源合格且审核通过的相关证据；缺少材料时明确说明未回答部分。草稿与正式报告采用同一写作结构。综合结果检查 JSON 和证据身份，每个批次在格式错误或临时故障后最多重新生成一次；取消会终止待执行工作。

阅读保留机制、实验条件、版本和来源归属。写作以实质回答开头，减少反复使用“某某称、某某表示”，同时保留厂商宣传和未经独立验证结果的归属说明。不设置每页摘录数量、摘录及陈述字符数、每题参考证据数、模型响应字节数或报告字节数的固定上限。原文支持的语义审核继续生效；独立佐证不再作为执行阶段。

#### Token 影响

每条查询请求最多 60 条合并搜索结果，按获批计划最多保留 30 个候选网页；上限不保证实际结果数量。抓取前先核对来源域名。新计划不设置总耗时截止时间，历史计划明确批准的截止时间继续生效。模型请求沿用所选模型的输出配置，不再额外压到产品专用的 4096/8192 token，并移除额外的 60 秒模型调用截止时间。已知上下文容量时，估算的序列化输入与预留输出必须装得下，必要时拆分提取、审核和综合请求；单项比对或综合证据仍装不下时明确失败，不截断后冒充完整输入。模型未披露上下文容量时由服务商校验。网络超时、取消、获批补查额度和有限失败重试仍保留，保存结果用于恢复与复用已接受证据。

#### KV Cache effect

证据提取按网页进行，可能分成多个容量适配请求。语义和跨来源审核仍按每批最多八条记录调度，不限制证据总数。综合写作包含所有合格引用，必要时按问题和证据批次拆分，每次请求及结果均保存。产品模型事件可选携带计划身份，供聊天 Trace 关联；历史记录缺少身份时仍可读取，不猜测关联到其他任务。

## 已知限制与后续工作

<a id="known-limitations-and-deferred-work"></a>

- **进程内任务** — 启动工具调用结束后，只要所属 Agent 仍在运行，任务会继续执行。进程重启后活动任务消失，已保存的任务记录显示为中断。同一获批计划可经再次明确调用，从已提交的检查点续跑；未成功落盘的模型响应可能需要重新调用。自动续跑和独立进度页面尚未实现。
- **复核范围** — 明确续跑会重新获取已选网址，保留匹配的来源快照及已核验的证据和审核。发生变化的来源重新提取，关键结论发生变化或候选证据新增时重新核对相应比对。新增产品、问题或网站须审核新计划；页面自报发布方仍不等于独立的归属证明。
- **页面声明不能证明归属** — 正式交付会核对获批域名与实际获取地址；页面自报发布方仅作披露，但不能独立证明法律上的发布方归属、来源真实性或产品实际行为。Web 获取结果不含 HTTP 响应头；获取流程不读取 JavaScript 渲染的元数据。文本 PDF 的引用可跳转至物理页，缺失的 PDF 适用范围声明记为未知。专用报告页面仍需实现。

### 开发备注

<details>
<summary>展开维护说明</summary>

调用方须持久记录运行事实和模型请求，以便恢复调查决策。

</details>

产品模式自行注册后台任务控制器，不挂载通用任务完成通知。新计划批准后，在计划轮次结束时自动启动；拒绝或关闭审核不启动。`run_product_investigation` 保留用于用户明确要求续跑，`cancel_product_investigation` 用于明确要求取消；工具完成后结束本轮，不要求模型重写报告。重启服务并新建产品会话即可验证新预设。历史报告仍可读取，历史未完成计划不会被静默重启。
