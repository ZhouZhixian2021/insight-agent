# @deepseek-ai/dsh-product-insight-workflow

模型输出未完成时记录具体结束类型。某批语义审核失败仍会影响交付，但不再阻止其他问题使用获批的缺口补读和补搜额度。关键来源缺少范围声明时，独立佐证不足仍可用剩余额度搜索另一获批发布方；补搜不能豁免来源资格检查。交付原因不重复列出同一未回答问题，跨站核对的一般局限保留在报告局限中。

[English](README.md) | 中文

## 概述

本包按获批的 `ProductPlan` 运行有界调查，串联网页发现、页面获取、原文摘录核验、语义支持审核、跨站结论比对、获批的问题缺口补搜和报告评估。产品预设宿主使用会话选定的模型与 Web 提供方启动会话所属后台任务。报告在带引用的结论旁披露实际搜索和网页获取范围。来源正文、完整阶段检查点、证据、比对、结论和报告结果写入会话。中断后再次明确调用启动工具，可从同一获批计划的最近检查点续跑；完成后由 `get_product_investigation` 读取结果。程序调用方也可提供自己的适配器。

## 使用本包

搜索结果识别和获批后台调查都使用会话选定的模型。模型调用重试仍使用原线路，不再切换备用模型。每次产品模型请求在 Session 请求事件中保存追踪 ID，并通过 `x-request-id` 发出；适配器诊断日志用同一个 ID 记录 HTTP 状态、响应及流首字节时间、流字节数和安全的错误码，不记录提示词或凭据。缺少追踪 ID 的旧请求事件仍可读取。

通过 `latestApprovedProductPlan()` 从持久化 Session 事件读取最新的原生或 PTC 明确批准结果，再用 `productPlanFromApproval()` 重建准确身份与获批计划；解析本身不授予执行权限。新计划最多允许 30 个候选网页，可不填写总耗时和每页正文字符上限；明确获批的额度仍须执行。未填写正文字符上限时，以模型容量、传输资源保护和取消信号处理完整的清理后正文。

<a id="understand-the-implementation"></a>
## 实现说明

<details>
<summary>展开实现说明</summary>

运行器先使用剩余获批补搜，再对已保存页面定点补读，使新抓取的页面也能使用补读额度。没有匹配片段时不消耗补读额度。模型给出的偏移错误时，只有摘录在所给片段中唯一出现才自动定位；重复或不存在的摘录仍被拒绝。

[审批交接](src/approved-plan.ts)从会话事件识别明确批准并校验结构化区块；仅解析待审计划不会授予审批。[运行入口](src/index.ts)复核审批，发现候选网页，获取入选页，新版按问题选择已保存网页的原文位置，旧版检查点才按重叠窗口分段，在全文偏移处核对候选摘录，去除相邻片段重复提出的同一证据，并在每个问题或旧版片段结束后保存已接受证据的检查点再进入审核。传输失败和请求超时在 120 秒内最多退避重试至五次请求；重试占用页面模型调用额度，不占用获批的缺口补搜额度。重试仍使用配置的产品模型。符合条件的模型输出失败可把窗口拆成两个更短且重叠的范围。每个窗口在适用的获批耗时内只走一种恢复路径。取消会终止重试等待，并在原检查点位置记录已用耗时。成功的子片段保留证据；无法恢复的范围使交付降为草稿。旧版分段调查按片段与获批问题的匹配程度安排每页的首轮提取。还没有核验摘录的问题优先轮到，未匹配的片段随后按原文顺序处理。版本 3 检查点记录未完成网页的派发顺序。版本 1 和 2 按原有片段布局和原文顺序续跑。[审核判定](src/claim-review.ts)要求每条摘录都有明确判断，只有 `supported` 才形成来源限定结论。失败的审核批次也可拆分一次；有效半批的判断和结论会保留，无法恢复的半批使交付降为草稿。若获批问题仍无准入结论，运行器可针对获批发布方域名为该问题补搜一次，在原页数上限与适用的耗时上限内接纳新网页或新入选页，并提取和审核其证据。候选池满时，新入选页可以替换未入选页。[跨来源核对](src/claim-verification.ts)为每个问题选择一条关键结论，与该问题其他已准入陈述比对，并拒绝遗漏或虚构的判断。其他批次或半批失败时保留有效判断；核对未完成的问题仍交付草稿。[报告评估](src/report.ts)要求关键与支持来源来自不同网站和发布方，还检查搜索完成、引用有效、来源校验值及是否存在冲突或不确定比对。它呈现实际查询结果、候选及获取数量和截断情况，不把搜索摘要当作证据，也不暴露提供方错误原文。外部来源须符合用户批准的发布方域名及页面声明；计划明确要求的地区、版本和日期也须与页面声明相符，缺失值保持未知。有证据但未达标时保留带引用草稿。

[产品调查工具](src/session-tool.ts)只在明确批准的计划已持久保存后启动，并在所属会话记录规范化正文、网页身份与范围声明、已接受证据、准确的分段提取、审核及比对请求与响应、已准入结论、逐问题核验、完整检查点、草稿和运行结算。转换文本超限时，可通过已注册的 HTTP 提供方读取同一获批网址。[后台状态](src/background-run.ts)也随这些事实写入会话。中断后再次明确调用工具时，先核验已保存正文和证据，再重新获取每个入选网页。正文及发布方、日期、版本和地区声明均未变化时保留页面或片段游标；任何变化都会先清除依赖旧快照的证据、审核、结论与比对，再参与交付判断。重新获取失败会停止续跑，保留旧检查点供下次重试。相同输入的已落盘模型响应可以复用。获批耗时累计检查点记录的各次实际运行时间。重复执行已结算的获批计划会返回已保存结果；`get_product_investigation` 无需启动任务即可读取结果或最新状态。

</details>

<a id="model-experience"></a>
## 模型体验

### 产品证据提取

#### 模型看到什么

工作流将按获批问题关键词排序的已保存网页段落及相邻上下文交给阅读模型。模型返回段落编号和其支持的陈述；程序从保存的原文复制最多三段准确引文，核对偏移与哈希。语义审核取得全部引文及上下文。搜索页面布局无法正常解析时，另用模型选择已观察到的链接编号；模型不能引入未观察到的网址，也不能把搜索摘要变成证据。综合写作使用合格且审核通过的材料，给出带引用的回答或明确缺口，并保留条件、版本、来源归属和不确定性。

#### Token 影响

每条查询请求最多 60 条合并搜索结果，最多保留 30 个获批候选网页。首轮提取没有每页固定证据数量上限；提取输出遵循所选模型线路容量，不再受产品专属 token 或响应字节上限约束。语义审核仍单独保留 8,192 token 和每批八条的限制。已知模型上下文容量时，序列化输入和预留输出均计入容量；线路未设置请求输出上限时，提取仅为这项检查预留 8,192 token，不把它设为请求上限。过大的提取、审核或综合任务会拆分；单项仍装不下时明确失败。搜索布局恢复中，每个引擎最多使用 1,024 输出 token。提供方超时、取消与有界重试继续生效。

网页段落证据提取不再设置额外的单次 60 秒截止时间。获批的整轮耗时上限、重试预算、提供方超时和明确取消仍然生效。

#### KV Cache effect

提取按问题选取网页段落，只发送选中的已保存原文；语义和跨来源审核每批最多处理八条记录。综合写作可按问题和证据批次拆分。每次请求与结果都保存计划身份供 Trace 关联；缺少身份的旧记录仍可读取，但不会猜测属于其他任务。

## 已知限制与后续工作

<a id="known-limitations-and-deferred-work"></a>

- **进程内任务** — 启动工具调用结束后，只要所属 Agent 仍在运行，任务会继续执行。进程重启后活动任务消失，已保存的任务记录显示为中断。同一获批计划可经再次明确调用，从已提交的检查点续跑；未成功落盘的模型响应可能需要重新调用。自动续跑和独立进度页面尚未实现。
- **复核范围** — 明确续跑会重新获取已选网址，保留匹配的来源快照及已核验的证据和审核。发生变化的来源重新提取，关键结论发生变化或候选证据新增时重新核对相应比对。新增产品、问题或网站须审核新计划；页面自报发布方仍不等于独立的归属证明。
- **页面声明不能证明归属** — 正式交付会核对获批域名、实际获取地址及页面自报发布方，但不能独立证明法律上的发布方归属、来源真实性或产品实际行为。Web 获取结果不含 HTTP 响应头；获取流程不读取 JavaScript 渲染的元数据。文本 PDF 的引用可跳转至物理页，缺失的 PDF 适用范围声明记为未知。专用报告页面仍需实现。

<a id="dev-note"></a>
### 开发备注

<details>
<summary>展开维护说明</summary>

调用方须持久记录运行事实和模型请求，以便恢复调查决策。

</details>

产品模式自行注册后台任务控制器，不挂载通用任务完成通知。新计划批准后，在计划轮次结束时自动启动；拒绝或关闭审核不启动。`run_product_investigation` 保留用于用户明确要求续跑，`cancel_product_investigation` 用于明确要求取消；工具完成后结束本轮，不要求模型重写报告。重启服务并新建产品会话即可验证新预设。历史报告仍可读取，历史未完成计划不会被静默重启。
