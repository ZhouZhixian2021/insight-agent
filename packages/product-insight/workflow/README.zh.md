# @deepseek-ai/dsh-product-insight-workflow

模型输出未完成时记录具体结束类型。某批语义审核失败仍会影响交付。缺少独立佐证只作披露，不再为此调用模型比对或补搜；原始来源资格检查仍保留。交付原因不重复列出同一未回答问题，跨站核对的一般局限保留在报告局限中。

[English](README.md) | 中文

页面发布方声明缺失或与登记名称不同，只在对应问题下提示，不排除来自已批准域名的证据。历史跨来源比较中的不确定或冲突同样只作披露；有原文支持的各方陈述仍可参与综合，并保留不同适用条件。原文支持、引用完整性、当前性、批准域名和明确范围检查继续保留。

## 概述

本包按获批计划执行网页发现、原文核对、语义支持审核和带引用报告交付。会话所属后台任务保存网页、证据、检查点、结论与报告；中断后可经明确请求从同一计划续跑。没有支持结论的问题会显示为未回答，供用户主动追问。交付状态依据证据和报告检查确定为正式、草稿或阻止；保存的报告披露搜索与网页获取范围。

<a id="use-this-package"></a>
## 使用本包

运行结算同时记录仍无准入结论的问题，供对话卡发起可选的后续调查。追问经新的计划批准后独立运行，不改写已结算报告。

通过 `latestApprovedProductPlan()` 从持久化 Session 事件读取最新的原生或 PTC 明确批准结果，再用 `productPlanFromApproval()` 重建准确身份与获批计划；解析本身不授予执行权限。结构化区块接受版本 1（逐站发布方白名单，历史计划继续生效）和版本 2（`focus` 必填，记录用户从固定词表确认的关注方向与自定义补充，站点只能作为用户点名的 `additionalSites`；版本 2 拒绝 `sourcePublishers`）。新计划允许最多 30 个候选网页，不填写总耗时与规范正文字符上限。历史计划中明确批准的额度继续生效。

<a id="understand-the-implementation"></a>
## 实现说明

<details>
<summary>展开实现说明</summary>

运行器完成首轮审核后直接评估报告，未回答问题可由用户发起新的调查。模型给出的偏移错误时，只有摘录在所给片段中唯一出现才自动定位；重复或不存在的摘录仍被拒绝。

[审批交接](src/approved-plan.ts)从会话事件识别明确批准并校验结构化区块；仅解析待审计划不会授予审批。[运行入口](src/index.ts)复核审批，发现候选网页，获取入选页，将完整正文按 1,499 个代码单元的重叠设置切成有界片段，在全文偏移处核对候选摘录，去除相邻片段重复提出的同一证据，并在每段结束后保存已接受证据的检查点再进入审核。传输失败或单次请求超时可等待 500 毫秒，对同一窗口重试一次。符合条件的模型输出失败可把窗口拆成两个更短且重叠的范围。每个窗口在获批耗时内只走一种恢复路径。取消会终止重试等待，并在原检查点位置记录已用耗时。成功的子片段保留证据；无法恢复的范围作为限制披露，剩余有效材料仍可交付。新调查按片段与获批问题的匹配程度安排每页的首轮提取。还没有核验摘录的问题优先轮到，未匹配的片段随后按原文顺序处理。版本 3 检查点记录未完成网页的派发顺序。版本 1 和 2 按原有片段布局和原文顺序续跑。[审核判定](src/claim-review.ts)要求每条摘录都有明确判断，只有 `supported` 才形成来源限定结论。失败的审核批次也可拆分一次；有效半批的判断和结论会保留，无法恢复的半批使交付降为草稿。原文支持审核后直接进入综合写作，不执行独立佐证调用或佐证补搜；恢复时仍可读取历史比对记录。[报告评估](src/report.ts)检查来源资格、引用有效、来源校验值及是否存在冲突或不确定比对。操作失败、检索受限、未回答问题和缺少独立佐证改为限制披露，不单独判为草稿。它呈现实际查询结果、候选及获取数量和截断情况，不把搜索摘要当作证据，也不暴露提供方错误原文。外部来源须符合用户批准的发布方域名及页面声明；计划明确要求的地区、版本和日期也须与页面声明相符，缺失值保持未知。有证据但未达标时保留带引用草稿。

[产品调查工具](src/session-tool.ts)只在明确批准的计划已持久保存后启动，并在所属会话记录规范化正文、网页身份与范围声明、已接受证据、准确的分段提取、审核及比对请求与响应、已准入结论、逐问题核验、完整检查点、草稿和运行结算。转换文本超限时，可通过已注册的 HTTP 提供方读取同一获批网址。[后台状态](src/background-run.ts)也随这些事实写入会话。中断后再次明确调用工具时，先核验已保存正文和证据，再重新获取每个入选网页。正文及发布方、日期、版本和地区声明均未变化时保留页面或片段游标；任何变化都会先清除依赖旧快照的证据、审核、结论与比对，再参与交付判断。重新获取失败会停止续跑，保留旧检查点供下次重试。相同输入的已落盘模型响应可以复用。获批耗时累计检查点记录的各次实际运行时间。重复执行已结算的获批计划会返回已保存结果；`get_product_investigation` 无需启动任务即可读取结果或最新状态。

</details>

<a id="model-experience"></a>
## 模型体验

原文支持审核每批 24 条，最多同时运行三批。审核输入包含摘录和陈述，不包含研究问题；获支持的陈述不要求审核模型分配问题编号。提取阶段的问题关联仅作发现线索。报告综合为每个问题提供全部符合条件且获原文支持的证据，由模型选择引用；无关材料可以不使用，无法回答时使用明确的无答案响应。结果记录对应请求序号，用于恢复和 Trace 配对。检查点保存已完成的其他批次，游标仅越过连续结束的批次；恢复时跳过已保存的审核，即使这些批次乱序完成。

### 搜索链接识别

#### 模型看到什么

常规搜索解析失败时，当前会话模型读取有界的搜索页观察，通过 `product/search-recognize` 只选择页面上显示的链接编号。搜索摘要和选中的链接仅用于发现网页，不作为证据。

#### Token 影响

每个来源的识别请求最多使用 1,024 输出 token。发现失败或尚未保存检查点时可能重复识别；常规解析成功则无需识别请求。

#### KV Cache effect

识别使用当前模型路由的独立请求，不重放会话对话。

### 产品证据提取与写作

#### 模型看到什么

阅读模型接收来源网址、获批问题及可装入上下文的完整规范正文；更长网页分段处理但不丢弃正文。摘录须对应已保存原文，语义审核只准入有支持的陈述。综合写作接收合格证据并引用其身份；未回答问题仍明确列出。

#### Token 影响

上下文容量不足时，工作流拆分提取、审核和综合请求。不再设置产品专用输出 token 上限或额外的 60 秒模型截止时间。[综合输出处理器](src/synthesis-output.ts)逐题校验，自动整理可明确识别的包装、引用格式、唯一编号前缀和冗余引用列表；E 编号映射回已保存的证据编号。部分回答出错、输出截断或请求失败时，保留已通过回答，仅对出错问题携带原稿和具体原因修复一次。请求故障且没有可用回答时，仅重试原请求一次。仍未修复的问题标明生成故障，不冒充材料缺失；覆盖状态允许自然描述资料缺口，不代表事实准确性认证。模型上下文限制和取消仍生效。

#### KV Cache effect

证据提取按网页进行，审核每批最多 24 条、三批并发。请求与响应均保存以供 Trace 和恢复，综合结果还记录已通过问题编号、修复原因及自动整理说明；没有这些可选诊断的历史结果从原始输出重新校验；用户主动追问须按新获批计划运行。

## 已知限制与后续工作

<a id="known-limitations-and-deferred-work"></a>

- **进程内任务** — 启动工具调用结束后，只要所属 Agent 仍在运行，任务会继续执行。进程重启后活动任务消失，已保存的任务记录显示为中断。同一获批计划可经再次明确调用，从已提交的检查点续跑；未成功落盘的模型响应可能需要重新调用。自动续跑和独立进度页面尚未实现。
- **复核范围** — 续跑重新获取已选网址，但来源变化或获取失败时仍保留原保存快照、证据和审核；报告注明依据历史内容，不代表网页当前状态。明确取消仍会中断续跑。
- **来源限制** — 关注方向计划的来源资格不再取决于域名是否登记：官网以外的页面按原文支持审核与来源类型使用，不再自动添加未登记站点提示；缺少独立佐证也不再追加固定提示，综合阶段依据材料内容说明具体限制。历史计划的域名未批准、地区/版本/日期不匹配和正文快照不一致只作报告披露，不单独判草稿。发现阶段仍在获取前筛选候选。没有语义支持或不能对应保存快照的陈述不进入已确认正文；没有支持结论的报告明确保留未回答问题。完全没有证据仍阻止报告生成。

<a id="dev-note"></a>
### 开发备注

<details>
<summary>展开维护说明</summary>

调用方须持久记录运行事实和模型请求，以便恢复调查决策。

</details>

产品模式自行注册后台任务控制器，不挂载通用任务完成通知。新计划批准后，在计划轮次结束时自动启动；拒绝或关闭审核不启动。`run_product_investigation` 保留用于用户明确要求续跑，`cancel_product_investigation` 用于明确要求取消；工具完成后结束本轮，不要求模型重写报告。重启服务并新建产品会话即可验证新预设。历史报告仍可读取，历史未完成计划不会被静默重启。

审核结果逐条接收，单条缺失或无效不丢弃同批有效结论，也不单独阻止交付；缺失记录在对应问题披露。审核可将证据关联到其他已批准问题，原始提取归属保留。综合模型在有依据的句子后给出证据标记，程序校验实际引用编号并生成编号脚注；聊天页面和 HTML 将其显示为可点击上标。旧报告的段尾引用不会自动重定位，需要重新生成。

获批会话入口将同一计划轮次中成功网页搜索的结构化结果传入候选发现，排除更早轮次、失败调用和计划提交后的结果。已有检查点保留原候选池，新启动的调查使用交接材料。模型自行书写的网址不视为已观察到的搜索结果。
