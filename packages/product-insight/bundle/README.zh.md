# @deepseek-ai/dsh-product-insight-bundle

新计划仅在预计来源网页提供对应声明时设置可选 `sourceCriteria`。宽泛的市场或发布时间范围留在调查范围和问题中，不当作网页元数据的逐字匹配标签。

[English](README.md) | 中文

## 概述

Web 模式选择器提供“产品洞察”。预设让用户确认调查方向及可选站点，再提交有候选页上限的计划供批准。批准后，后台搜索并读取网页、核对原文摘录，保存带引用的报告或列明缺口的草稿。对话卡展示进度，并可从未回答问题发起范围更窄的追问。预设使用独立的公开 Web 提供方；修改配置后须重启服务并新建会话。

<a id="use-this-package"></a>
## 使用本包

内置 Web 配置在学术接入包之后加载本包。开始新任务时选择“Product Insight / 产品洞察”。Agent 先做小范围初筛，再用一次提问同时确认关注方向（多选）与是否自定义站点；随后展示产品、范围、已确认方向、用户点名的站点、问题、资料办法，以及需要的地区、版本或来源日期要求、候选页上限及预期结果，并附结构化执行区块；用户可以批准或要求修改。关注方向来自固定词表（性能、对比、商业信息、上市与可获取性、兼容与生态、使用条件、支持与服务、风险与口碑），用户还能补充自定义表述。计划只约束方向，不登记网站：官网通过 `product.officialUrl` 成为唯一固定域名，其余页面由搜索发现并按方向相关性读取；`additionalSites` 只接收用户在对话中点名的站点。批准后，对话中会显示产品洞察进度卡：页面获取、逐篇提要与全文审核、报告生成，同时展示数量、未达标原因，并可展开阅读或下载已保存报告。批准后结束计划聊天轮次，由宿主启动已保存的计划；对话卡直接展示进度与正式保存的报告，不再通过完成通知唤醒聊天模型重写。任务中断后，再次明确调用可从同一获批计划已提交的工作续跑，包括已完成的逐篇审核；后续新调查仍先提交新计划。搜索与获取使用已配置的 DSH Web 提供方。

调查结算后，对话卡列出没有准入结论的问题。用户可将其中一题填入空白输入框，编辑后发送；已有草稿不会被覆盖。追问重新提交计划审核，获批后作为独立调查运行。没有结构化未回答记录的历史调查仍可阅读保存的报告，但不显示追问入口。

<a id="understand-the-implementation"></a>
## 实现说明

<details>
<summary>展开实现说明</summary>

[预设补丁](presets/product.patch.yml)声明产品调查指令、计划模式、提问工具、通用 Web 工具及产品工作流插件。计划段要求先调用一次 `ask_user_question`，在同一张卡里多选关注方向并询问是否自定义站点，再生成受限计划；提交审核前会检查 `product-insight-plan-json` 区块，版本 2 只接受词表内的方向 ID 与用户点名站点；工作流工具使用 Web 和模型服务前会再次核对持久审批。[Web 补丁](web.patch.yml)注入本功能自有的会话投影，通过 Conversation Definition/slot 边界折叠产品工作流的持久事件，使实时更新和历史会话回放呈现同一阶段卡，同时不修改公共框架提示词或页面组件。

</details>

<a id="model-experience"></a>
## 模型体验

通过产品预设插件间接影响模型，由这些插件提供计划指令和工具。

#### KV Cache effect

预设改变角色指令及可用工具；同一会话后续轮次沿用这套组合。

## 已知限制与后续工作

<a id="known-limitations-and-deferred-work"></a>

- 后台任务归属 Agent 且在当前进程中运行。进程重启后可将已保存状态识别为中断；再次明确调用可从该计划最近的完整检查点续跑。自动续跑仍需后续实现；当前阶段卡是 Session 会话投影，不是独立任务控制页面。正式状态要求异站支持且没有未解决冲突，并不证明发布方独立或产品实际行为。
- 关注方向放开后，外部站点不再由用户逐站审核：报告按已确认方向纳入未登记站点，并逐题披露其数量，读者仍须自行判断站点可信度。用户在提问卡里填写的域名通过 `additionalSites` 进入读取范围；没有可点选的站点列表，计划批准后也不能追加，需要取消并按新计划重来。
- 预设需要 Web 与基座接入包以及已配置的搜索提供方。

### 开发备注

<a id="dev-note"></a>

<details>
<summary>展开维护说明</summary>

产品会话展示保留在本接入包，持久调查状态保留在工作流包。新增展示字段时应扩展 Session 事件和投影，避免让阶段卡依赖 Agent 回复。

</details>

产品模式自行注册后台任务控制器，不挂载通用任务完成通知。新计划批准后，在计划轮次结束时自动启动；拒绝或关闭审核不启动。`run_product_investigation` 保留用于用户明确要求续跑，`cancel_product_investigation` 用于明确要求取消；工具完成后结束本轮，不要求模型重写报告。重启服务并新建产品会话即可验证新预设。历史报告仍可读取，历史未完成计划不会被静默重启。

生成报告的句内引用在聊天正文与导出 HTML 中显示为可点击上标编号，点击进入对应来源；Markdown 下载保留编号脚注。来源位置由综合模型提供并经工作流校验，历史段尾引用不自动重定位。

综合生成的 Trace 详情展示已通过问题编号、逐题校验失败原因和自动整理说明；未记录这些诊断的历史结果仍可读取。

聊天卡片默认收起报告正文，两个下载按钮始终可用。展开后宽表在预览内横向滚动。草稿和受阻的交付显示相应原因。聊天与 HTML 均折叠调查问题覆盖情况、证据附录和检索取证范围。旧地区价格表中可明确辨认的常规价和教育优惠价在查看和下载时分列，并保留原来的来源链接。

新报告使用 Markdown 章节标题。展示器也识别历史覆盖区标签，并继续禁用任意 HTML。
