# @deepseek-ai/dsh-academic-workflow

English | [中文](README.zh.md)

## Summary

extractPaperEvidence fills a first observed version hash before invoking the existing evidence extractor, retaining the version ID and historical objects. Conflicts return paused so callers can retain the record and continue other papers.

## Use this package

Progress types are exposed through the type-only `@deepseek-ai/dsh-academic-workflow/progress` entry. Browser consumers use this entry to avoid importing host Session declarations through the execution barrel.

Candidate selection accepts an optional review observer. It reports the bounded model-review plan and each settled paper separately from the screening stage's deduplicated-work total, so clients can show review progress without counting an unreviewed work as model-approved.

The workflow maps each full-text candidate observation into the owning paper activity. Candidate starts publish `fulltext_fetch` with one-based attempt counts, a failed candidate with another candidate available publishes `waiting_retry` and its classified failure, and an accepted HTML or PDF publishes `fulltext_parse` before evidence extraction begins. Cancellation publishes a cancelled paper fact before the run settles.

`PaperEvidenceGenerator` accepts an optional A-owned progress observer without changing the evidence package's `EvidenceGenerator`. `createModelEvidenceGenerator()` publishes one-based batch positions, publishes attempt starts and settlements only after their `academic/evidence-request` or `academic/evidence-result` record is durable, and publishes `waiting_retry` after a bounded retry decision. Timeouts, output limits, incomplete output and invalid output use the shared sanitized failure codes. `extractPaperEvidence()` publishes accepted and rejected source-validation counts before the paper settles. Observer failures never change model execution, validation or the final research result.

Warning admission does not satisfy the replenishment stop condition. After the candidate pool or inclusion cap is exhausted, `continue_with_warning` permits a limited draft from positive usable evidence; `stop_for_review` blocks synthesis. Warning drafts return `synthesis.status=partial_success` and host-owned reasons. Cancellation and zero usable evidence never start synthesis.

`includedWorkTypes` filters `WorkVersion.versionType`: `preprint`, `accepted_manuscript`, or `version_of_record`. Conference and journal categories are not version states. `allowPreprints: false` takes precedence. The pipeline also rejects adapter-selected versions outside the approved list before fetching; venue labels do not determine eligibility. `validateResearchBriefRequirements()` exposes the shared analysis check for plan review callers.

The formal entry admits evidence and invokes question synthesis with the Session model; its optional synthesisModel supplies independent generation controls for final synthesis. Paper extraction can retry output-limit exhaustion plus configured `TRANSPORT` and `TIMEOUT` failures, reusing the same parsed paper request without repeating search or acquisition. Final synthesis can separately retry configured `TRANSPORT` and `TIMEOUT` failures with exponential backoff, reusing the admitted evidence without repeating search, acquisition or extraction. Output-limit exhaustion consumes at most one recovery attempt whose smaller request retains approved questions, paper identities and verified excerpts while removing duplicate version, locator and card data. A second output-limit failure stops with `SYNTHESIS_MODEL_OUTPUT_LIMIT`; it never repeats the compact request. When `retryInvalidOutput` is enabled, a settled response rejected with `SYNTHESIS_INVALID_MODEL_OUTPUT` can consume another bounded attempt that regenerates the entire JSON from the same full or compact admitted input plus a source-text-free parser diagnostic. It never patches or reinterprets the rejected response. `academic/synthesis-request` records each exact request; `academic/synthesis-result` records every attempt's raw output, usage and rejection diagnostics. Partial paragraph acceptance is logged as `partially_validated`; all rejected paragraphs produce `failed` with `SYNTHESIS_NO_VALID_STATEMENTS`. Earlier events and failures before JSON parsing omit `rejectedStatements`. The Remote returns `partial_success` plus rejection reasons and a draft when valid paragraphs survive; no valid paragraphs means no report. Structurally invalid responses after the configured attempt limit, insufficient evidence, exhausted retries or cancellation also return no report. Durability failures stop the run. No template fallback, automatic semantic repair or weakened references are used.

Pass the reconciled WorkVersion, successful EvidenceExtractionInput, an explicit boolean indicating historical content or evidence, an EvidenceGenerator, and optional cancellation signal. First observation requires not_extracted and no historical binding; matching hashes reuse the version. For extracted results, pass version and evidence together downstream instead of the original unfilled version.

paused contains work and version IDs, old and new hashes, source URL, acquisition time, and a machine-readable reason. Paused papers never invoke the generator, overwrite conflicting content, or mint a version. Generator errors and cancellation propagate to the caller rather than becoming hash conflicts.

Returned paper records share readonly references; they are not deeply frozen or durable snapshots. No invariant companion is published because this library has no registrations or independently maintained runtime service observations; the model adapter dispatches immutable request data read directly from its persisted Session event, and call-time checks verify storage correspondence.

## Bounded research draft

`planCandidateBatch()` is the Q5 decision boundary between B's ranked candidates and A's full-text workflow. It preserves the authoritative P0/P1/P2 order, selects an explicitly configured first batch, then prefers unscheduled candidates whose reviewed question matches address uncovered or partial questions. When no ranked candidate can fill the remaining need, it returns the exact Brief questions for an evidence-gap search instead of inventing a query. It returns stable stop decisions for target and coverage completion, inclusion limits, saturation, search and candidate limits, elapsed time, cancellation, review, and exhaustion. A batch counts toward evidence saturation only after at least one paper yielded usable full text; failed downloads leave remaining ranked candidates eligible for scheduling. The function is pure and replayable; callers persist its inputs and completed batch facts before scheduling network or model work. Batch sizes are required caller policy, not hidden package constants.

Ranked scheduling carries the reviewed `CandidateAssessment` values beside the authoritative ranking. `runResearchDraft()` publishes complete `AcademicQueryWorkflowObservation` snapshots when ranking, coverage, batch decisions, batch settlements, gap rounds, or the terminal stop state changes. Each snapshot contains one run identity, a monotonic run-local sequence, the exact plan and Brief version, joined works and versions, authoritative queues, completed rounds, absolute batch facts, current question coverage, and the recorded stop decision. Browser type consumers import these fields through the type-only `@deepseek-ai/dsh-academic-workflow/query-workflow` entry. The latest snapshot is retained in `DraftPipelineResult.queryWorkflow`; a legacy selector without ranked scheduling leaves it absent. Observer failures cannot change research settlement.

When `PaperSelectionResult.candidateScheduling` is present, `runResearchDraft()` executes the selected full-text candidates one scheduler batch at a time. After each completed batch it rebuilds question coverage only from source-validated evidence whose run-specific `EvidenceQuestionLink` names that exact approved question, counts independent supporting works, and asks the scheduler for the next action. Candidate-level `matchedQuestions` can schedule a likely relevant paper but never proves evidence support. Uncovered and partial questions retain explicit structured gaps. Candidates without a currently resolvable full-text handoff do not consume the bounded Q5 queue. A requested evidence-gap search ends the current draft pass with an explicit limitation; executing that new retrieval round and persisting batch decisions for Session recovery remain deferred.

Candidates start and settle in selection order, with up to `paperConcurrency` acquisitions/extractions in flight (omitted means 1). After two consecutive papers with extraction transport errors or timeouts, the limit for new starts decreases by one to a minimum of one; two consecutive papers without those failures restore one slot, up to the configured limit. Work already started continues. An earlier slow candidate can delay ordered settlement and replenishment. Each unsettled candidate reserves one inclusion slot; usable evidence plus reservations cannot exceed the approved inclusion cap. Exclusions, pauses, failures and empty evidence release their slots. After each settlement, evidence admission checks the independent-work and full-text minimums. When those minimums and `targetIncludedWorks` are satisfied with `stopWhenEvidenceRequirementsMet` enabled, no new paper starts; already-started papers finish, so evidence may exceed the target within the inclusion cap. Cancellation stops new work and joins active tasks; durable logging failure aborts siblings and rejects after joining them. Coverage distinguishes evidence sufficiency, inclusion cap, selector truncation and candidate exhaustion, not downloads alone. Queries and requirements are unchanged.

runResearchDraft accepts an approved Brief, one to three ordered explicit queries with their approved `academic` and/or `web_discovery` channels, and synthetic disclosure. The query count must also fit the Brief's `maximumSearchRounds`. It runs the queries sequentially, then orders merged ingestion → version selection → per-paper full-text parsing and extraction → analysis → an evaluated draft report. Selection admits one version per work and is fully checked before acquisition.

`executeHybridSearch()` is the policy-aware discovery unit for one approved query. It starts direct Academic search and DSH Web discovery together, identifies DOI/arXiv/ACL/PMLR/CVF references from bounded Web candidates, removes exact repeated references, applies the approved verification-provider list and attempt limit, and admits only verified works to the Academic batch. Repeated references use one verification attempt but retain every discovery URL with its verification Provider. Exact identifiers merge direct and verified records before the candidate bound applies to distinct works; every retained work keeps its separate versions, so the returned record count may exceed `maxResults`. One channel or reference failure retains successful sibling results; caller cancellation aborts the operation. The returned observation keeps Academic records, Web URLs, identified references, verification attempts and outcomes as separate counts for the later Remote projection. The caller supplies all four operations explicitly, so Provider lookup remains in Academic Source and generic Web access remains in `ctx.web`.

Callers supply search, selectPapers, fetcher, generator, synthesize and now. search returns `AcademicSourceSearchBatchResult` from `ctx.academicSource.searchAll()`, and fetcher can adapt ctx.web.fetch. `selectPapers` may return a `PaperSelectionResult` directly or asynchronously and receives the run's cancellation signal, so a caller can settle model-backed candidate review before ranking. `selectResearchPapers()` applies deterministic version, date, work-type, retraction and preprint rules through a provider-owned full-text resolver; its `PaperSelectionResult` records whether the candidate selector omitted another eligible paper. Generator and clock are explicit; this library reads no credentials, creates no network client and introduces no generic scheduler.

Callers may also provide `onProgress`. The workflow then publishes complete, monotonically sequenced run-local snapshots for retrieval, screening, full-text work, evidence extraction, analysis and report generation. A query activity carries its approved channels before execution, including when Web discovery fails. Ingestion observations come from the ingestion package and distinguish merged work identities, merged version records, retained versions and suspected duplicates. Concurrent paper activities carry work and version identities. Each Academic Source provider emits a running activity when its request starts and a success, failure or cancellation activity when it settles; the workflow stamps those facts with its query position and clock. The hybrid orchestrator publishes the same lifecycle around Web discovery, aggregate reference identification, and every bounded reference verification; operation names and one-based verification positions keep these facts distinct from direct Academic search. Successful papers and validated evidence survive sibling failures, and cancellation retains all counts committed before the terminal cancellation snapshot. Report generation publishes `evaluation` before quality checks and `rendering` before Markdown assembly; model synthesis remains part of the analysis stage. Subscriber exceptions are contained and cannot change research settlement. Model-internal batch indexes and retry indexes remain `null` until their owning adapter publishes those facts. These snapshots do not include `sessionId` and are not a Remote stream; the Controller owns that projection.

Each query uses the same candidate bound. Completed query batches are merged round-robin so an earlier query cannot consume the global bound alone, exact identifiers are deduplicated, and all returned works enter preliminary date, version-state and full-text-URL screening. Only eligible works consume the global candidate allowance, bounded by `maximumCandidateWorks` and the request bound. URL resolution does not download or guarantee parseable full text. Per-query discovery and verification bounds still apply before results reach this workflow. `coverageSummary.deduplicatedWorks` records the returned records after cross-query deduplication but before the aggregate run applies its global bound; `academicWorkIds` contains the validated selected candidates and stays empty if the run stops before selection. Selection returns the eligible candidate pool under `maximumCandidateWorks`; processing stops at `maximumIncludedWorks` works with usable evidence. Unapproved input, too many queries, duplicate selected works, unknown versions and excluded/retracted selections reject. A failed source batch does not block a later explicit query; configuration or unrepresented search errors still reject. Hash conflicts return pauses; model scope exclusions retain their reason without contributing evidence. Acquisition or extraction failures retain the version and failed stage while other papers continue. Known extraction failures are classified without exposing model output: invalid model JSON/content is `parse_failed`, missing model budget is `invalid_request`, incomplete model output is `upstream_error`, and other extraction failures are `unknown`. The terminal `RetrievalRun` combines source and paper failures, deduplicated and included work counts, successful full-text acquisitions, called providers, actually started queries, and explicit truncation reasons. Reports disclose the same incomplete-coverage observations without claiming complete coverage.

Output status=completed means only that this pass finished, not that research or review is sufficient. `retrievalRun.status` independently reports success, partial success, or failure from included works and recorded failures; an all-source failure therefore returns a blocked draft with a failed retrieval run. report always uses draft mode and empty semantic reviews; report.evaluation carries quality status. Cancellation returns cancelled with completed papers, failures, observed coverage, and no report. Configuration and unrepresented search failures reject. Callers own durable model/network records and cancellation; a non-null Plan maximumElapsedMinutes adds a deadline shared by search, extraction and synthesis.

The Academic Controller mounts the hybrid executor for approved version-3 and version-4 queries and retains the Academic-only legacy path. `DraftSearchResult.hybridObservation` travels through the pipeline into optional `hybridSearch` run facts. Completed queries retain observations; interrupted queries appear only in RetrievalRun limitations and started queries. Counts of admitted records, exact merged records and distinct works are settled from ingestion before the run-wide work cap. Original contributions remain in the observation before per-query version reconciliation, so merging the same version does not erase its duplicate count. Duplicate references and records excluded by per-query bounds are not work merges. The Controller projects these facts without returning raw Web content. Automatic query expansion, cross-run recovery, abstract fallback and final publication remain outside this pass.

## Model response validation

`parseScopeDecision(text)` validates an independent `included`, `excluded`, or `needs_more_context` decision and its reason. `parseFocusedEvidence(text)` validates at most six short evidence entries with exact excerpt proposals, question indexes and one of six card sections; it constructs card items with section-specific fields marked `not_extracted`. Extraction maps question indexes to the approved questions and rejects out-of-range relations per draft. Unknown fields, invented identities and malformed output throw EvidenceError with code EVIDENCE_INVALID_MODEL_OUTPUT. The exported `parsePaperModelResponse(text)` and `parseEvidenceDrafts(text)` continue to validate combined JSON for callers that supply it; the Session-backed generator uses the separate parsers. Diagnostics identify a field path without copying response content.

The model has no producer-owned failure IDs, so failed availability is rejected; unknown, not_applicable and not_extracted remain available for absent information. B retains source-index bounds and exact excerpt checks. Parsing alone does not verify semantic support, stream completion or input budgets. Callers must reject incomplete model streams before parsing and preserve raw responses in their own durable records; this function neither calls a model nor records a Session.

## Session-backed model extraction

Paper settlements distinguish `extracted`, `partially_extracted`, and `extraction_failed`. Accepted records from a partially extracted paper participate in analysis with their original provenance; rejected drafts never enter cards or report citations. A paper with only rejected drafts remains visible but contributes no included work. Each affected paper contributes one `extract_evidence` failure operation, irrespective of the number of rejected drafts; per-draft indexes and reasons remain in `evidence.rejectedDrafts`. Coverage and report limitations disclose accepted and rejected counts. This does not add model retries or relax whole-response JSON validation; JSON `validated` is distinct from exact-source verification.

Bind `createModelEvidenceGenerator(ctx, session, config, policy)` to a live Session with an active persistence writer, explicit `LlmCallConfig`, and a positive `maxAttempts`. The context requires llm, sessions, sessionPersistence and tokenMeter. The configured provider resolves its model capacity and output cap; missing capacity or cap fails that paper before dispatch. The generator first reviews scope using the first ordered evidence batch; exclusion stops extraction, and insufficient context pauses the paper without counting it as excluded. `inputBatchTokenLimit` partitions ordered source segments by the complete framed evidence-input estimate; an oversized individual segment is split with `inputBatchOverlapCharacters`, and local indexes are mapped back before source verification. `attemptTimeoutMs` bounds each scope or evidence attempt. Output-limit and provider-reported transient failures may retry within each operation. When a local evidence deadline expires and `maxAttempts` exceeds one, the generator replaces that batch with two smaller source inputs instead of repeating the same timed-out input; it does not split again. Tool calls, invalid JSON, unsupported content, admission failures and external cancellation are never retried. Callers select the model route and all deployment limits.

The returned PaperEvidenceGenerator accepts B's request, parsed provenance and approved natural-language scope rules and can be assigned directly to runResearchDraft's generator. B receives its unchanged EvidenceGenerationRequest; the A-owned wrapper associates the call with the work, version, content hash, source, extraction method and scope decision.

Application callers use `runAcademicResearchDraft({ ctx, session, model, modelPolicies, input, adapters, signal })`. `modelPolicies.evidence` and `modelPolicies.synthesis` independently select their attempt limits, transient failure codes and initial retry delays; synthesis may also enable whole-response structural regeneration with `retryInvalidOutput`, within the same attempt limit. This stable entry checks the exact model route before search or acquisition. An omitted reasoning effort uses the model route default; an explicit caller choice is preserved and validated. Unsupported explicit reasoning fails before external paper work begins. The result includes `sessionId` and the terminal `retrievalRun` alongside the per-paper states, failures, analysis and report so callers can locate the durable model records and present observed coverage.

`runModelResearchDraft(ctx, session, config, policies, input, adapters, signal)` remains the lower-level composition entry. Supply search, selectPapers, fetcher and now in adapters; it binds extraction and synthesis generators to their separate policies and runs the existing pipeline through B's parsing/evidence and C's analysis/evaluated draft. Neither entry owns the Session lifecycle. Brief approval, selection policy, deadlines, report storage and publication remain caller responsibilities.

Each attempt's request and result records include its attempt number and bound, then are appended, flushed through SessionStore and read back from persistence before progress. Missing writers, append failures, rejected checkpoints or mismatched stored events throw WorkflowLogError and stop the entire research pass, including when cancellation races that failure. Result recording is not cancelled with the model request. A crash during streaming can leave a recorded request without a result; automatic resume is not implemented.

At paper settlement, the workflow captures an independent copy of accepted, source-checked extraction records before exposing the working evidence graph to synthesis. Reports pass this batch as `admittedEvidence`; changed or added cited evidence is rejected, including in drafts. Host reports receive `retrievalDisclosure` derived from completed queries, approved budgets, counts and failures. Web snippets and candidate URLs do not become report evidence or bibliography. A verified identity with a full-text resolution failure stays verified and contributes a separate `resolve_fulltext` failure.

Formal `runModelResearchDraft()` now uses `createModelFragmentEvidenceGenerator()` after the same scope review. B's fragment extractor packs adjacent short source segments within the character limit, verifies each source excerpt against its own locator, and splits a failed pack at source boundaries. The workflow durably saves `academic/evidence-fragment-verified` before dispatching the next fragment. Each fragment model call has one transport attempt; fragment recovery alone owns its three-attempt budget. The configurable defaults are 4,000 maximum characters, 1,000 minimum characters, 256 overlap characters, 16,384 output tokens, and a one-second first transport backoff. The model's configured output cap can lower that fragment cap. Request and result events include the original segment and character range, with `sourceRanges` for packed segments. Incomplete fragments leave already verified evidence available for a limited report. A fixed real-paper sample showed repeated output-limit truncation at 4,096; the 16,384 default matches the controller's existing extraction ceiling. Whole-paper reliability and latency still require validation.

The Controller selects `depth: 'minimal'` for formal research runs. Scope review stays separate; included papers retain at most five source-verified, question-linked records across all fragments, and the persisted fragment contains only those retained records. When provided, reviewed aliases in approved Brief-question order prioritize minimal-depth source fragments; they neither decide inclusion nor count as evidence. Older plans without reviewed aliases retain question-text prioritization. A clean stop at the evidence cap is not a failed extraction; actual fragment failures and rejected drafts still produce partial status. Callers that omit the depth policy retain complete extraction. Minimal evidence can support a limited draft but does not grant formal delivery or prove every approved question is covered.

The draft pipeline forwards the extractor's approved-question links through evidence admission to analysis and report rendering. `runAcademicEvidenceEnhancement()` is a separate, caller-selected, complete-depth operation for one already committed paper. It preserves first-tier identities and commits additions before dispatching the next fragment; the caller owns source re-acquisition, selection, cancellation and the original report. It does not revise that report or grant semantic approval.

## Model Experience

### Session-backed model extraction

#### What the model sees

`createModelEvidenceGenerator()` sends one tool-free scope request before any evidence request. Scope sees approved inclusion and exclusion rules, program-owned source provider and URL, and the first ordered text batch; a `sourceComplete` flag identifies partial input. It returns only a decision and reason. An included paper then sends B's instruction, focus questions and ordered text/locator batches without scope rules. Evidence output contains at most six direct answers, each with an exact excerpt and one card section; the program marks unextracted section fields `not_extracted` before source verification. Source metadata may establish an official source or stable identifier but cannot support a research claim. Both phases use immutable `academic/evidence-request` and `academic/evidence-result` records identified by `phase`; historical records without `phase` retain their combined-prompt meaning. Results retain lossless stream, supplied usage, attempt duration, first-content delay and coarse failure phase. These facts do not identify a failed network hop. `validated` means JSON validation only; log-only events do not enter the main conversation history.

#### Token effect

DSH's existing message estimator counts the complete framed input. With batching enabled, each batch must fit both the configured input limit and the model context after reserving output tokens. Successful batches are merged in source order, drafts with the same original segment, exact excerpt, statement and question-index set are deduplicated, and at most six drafts continue to exact-source verification. A failed batch leaves validated sibling evidence available and marks the paper partially extracted; all failed batches fail the paper. This heuristic is not exact tokenization, so a provider can still reject an admitted request.

#### KV Cache effect

Each extraction sends only its own paper request, without replaying the main conversation. No cross-paper cache-reuse guarantee is made.

### Evidence handoff

#### What the model sees

`extractPaperEvidence()` adds no prompt; it invokes B’s extractor and the caller-supplied generator only after successful handoff.

#### Token effect

The handoff itself consumes no model tokens; extraction tokens and request logging belong to the caller.

#### KV Cache effect

No model cache policy changes.

## Known Limitations and Deferred Work

- Scope review reads only the first evidence batch when a paper exceeds the configured input bound. The model can return `needs_more_context`, which pauses the paper for review; it does not automatically retrieve further passages. An `included` decision over partial text is not proof that unseen sections satisfy the rules. The short evidence draft populates the card section and statement but leaves section-specific attributes `not_extracted`.

- This library provides a bounded explicit-query draft pipeline, paper handoff and opt-in model adapter. The `@deepseek-ai/dsh-academic-workflow/recovery` type entry fixes the normalized recovery contract, while the root `reconstructAcademicResearchRecoveryState()` export performs pure A-S2 reconstruction from one complete ordered Session log. A-S3 persists a JSON-safe executable checkpoint before each ranked batch and after its settlement. Cancellation leaves an unfinished batch pending; recovery retries that batch as a unit. The Session-backed Controller accepts `resumeRetrievalRunId`, acquires the Session write handle, validates the checkpoint against the approved plan and committed batch history, skips retrieval and screening, preserves the original run identity, does not repeat settled batches, and retries one unsettled batch as a unit. Historical incomplete runs without a checkpoint fail with `candidate_state_missing`. A resumed retained pool does not start a new evidence-gap search round because source-runtime resolution caches are not persisted. Adaptive query planning and final semantic review remain subsequent work; a source provider may repeat transient transport attempts within its own configured bound. It does not prove scholarly identity or distinguish format changes from content revisions.
