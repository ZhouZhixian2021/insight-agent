## 使用本包

面向读者的说明由报告生成端统一分为关键限制、逐题内容缺口、筛选与处理记录及原始诊断。已知来源运行机制只进入诊断；正常停止记录不算证据缺口。重复批次警告合并展示，不累加可能重叠的数量。可读记录用已知论文标题替换内部版本标识。分组写入报告 Markdown，前端通过现有 Remote 字段读取对应章节；缺少这些章节的历史报告仍保留原始说明，并明确提示尚未归类。原始限制、评测问题与交付判定均不变。Markdown 和独立 HTML 保留经过转义的原始诊断供核查。

writingStyle: evidence_narrative 报告采用 B 写法：带引用的连贯正文和实际结果表先于范围及逐题核对。同一陈述在正文只出现一次，重复章节索引既不重复展开，也不生成跳转占位。条件和不确定性留在论述旁，完整原文及标识保留在附录。既有证据与正式交付检查继续执行；未标记的历史草稿保持原布局。

方向布局草稿落实预设报告层级：开篇范围／时间窗口／日期／政策、执行洞察、方向地图、逐方向主题及代表论文、机制、结果、判断和面向读者的应用含义，最后提供跨方向综合与逐题结论。缺少证据的部分省略，并汇总为方法中的覆盖限制。参考文献只使用已有元数据，部分日期保留精度，缺项明确说明；标题、作者、场所、发表状态及实际／引用版本附带 DOI、arXiv 或安全来源链接。每条分析段落仅展开一次，保留适用范围、不确定性及证据；其他章节通过段落链接引用，不重复正文。定量结果表保留各项条件，不制造跨数据集排名；缺少可核验图示时说明限制，不绘制。交付检查、内容限制与独立语义审核通过保持区分。

逐题论证在每个保留段落旁展示引用摘录、版本和定位身份，以及模型提出的关联理由。引用分为支持依据、不同发现／相反证据和背景材料，背景不显示为直接支持。没有相反关联明确表示其他发现仍未知；未说明不确定性不等于没有限制。部分回答和尚未回答的问题展示剩余缺口。同一分析段落只展开一次；其他章节使用交叉引用，定量结果表链接到段落。证据附录按论文标题分组排序，组内按版本排列，保留原始证据标识与定位。排版不重新判断证据，也不改变批准状态。

`appendRetrievalDisclosure()` 在保留原始 Markdown 正文的同时，附加经过转义和本地化的观察结果、限制及失败。`generateReport()` 接受相同的可选 `retrievalDisclosure`，不会把发现 URL 转为参考文献，也不改变审核资格。工作流为 Web 与 SDK 报告提供已完成查询的观察、批准预算及失败。含有该附录的报告返回 `retrievalDisclosureIncluded: true`，客户端据此保留 Markdown，不重复追加披露。展示记录不是权威核验台账，也不证明完整覆盖。

逐题草稿分别披露纳入分析、正文引用和支持正文的论文数量。支持正文的论文或全文数量低于 Plan 要求时，显著显示证据有限提示及 `unmet_plan` 问题。这类草稿仍可查看，正式交付保持阻止状态；批准下限和引用完整性检查均不放宽。

传入已验证的 `synthesis` 与实际 `coverage` 后，`generateReport()` 渲染批准的问题、保留的段落和数字引用。被拒候选段落序号和原因进入内容限制；被拒正文不进入结论或 Claim。受影响的问题和章节披露覆盖不足。每个合格段落只展开一次。书目与摘录来自输入记录。数量和必要结构决定交付资格；报告不限制字数，历史 targetLength 不阻止交付；部分回答、方向缺口和被拒候选提示作为不阻止交付的内容限制，不表示语义审核通过。

`generateReport()` — 传入共享模型记录、论文书目信息、草稿、最终或 auto 自动模式、合成数据标志和局限说明。报告生成内部执行评测。可选同步观察器在质量检查前收到 `evaluation`，在 Markdown 组装前收到 `rendering`；观察器异常不改变报告生成。auto 在交付检查通过时生成正式报告，否则生成草稿；final 拒绝未通过交付检查或合成数据。缺少独立语义审核不阻止交付。正文分别展示交付未达标原因，以及内容限制与未回答问题；数量和必要结构仍为交付条件。原文片段、证据 ID、实际版本和引用版本均可追溯。Markdown 内容经过转义，仅激活 HTTP(S) 来源链接。

本包是无状态函数库，不发布 invariant 伴随模块；自动化测试核验输出关联和失败行为。

问题驱动报告包含已批准问题与证据核对表。可选的 `ReportInput.questionLinks` 来自抽取；表格分别展示这些关联、原始摘要／全文等级、模型回答提案和未独立核对状态。未提供关联时明确披露，不根据模型问题索引推断。空卡片分区不表示已完成增强抽取，本身也不授予或排除正式交付资格。引用证据为零时拒绝合成报告生成；证据数量低于批准下限时，按批准策略保留明确受限草稿。渲染器不调度二级抽取，也不提供独立语义审核。

本地固定材料实验通过 `scripts/academic-experiment.ts` 导出一次已完成研究，并离线执行当前源码报告／评测，不调用模型。输入有哈希保护，原 Session 不变，报告参数重建明确披露，新实验目录保存对比及 C 源码快照。这是开发工具，不是网页导出操作。

内部 writing-experiment.ts 对明确提供的实验正文和比较表执行证据检查，并生成数字引用；隔离未知证据引用且不猜测修复，保留原始证据，输出明确标为实验草稿，不替换生产交付或声称内容审核通过。固定材料对比命令见[C 实验说明](../../../z-team_docs/模块分工/member-c-fixed-experiment-guide.md)。

## 模型体验

### 返回结果

#### 模型看到的内容

`generateReport()` 仅返回数据，不发送模型请求。

#### Token 影响

无直接消耗。消费方负责后续渲染和记录请求。

#### KV Cache 影响

本包不操作模型缓存。

## 已知限制与后续工作
<a id="known-limitations-and-deferred-work"></a>

- 使用受支持的 Plan 中文章节和数字引用；不提供 PDF、DOCX 或语义审核服务。调用方须如实标记合成材料。本包不是 Session 工作流或发布审批服务。
