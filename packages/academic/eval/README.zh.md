## 使用本包

每个跨论文 Claim 必须独立获得至少两项不同论文身份的支持，不能用报告整体覆盖数量代替。单篇论文的多条摘录或多个版本不满足该要求。重复的结论／证据关联会阻止交付；匹配审核必须恰好列出每个快照证据 ID 一次。来源陈述继续遵守单篇论文规则。

固定合成语义案例覆盖扩大适用范围、将相关性写成因果、遗漏相反发现、将缺少证据写成否定证明，以及跨不同数据集比较。没有审核记录时，结构完整的案例可以通过交付检查，但不表示语义审核通过；已提供且匹配的审核若不支持结论，仍阻止交付。案例是人工编写的审核规则回归依据，不是自动语义检测器，也不是实际模型准确率测量。

人工审核者阅读原文摘录，比较结论范围和实验条件，检查因果表达是否有依据，保留重要相反证据，并区分未测量和负面发现。审核记录使用同一组证据 ID，填写支持或负面评估、方法及版本和明确理由。生成模型的置信度不是独立审核。

可选 `admittedEvidence` 是来自直接学术来源或已核验论文的可信原始抽取批次。所有引用记录（含单篇归属陈述）必须匹配其中唯一的证据身份、论文与版本、定位、摘录、哈希、来源和抽取方法；被拒记录不计入论文覆盖。这项检查不执行学术核验：工作流必须传入独立的生产批次，不能复制待审核记录充当依据。工作流在通过原文核对的抽取结算时独立保存该批次，再把工作记录交给分析。其他调用方省略此选项时保留既有完整性检查，不证明 Web 准入。

可选的 `sourceStatements` 保留单篇论文陈述，不为其创建跨论文 Claim。每条陈述必须有支持证据，其引用接受同样的当前版本、定位、哈希和来源深度核验，并计入独立论文覆盖。来源陈述不再要求独立语义审核记录才能交付。

`evaluateClaims()` — 传入当前研究简报、结论、关联、证据、版本、定位、审核记录和评估时间。函数检查快照与关联集合、当前性、来源、证据等级、预印本策略和最低论文数量。证据缺失或无效会阻止交付。缺少独立审核不阻止交付。ready 表示交付检查通过，不表示结论语义已核实；已提供但无效或不支持结论的审核仍阻止交付。问题可带 delivery/content 分类，历史记录允许省略。审核记录必须由调用方从可信审核人处取得；本函数不认证审核人身份。

本包是无状态函数库，不发布 invariant 伴随模块；自动化测试核验输出关联和失败行为。

<a id="model-experience"></a>
## 模型体验

### 返回结果

#### 模型看到的内容

`evaluateClaims()` 仅返回数据，不发送模型请求。

#### Token 影响

无直接消耗。消费方负责后续渲染和记录请求。

#### KV Cache 影响

本包不操作模型缓存。

<a id="known-limitations-and-deferred-work"></a>
## 已知限制与后续工作

- 不提供模型裁判、真实性保证、外部检索或审核人认证。外部输入由其入口负责人完成类型校验。
