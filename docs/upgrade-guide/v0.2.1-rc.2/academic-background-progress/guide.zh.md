# 读取学术后台进度事件

[English](guide.md) | 中文

## 变更

学术后台研究的普通进度继续使用必读的 `academic/background-run-progress` 原有载荷。新增必读的 `academic/background-run-q6-update` 事件，在相同进度字段之外携带不含 `candidates` 的完整 Q6 元数据。它适用于 Session／运行／Brief 绑定和候选内容与完整基底匹配的情况，包括重新创建但内容相等的候选对象；读取器从该基底继承候选。初始化、候选内容变化、绑定或检索运行 ID 变化、取消意图和终态结算仍写入完整的 `academic/background-run-state` 检查点，保留原有 `schemaVersion: 1` 载荷。

当前读取器将三类事件折叠为相同的完整 Remote 视图，保留每次持久化进度更新；旧完整检查点和旧进度事件继续可读。只认识旧 progress 标签的读取器会拒绝新的必读 Q6-update 标签。学术投影缓存状态版本为 3，Session 写入格式仍为 4。[兼容记录](../../../persistence-changes/2026-10-26-academic-background-progress.zh.md)说明了两类必读轻量事件。

每个实时订阅者只保留一份尚未消费的最新视图。较慢的订阅者可能跳过中间实时帧，持久化事件仍完整保留。订阅结束前会交付待消费的终态视图；中止订阅会移除观察者和待消费视图，不会取消研究。

已有日志不作改写或压缩。此改动消除内容相等的候选重复，不约束频繁候选内容变化。重新打开超大历史时的内存峰值和真实 Web 长时运行验收仍未验证。

## 迁移

1. 在写入新后台更新之前，升级所有应用或自定义读取器。读取器必须处理两类必读轻量标签，基于匹配的完整基底恢复 Q6 元数据，并继承其中的候选；参见[控制器约定](../../../../packages/api/academic-research-controller/README.zh.md)。
2. 保留已有 Session 文件。旧 `academic/background-run-state` 记录保持原有含义并继续可读，无需改写历史。不要删除新事件、将其标为可忽略，或修改 Session header 来迫使旧读取器接收它们。如需回退到旧读取器，应保留升级前副本。
3. 确认纯旧记录和混合记录均能恢复最新进度、Q6、取消意图和最终结果。按最新视图传输约定检查较慢的实时订阅，不应要求每个中间帧都送达。Remote 完整视图类型、模型参数和用户文案无需迁移。
