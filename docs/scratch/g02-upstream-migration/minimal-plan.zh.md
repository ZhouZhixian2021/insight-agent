## 摘要

## Dev Note

<details>
<summary>尚未实施的方案及后续检查</summary>

以下步骤是核对材料，不代表已交付支持，也不是现在要执行的命令。

1. 由 2→3 转换代码持有固定的 T0 学术 schema，列出 19 类事件、精确必需和可选字段、嵌套结构、版本、8 个引用与两个已审计请求来源。不从已安装 SessionEventMap 推导历史许可，也不开放整个命名空间。仅有格式 2 header 不能标识写入者。

2. 在 2→3 增加精确学术接纳与引用处理。在映射实际输出位置前，校验日志封套、载荷、较早目标类别和匹配身份。保留 null，拒绝必需字段缺失。复用标准系统消息插入、PTC 更名、切口跟踪及全部非学术行为。不修改前代 codec 或冻结 dispositions。

3. 在 3→4 的 opaque/unknown 分支之前处理已审计学术事件。新增处理仅限前段已验证且 input.sourceKind=transformed 的中间结果。直接落盘的格式 3 学术扩展缺少本次审计依据，继续不支持。应用第二张映射，即使 seq 不变也验证引用，仅转换两个已声明请求来源槽。保留可见内容和私有回放 JSON。

4. 同步处理收集直属子前置事实的历史 catalog。它对转换后当前结果的校验需要固定 released-V3 加已审计 T0 事件集合，并检查学术载荷。原生 V3 restoreCurrent 保留发布集合。不替换为全部已安装事件类型。生产父迁移仍收集完整可用子证据，只有独立转录测试显式传入空数组。

5. 保留最终验证、JSONL 准备、Worker 验证、源变化检查、原子发布和继承切口。未来副本验收仅能建立合法当前代后继，绝不移动、覆盖或删除已提交历史代。不通过改变 Session、Brief 或 call 身份使校验通过。本次文档工作不读取私有 Session。

### 后续聚焦验证

这些检查属于计划，不是已执行迁移证据。此前轮次的测试数量不能计入本次实施。

| 用例组 | 预期证据 |
| --- | --- |

| 跨两段的 8 个引用 | 无插入、单段插入、双段插入、null、错目标或身份、缺失、未来、负值、小数和越界值。 |

| 来源转换、文本、流和不透明 JSON | 仅已审计归属改变；ID、路由、文本、内容、流顺序、私有数据和普通数字相等。 |

实施获得授权后，先运行聚焦单元检查，再完成适用的类型、lint、持久化、文档检查与构建，然后本地提交代码。实际 Session 导入和产品运行需要另行明确范围。不推送或合入 master。

### 保留阻断

缺少明确 approved=true 的 T0 PTC 成功调用仍不充分。格式 2 额外 meta 没有已审计来源，不得剥离或伪造。重新评审建立新 Brief 身份，不得自动绑定旧运行。

15 类事件仍需合成覆盖。其他分支的额外载荷、泛型 Message[] 变体和原生格式 3 学术扩展没有自动兼容承诺。完整历史导入仍未验证，本次文档检查点不改变这些限制。
