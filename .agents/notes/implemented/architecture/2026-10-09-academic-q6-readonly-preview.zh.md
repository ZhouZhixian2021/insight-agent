# Agent Note: Q6 将合成预览与正式运行投影分开

Status: implemented

[English](2026-10-09-academic-q6-readonly-preview.md) | 中文

## 问题

Q6 需要在真实研究运行前和运行中使用同一页面展示计划、候选解释、批次和逐题覆盖。把固定数据放进真实结果会让合成候选看起来已经核验；从 Session 事件或第二次运行重建实时事实则会混合身份或重复工作。

## 决策

现有学术侧栏组件提供独立且标注清楚的 Q6 只读演示。无需会话即可打开，且不调用 Remote。包内 JSON 副本必须在模块内测试中与规范 Q1 夹具完全一致。组件输入组合现有共享类型，不重定义论文身份或评分规则。

排序执行在 Q5 事实提交点发布完整的 `AcademicQueryWorkflowObservation` 快照。Controller 的纯函数 `academicQ6Projection()` 把每项权威评估与准确论文、版本和审核过的评估输入关联，保持生产方队列顺序，并提供计划、轮次、批次决定与结算、覆盖、停止决定和限制。每份投影绑定一个 Session、检索运行和 Brief 版本，使用运行内单调递增序号。独立生成的分区区分尚未产生、可用空值、截断和失败。

`academicResearch.runStream` 在同一次操作中用 `q6` 帧发送这些快照。终态 `AcademicResearchRunValue.q6` 保留最后一份投影，只有旧选择器没有产生排序工作流时才为 `null`。Web 客户端不解析内部 Session 事件重建这些状态。真实投影缺失或失败时绝不回退到合成样例。

候选分组遵循生产方队列顺序；搜索与优先级控件仅筛选展示。分数、阈值、分类与原因保持生产方事实。标题和作者缺失时明确披露，不自行生成。未知元数据与全文未解析保持不同含义。

记录的进度快照使用绝对计数，与夹具单独结算的证据覆盖分开。选择快照不表示正在运行研究。演示展示已有缺口和停止原因，不生成补检决定。

## 考虑过的替代方案

**真实请求失败时回退到夹具。** 不采用，因为会隐藏错误并误表示研究结果。

**增加模拟审批或优先级修改按钮。** 不采用，因为本轮没有权威执行接口支持这些操作。

**按展示的总分重新排序。** 不采用，因为 B 的队列已包含多样性安排和权威调度顺序。

**只在终态报告附加 Q6 字段。** 不采用，因为用户需要在同一有界运行期间查看排序、批次和证据缺口。

**发送增量 Q6 补丁。** 不采用，因为断流缺项和乱序到达会迫使客户端重现服务器状态转换。带序号的完整快照沿用现有进度替换规则。

## 结果

[Q6 接口需求](../../../../z-team_docs/模块分工/academic-q6-ui-interface-requirements.md)已固定为只读 Remote 投影。[实时进度决策](2026-09-28-academic-progress-client.zh.md)继续约束六阶段运行视图；Q6 在其旁补充查询工作流解释。固定数据测试保持演示隔离，工作流与 Controller 测试固定完整观察、投影身份、流传输和终态保留。当前 Web 研究页能够容纳 `q6` 帧；在真实 Q6 页面中渲染这些帧及候选调整操作仍是后续工作。
