# Agent Note：Academic 证据抽取使用有界恢复与明确阶段结论

状态：已实现

[English](2026-09-20-academic-evidence-extraction-recovery.md) | 中文

## 问题

Academic 来源检索与全文获取可能已经成功，但逐篇模型回答会达到输出 token 上限，或把逐字引文填到错误的输入片段序号。由于没有论文进入分析，整轮 `RetrievalRun` 随后失败；Web 上的“检索结果”又会让用户误以为来源检索失败。

## 决策

应用显式提供逐篇模型尝试上限，Web 部署使用两次总尝试。只有已记录模型结果以 `finish.kind: max-tokens` 结束时，工作流才重试；每次尝试都有独立的持久请求与结果记录，并带 `attempt` 和 `maxAttempts`。非法 JSON、工具调用、不支持的输出、准入失败、持久化失败和取消都不重试。

证据核验在逐字引文命中指定片段时保留原定位。有效片段序号指错位置时，只有未经改写的引文在全部输入片段中恰好出现一次，抽取器才允许重新定位。歧义引文、规范化改写或 OCR 差异仍然失败。

来源核验失败按模型草稿逐条隔离。合格记录保留定位、哈希和卡片引用，被拒草稿返回原始序号及原因。工作流区分部分抽取与全部拒绝，将合格证据交给分析，并按受影响论文各计一次失败抽取操作。报告限制和 Web 均披露被拒情况。程序拥有的输入无效、生成器错误和整份 JSON 错误仍使调用失败。原始模型请求与结果继续作为持久回放输入，拒绝记录投影本身不新增跨运行持久化。

Academic Remote 返回由生产方确定的 `search`、`fulltext` 与 `extraction` 阶段结论。Web 分别展示三个阶段，并把汇总的 `retrievalRun.status` 命名为研究处理结果。

## 考虑过的替代方案

**第一条引文未匹配就丢弃整篇论文。** 拒绝，因为一个被改写的公式不会让同一版本中其他可独立核验的引文失效。部分接纳保留逐字来源要求，也不会将整篇论文宣称为核验全部通过。

**再次提高输出 token 上限。** 不作为恢复策略，因为它会增加调用成本和上下文预留，却无法区分偶发未完成与持续无界输出。

**接受模糊或规范化引文。** 拒绝，因为更改 Unicode、空白、标点或 OCR 痕迹会削弱来源可追溯性。

**让浏览器根据计数推断阶段。** 拒绝，因为阶段语义归生产工作流所有，客户端应直接展示生产方事实。

## 结果

一次偶发的输出上限结束可以恢复，不会重新执行来源检索或全文获取，持久记录会展示两次尝试。模型定位序号写错时可在不接受改写引文的前提下恢复。同一轮完成结果中，Web 可以同时显示“来源检索：成功”“全文获取：成功”和“证据抽取：失败”。长论文分段、模糊引文恢复与跨运行续跑继续延期。
