# Agent Note: 学术能力与 U0 组合的集成

Status: implemented

[English](2026-10-21-academic-u0-integration.md) | 中文

## 问题

学术部署扩展共享预设、审批、Web 和 Remote 服务。固定的上游版本以声明式注册替代文件系统预设发现，将普通计划阅读移入侧栏，并在执行时读取 Web Provider 设置。保留旧版共享实现会丢失这些上游变更。

## 决策

[Web Bundle](../../../../packages/bundle/web-app/package.json) 通过 `dsh-agent-preset` 声明学术预设，与上游预设并存。其补丁拥有既有研究组合，并相对于补丁解析随包发布的技能。注册表拥有预设选择和修订生命周期，不恢复文件系统根目录发现服务。

[审批面板](../../../../packages/client/ui-user-questions/src/client/PlanReviewPanel.tsx) 保留上游预览操作和 Remote 结算。恰好一个具名学术执行块启用行内可读范围、折叠执行细节和自然语言修改。修改提交反馈而不授予批准；普通或含糊计划保留上游摘要和侧栏预览。

[Web 服务](../../../../packages/web/web/src/index.ts) 让显式的单次抓取 Provider 优先于当前部署选择。省略该覆盖时，在执行时读取动态设置和环境选择。因此学术全文抓取可以选择所需 Provider，而不改变用户的通用 Web 设置。

[Remote 组装](../../../../packages/api/remotes/src/client/index.ts) 在上游命名空间旁挂载学术研究。pi-ai 适配器保留有界的调用独立传输诊断，同时使用上游模型工厂。

持久化读取使用返回的 `events` 切片并保留上游所有权元数据。学术模型生产者声明各自的消息来源类型。计划评审将明确的批准决定写入持久化工具结果元数据；学术计划恢复要求该决定，而不把每次成功工具调用视为批准。缺少此元数据的历史原生结果需要重新评审。构建元数据读取器容纳尚未提交的上游合并产生的大量 Git 状态输出。

新增学术事件和归属类型的同版本评审由[持久化确认记录](../../../../docs/persistence-changes/2026-10-21-academic-u0-events.zh.md)负责。

## 考虑过的替代方案

**恢复文件系统预设注册表。** 这会重复上游选择职责，并丢失声明式预设编辑和修订生命周期。

**学术全文沿用通用抓取默认值。** 这会将证据获取绑定到用户选择的 Web Provider，而该 Provider 可能返回摘要而非全文字节。

**整体替换上游审批面板。** 这会丢失侧栏预览操作和 Remote 结算。学术控件仅针对具名执行块扩展该面板。

## 后果

既有 T0 同步 Session 历史读取按上游政策保留逐行弃用豁免，不引入新的同步读取器或别名。基于投影的历史访问仍待迁移。

学术技能文件随 Web Bundle 及其发布清单迁移。活动测试输入引用新位置，带日期的开发记录保留历史路径。冻结的 T0 样本留在本升级目录之外。依赖安装和编译建立工程兼容性；实际研究、历史数据兼容性和报告质量需要独立验收，构建成功不代表这些能力已通过。
