# Agent Note: 学术业务包统一管理接入配置

Status: implemented

[English](2026-11-03-academic-composition-bundle.md) | 中文

## 问题

学术算法已有独立代码包，但来源配置、页面注册和研究预设仍放在上游 Web 包中。因此，业务调整会修改公共组合文件，复用时也需要查找多处接入位置。

## 决策

[学术接入包](../../../../packages/academic/bundle/README.zh.md)统一管理后端注册、页面注册、预设和技能资料。CLI 依赖此包，内置 Web 配置在公共 Web 层之后选择它。现有配置迁移机制只迁移与旧默认 Web 列表完全一致的组合，自定义列表继续由用户管理。保留插件标识，使后续覆盖仍然有效。此次没有持久化数据格式变更。

## 考虑过的替代方案

**只把全部学术包移到一个目录，不抽离接入配置。** 单纯搬目录仍会把运行组合留在 Web 中。[后续目录决策](2026-11-04-academic-workspace-group.zh.md)在拆出接入包之后集中这些独立包，保留各自的包名和构建职责。

**只在 Web 包内部拆出学术补丁。** 这能缩小单个文件，但业务资料和依赖仍归上游 Web 所有，也不能独立选择是否加载此业务包。

**增加新的启动器或补丁加载机制。** 现有有序配置组合已经能够表达所需装配，再增加一种机制会增加上游维护点。

## 影响

公共 Web 包不再管理学术注册和依赖。默认 Web 仍提供学术功能，其他组合可以不加载此业务层。自定义配置迁移时需要显式加入它。该模块仍依赖 Harness 服务、生成的 Remote 类型及已有 Session 支持；此次拆分不提供脱离框架运行的能力。组合测试覆盖选择、不加载及精确迁移；已有基于 Loader 的学术预设测试覆盖模型可见的技能读取和计划审批。
