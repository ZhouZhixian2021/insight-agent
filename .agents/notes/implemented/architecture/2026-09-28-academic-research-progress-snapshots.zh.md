# Agent Note: 学术研究进度使用完整阶段快照

Status: implemented

[English](2026-09-28-academic-research-progress-snapshots.md) | 中文

## 问题

一次 Academic 研究 Remote 调用可能长时间执行来源检索、并发全文获取、证据抽取、洞察分析和报告合成，但客户端收不到中间状态。候选总量会变化，论文处理存在并行、重试或证据达标后提前停止，因此单一估算百分比无法如实表达进度。

## 决策

Academic Research Controller 导出第 1 版浏览器进度格式。每个进度帧都是由 `RetrievalRunId` 与单调递增序号标识的完整快照；较新序号替换较旧快照，客户端无需重放增量事件即可重建当前状态。

快照分别携带检索、筛选、全文、证据抽取、洞察分析和报告阶段。每个阶段包含生产方确定的状态、时间、已完成数量、可选的已知总量和计数单位。不同论文可能同时获取全文和抽取证据，因此 `activeStages` 可以包含多个阶段；`primaryStage` 只用于页面主标题。

快照公开已观察数量、已运行时间、并发活动、从一开始的分段与尝试序号，以及清理后的失败代码。摄取计数分别表示被合并的论文身份、分配到已有论文的输入记录、最终保留版本和未解决的疑似重复。论文活动同时携带 `AcademicWorkId` 与 `WorkVersionId`；Provider 活动携带查询位置与单个 Provider 的结算状态。它不公开估算完成百分比或原始 Provider／模型诊断。阶段结论与汇总计数保持独立，已验证证据也与模型返回或被拒草稿保持不同含义。

导出的 `AcademicResearchRunFrame` 包含进度帧和唯一最终结果帧。`academic-workflow` 接受可选的同步观察者，在检索、筛选、并发论文处理、分析、报告生成和取消的提交点发布完整运行内快照。进度只用于观察，因此订阅者异常会被隔离。工作流使用摄取包提供的审计汇总填写摄取计数。它通过 Controller 适配器把一个运行内观察器传给 Academic Source，使用查询位置和工作流时钟为每个 Provider 的开始与结算事实补齐上下文，并把这些事实发布为 Provider 活动。工作流还观察每个全文候选：候选开始时发布带一基尝试序号的 `fulltext_fetch`，候选失败且存在后备地址时发布 `waiting_retry` 和分类后的失败，接受 HTML 或 PDF 后发布 `fulltext_parse`，取消时在整轮结算前发布论文取消事实。A 持有的论文生成器发布从一开始的模型批次位置；尝试开始与结算只有在对应 Session 请求或结果准确持久化后才对外可见，有限重试确定后发布带清理后失败代码的 `waiting_retry`。来源核验发布接受与拒绝证据数量，不改变 B 的 `EvidenceGenerator` 接口。`academicResearch.runStream` 将同步观察者桥接到一个有序、单消费者 Remote 数据流；关闭数据流会中止该次操作。一元 `academicResearch.run` 暂时为客户端兼容保留，但不发送进度。

## 考虑过的替代方案

**从终态论文数组推断进度。** 不采用，因为终态数组不能表达活动查询、并发论文、重试或下游失败前已经完成的阶段。

**只发布增量事件。** 不采用，因为客户端重连或漏掉事件后，需要额外的重放协议才能呈现当前状态。

**发布总体百分比。** 不采用，因为候选总量可能在筛选后才确定，重试和证据达标后提前停止也会改变剩余工作。

**扩展粗粒度 `ResearchStage` 联合类型。** 不采用，因为该类型表示整轮生命周期，而检索、全文、证据、分析和报告可能重叠，并需要独立结算。

## 结果

B 可以发布来源、论文、分段、尝试和证据事实，无需决定界面文案。C 可以消费真实数据流，也可以继续使用固定合成快照开发。完整快照会重复少量有界状态，但能简化替换与排序。工作流生产方在单篇失败和取消时保留已经完成的同级事实。该数据流明确为一次性流，不提供自动重连，也不提供调用方离开后的后台执行、进度持久化或恢复。
