# Agent Note: 学术洞察共用一个不依赖提供方的模型包

Status: implemented

[English](2026-09-10-academic-model-package.md) | 中文

## 问题

学术检索、单篇论文证据生产和跨论文报告需要共用标识符与字段状态语义。如果每个包分别声明记录，提供方字段会泄漏到分析层，三位实现负责人也必须在相同文件中协调普通改动。

## 决策

位于 `packages/academic/model` 的 `@deepseek-ai/dsh-academic-model` 是学术洞察的最底层包。它负责不依赖提供方的记录与纯函数，但不提供 Cordis 服务、模型调用、检索适配器、工作流、持久化提供方或界面。上层学术包依赖它，而它不依赖上层包。

跨包学术 ID 使用不透明的品牌化字符串。本包定义成果、不可变成果版本、证据卡片、论断、已批准研究简报和失败的 ID。`Availability<T>` 通过不同的可辨识状态表达可用、来源未知、不适用、尚未抽取和抽取失败；失败状态保留失败 ID 和原因，`isAvailable()` 只把类型收窄到包含值的状态。

`AcademicWork` 负责跨版本书目信息和规范引用版本。`WorkVersion` 负责一个不可变版本的类型、日期、提供方记录、内容哈希、前代版本和有效状态。成果、版本和研究简报 ID 使用随机 UUID，而不从外部标识符推导。`externalIdentifierDedupKey()` 编码已准入的标识符类型和规范化值，不执行隐藏规范化；本包尚不包含持久合并审计记录。

`ResearchBrief` 负责一个版本的用户审核研究范围、发表时间窗口、证据要求、报告要求、资源上限、假设和批准状态。`isExecutableResearchBrief()` 只有在批准记录指向 Brief 当前版本时才允许执行；等待审核、要求修订和针对旧版本的批准都不能授权执行。

`EvidenceRecord` 把原文片段和带来源陈述绑定到实际成果版本、提供方、获取时间、提取方法、内容哈希和一个 `SourceLocator`。定位联合类型区分提供方记录、摘要范围、PDF 章节、段落、表格和图片；来源没有页码时不能编造页码。`EvidenceCard` 固定研究问题、方法、数据集、指标、发现和局限六个分区，每个条目必须有至少一个直接证据 ID。`EvidenceSnapshot` 保存一个研究简报版本实际使用的不可变证据 ID、成果版本和内容哈希。

类型完备的同进程值不接受重复运行时校验。后续解析器只在记录跨越不可信或持久化边界时校验。

## 后果

成员 B、C 可以针对同一套语义完成编译，而不需要导入对方的实现。提供方特定响应字段保留在适配器中，报告特定展示字段保留在分析或界面包中。共享模型改动由模型负责人提交，从而减少 PR 重叠。

本包尚不负责论断、覆盖度摘要或批处理结果。消费者不能为这些领域发布替代公共记录；他们应向模型负责人提供样例，并等待共享类型。

## 验证

聚焦测试覆盖五种可用性状态、随机共享 ID、版本化成果记录、精确外部标识符去重键、当前版本 Brief 审批、全部来源定位类型、六分区证据卡和不可变证据快照。本包加入 Host TypeScript 工程；仓库包路径生成、文档门禁和双语配对覆盖本分组与包。

## 考虑过的替代方案

- **在每位成员的包中保留类型**——不采用，因为同名记录会发生漂移，每次交接都需要转换。
- **把记录放入工作流包**——不采用，因为证据生产和离线分析不应为了类型而挂载编排。
- **一次实现完整 v1 模型**——不采用，因为小规模已确认阶段能为 B、C 提供稳定检查点，并隔离接口评审。
