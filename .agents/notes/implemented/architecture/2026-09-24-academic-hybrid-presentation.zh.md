# Agent Note: 学术混合检索展示保留生产端事实

Status: implemented

[English](2026-09-24-academic-hybrid-presentation.md) | 中文

## 问题

[混合检索契约](2026-09-22-academic-hybrid-retrieval-contract.zh.md)区分 Web 发现、学术核验和去重论文。统一的成功标记会隐藏这些区别，而未经补充的报告下载缺少界面其他位置展示的运行限制。

## 决定

学术客户端直接展示已批准的逐查询策略和混合检索终态观察。缺少投影时保持未知；生产端报告核验之前，已识别引用仍是未核验状态。数量保留各自单位。请求运行期间不模拟阶段进度。工作流把已完成的检索事实和批准查询预算交给后端报告渲染器。报告用 `retrievalDisclosureIncluded: true` 标记已有检索附录；Web 预览和下载原样保留该 Markdown，仅在缺少标记时追加经过转义的披露。浏览器只导入报告展示类型并在本地渲染，防止宿主执行代码进入客户端包。候选链接不进入参考文献，披露不能授予审核通过状态或宣称完整覆盖。

评测库接受可选的原始准入证据。引用记录的身份、内容和来源必须匹配，才能计入覆盖。这项输入由可信抽取生产端提供；评测器不通过 URL 或模型声明建立信任。工作流在原文核对后的抽取结算时独立复制合格记录，再把工作证据交给分析适配器，并向报告评测传入这份原始批次。工作记录被修改不会改变比对批次。权威核验的全文候选及失败按来源记录和当前运行保留；地址解析失败时，身份核验仍为成功。这类失败通过检索失败列表的 `resolve_fulltext` 和既有引用说明展示，不改变引用计数。

范围审核在接收论文片段时，同时接收由程序持有的学术来源 Provider 和来源 URL。它可以用这些元数据满足已批准的稳定标识或官方来源规则，不要求抽取正文再次写出标识。元数据不能支撑研究结论；模型抽取证据仍必须来自正文摘录。

## 考虑过的替代方案

**根据数量或官方 URL 推断成功。** 拒绝，因为识别、核验和论文准入是不同操作，统计单位也不同。

**在报告和评测中导入 Controller 类型。** 拒绝，因为 Controller 已经依赖工作流和报告。报告持有本地化展示输入，客户端适配正式 Remote 投影，不改变共享模型。

**用浏览器生成的报告替换服务器报告。** 拒绝，因为必须保留生产端内容及质量状态。带标题的附录记录运行事实，不创造结论。

## 影响

模块内测试消费 A 的合成夹具，验证旧版缺项、核验结果、覆盖披露、摘要替换和报告交付资格。合成展示测试不证明真实来源成功。已有混合检索契约保持有效；本决定增加客户端消费，不取代共享接口。
