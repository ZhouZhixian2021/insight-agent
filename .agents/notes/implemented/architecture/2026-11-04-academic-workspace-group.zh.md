# Agent Note: 集中学术目录并保留各包构建职责

Status: implemented

[English](2026-11-04-academic-workspace-group.md) | 中文

## 问题

复用学术业务需要从四个工作区分组中查找业务包、后台控制器、浏览器页面和接入包。共同的业务归属不够直观，直接搬动文件而不更新发现规则，还会使页面代码悄悄退出仓库检查。

## 决策

学术审批展示和模式文案归 ui-research，client-remote 挂载生成后的浏览器接口。公共问答控件提供业务正文链式插槽并保留回答提交责任；公共模式页面提供按实例管理、支持本地化和注销的文案登记。继续把学术分支放在公共页面或公共 Remotes 中会重新引入业务耦合；在学术目录另建传输则会重复 Gateway 的生命周期逻辑。

[academic 分组](../../../../packages/academic/README.zh.md)以独立代码包承载这四类职责。后台位于 `research-controller`，页面位于 `ui-research`，接入配置位于 `bundle`。公开包名、导出入口、插件标识和持久化事件格式保持不变。工作区仍为两层目录，Host 与 Client 保留各自的编译引用；浏览器打包继续使用公共 Client 配置。

这项决策调整了[接入包决策](2026-11-03-academic-composition-bundle.zh.md)中对目录方案的选择，同时保留独立接入包。Client 检查根据原有包名以及原 Client 分组识别迁移后的页面。公开浏览器通信类型的 Host 包继续保留原分类。

## 考虑过的替代方案

**保留四个工作区分组。** 可以沿用按位置发现代码的方式，但业务交接和源码复用仍依赖另一份目录清单。

**把全部职责合成一个包。** 这会丢失有用的依赖和编译边界，让浏览器使用方承担后台依赖，也使单项能力更难复用。

**增加目录链接而不移动代码。** 实际所有权仍然分散，复制目录后还依赖外部目标，在 Windows 工作区之间尤其不便。

## 影响

学术专用源码、测试、包说明和配置资源集中在一个分组。公共框架服务、已发布的 Session 迁移代次、仓库实验脚本及应用级测试保留原归属。完整复用仍需要版本匹配的 Harness 依赖和配置组合。上游更新仍涉及 CLI、生成的 Remote 接口、构建引用和检查发现规则；目录集中减少业务分散，不承诺升级完全没有冲突。

验证覆盖搬迁后的页面发现、保留的 Client 约束、包编译、随包移动的测试，以及已有的真实 Loader 学术预设场景。本次变更不修改架构图。
