# Agent Note: 生命周期演示区分运行状态与查看连接

Status: implemented

[English](2026-10-10-academic-run-experience-preview.md) | 中文

## 问题

Q7.4 后续需要页面解释长任务、部分证据和重新查看。当前 Remote 执行流在消费结束时取消任务，因此只修改客户端不能承诺持久后台运行。

## 决策

第一阶段在独立 Q6 演示中增加固定 JSON 生命周期预览。父入口持有演示记录，使其跨弹窗卸载保留。关闭或切换记录只改变查看连接；明确的本地演示取消改变运行状态并记录已知来源。重开读取同一记录和已有草稿，不创建请求或生成报告。刷新页面与插件释放会重置本地原型。

预览展示阶段输入／输出单位、原因文字、独立运行和连接状态、取消来源、限制与草稿可用性。未知计数与阶段耗时保持未知。事故中的 70 条发现记录、30 篇候选上限、20 篇安排处理、12 条证据和两篇部分可用论文，不合并解释为已正式纳入。合成报告下载使用独立文件名。

## 考虑过的替代方案

**让现有真实运行脱离 AbortSignal。** 不采用，因为服务器持有流终止逻辑，目前尚无后台订阅接口。

**每次关闭弹窗都重置记录。** 不采用，因为无法验证第一阶段的重开与结果保留。

**推断取消来源或缺失阶段数量。** 不采用，因为事故未记录这些事实。

## 结果

[真实流生命周期](2026-09-28-academic-progress-client.zh.md)与[Q6 隔离决策](2026-10-09-academic-q6-readonly-preview.zh.md)仍有效；本地原型不取代它们，也不改变真实请求。固定数据测试和一条真实 Web Loader 场景验证重开、连接状态独立、明确取消、草稿保留及无 Remote 调用。第二阶段需 A 的权威后台运行接口，再将这些交互连接到真实运行。
