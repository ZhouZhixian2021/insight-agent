# Agent Note: 学术进度由一次请求持有

Status: implemented

[English](2026-09-28-academic-progress-client.md) | 中文

## 问题

[进度快照契约](2026-09-28-academic-research-progress-snapshots.zh.md)在同一次执行流中发送中间事实和最终结果。如果当成可自动重连的订阅，会重复启动研究。传输异常不能证明研究失败。

## 决策

学术表单持有一个 AbortController，每次明确提交仅消费一次 `runStream`。必须匹配 Session 和运行身份。递增序号替换当前快照，重复和旧快照被忽略。最近观察最多保留 20 条。收到第一个匹配的结果后结算页面并结束消费。表单卸载取消请求，迟到帧不能更新另一个表单。

页面展示固定六阶段、并发活动、分段与尝试事实和已观察耗时，不从计数推断成功或编造百分比。取消和中断保留最近观察，两者均不自动重连。明确的 Remote 拒绝使用服务器错误文案；通用内部错误或传输错误保持结果未确认。

浏览器通过 workflow 的仅类型 `./progress` 导出导入进度类型。Controller 的类型导入与对应 TypeScript 源码别名指向该独立入口。导入 workflow 执行总入口会将宿主 Session 扩展带入客户端测试，与 ClientSessions 冲突；隔离修复依赖关系，不改变进度字段或工作流执行。

## 考虑过的替代方案

**断线后重试流。** 不采用，因为每次调用都会启动新的研究操作。

**把未知总数填零或把等待时长换算为完成比例。** 不采用，因为生产方未提供这些事实。

**在 UI 复制共享类型。** 不采用，因为消费者必须遵循正式 Remote 契约。

## 结果

已有快照决策仍有效，本记录补充客户端生命周期与类型导入隔离。固定夹具测试覆盖并发活动和重试。真实 Web Loader 场景仅替换外部搜索来源，通过真实 Controller 和工作流验证检索进度与无证据终态；它不证明外部网络或模型的可靠性。后台执行和恢复仍不在本轮范围内。
