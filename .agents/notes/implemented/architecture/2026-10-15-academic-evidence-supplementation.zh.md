# Agent Note: 完整抽取补充已提交的论文证据

Status: implemented

[English](2026-10-15-academic-evidence-supplementation.md) | 中文

## 问题

重复执行完整抽取会生成新的证据身份，即使已核验摘录已经支持草稿。替换一级结果会丢失已提交的引用关系和来源字段。丢弃所有重复记录也会丢失同一摘录支持的新卡片分类。

## 决策

`enhanceEvidenceInFragments` 使用现有完整深度分片执行器补充已提交的抽取结果。初始证据必须与论文、版本和内容哈希一致，且保留定位与证据引用关系。抓取正文变化时须单独抽取；增强不会把摘要记录提升为全文证据。

所有初始记录、定位、问题关联和卡片条目保持不变，结果沿用初始卡片 ID。定位、陈述和摘录相同的记录复用已提交证据 ID。新增问题关联和六分区分类可以引用这些记录。分类字段和支持证据 ID 相同表示已有条目；不同分类保持独立。不从改述推断语义等价。

提交回调在下一个片段运行前接收新增内容和拒绝事实。其卡片条目可以引用初始记录而不重复发送，因此调用方须先提交初始结果。已分类失败返回累积证据和未完成范围。取消、未分类错误和持久化失败会使调用失败，调用方仍持有初始证据与此前的回调提交。工作流选择、模型路由、Session 日志和正式审核资格仍由调用方负责。

[一级深度决策](2026-10-14-academic-minimal-evidence-depth.zh.md)负责一级上限，[片段恢复](2026-10-14-academic-fragment-priority-recovery.zh.md)负责派发预算与失败处理。这些决策继续有效。

## 考虑过的替代方案

**用完整抽取结果替换一级证据。** 不采用，因为新 ID 会使已提交引用失效，且不能保留初始抽取来源字段和方法。

**在卡片组装前丢弃所有重复摘录。** 不采用，因为一条已核验摘录可以支持更多分区或批准问题。

**合并不同版本或内容哈希。** 不采用，因为相同论文身份不能证明引文和定位指向同一内容。

## 后果

增强重新读取调用方提供的内容，不应用五条记录上限。它补充通过原文核验的材料，但不认证语义支持、独立审核或正式交付资格。初始 `not_extracted` 属性与补充分类一起保留。完整深度限制和明确的局部失败事实继续适用；工作流激活与真实模型校准属于独立工作。

## 验证

包内测试覆盖六分区补充、来源字段、抽取方法与身份保留、重复摘录的新分类、重复增强、被拒草稿、部分与全部模型失败、来源身份不匹配、取消和提交失败。现有一级与完整分片测试及固定工作流交接覆盖共享执行器。两个受影响的实现模块语句、分支、函数和行覆盖率均为 100%。
