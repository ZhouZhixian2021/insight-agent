# Agent Note: 论文准入先于聚焦证据抽取

Status: implemented

English | [中文](2026-10-11-academic-paper-screening-evidence-phases.md)

## Problem

每个全文批次的一次模型回答同时审核论文资格、选择逐字引文并填写六分区卡片属性。长论文因此重复判断准入，合并请求也可能耗尽单次时限仍不返回最终 JSON。

## Decision

带会话记录的生成器在抽取前使用首个有序证据批次判断一次论文范围。判断输入包含获批逐篇规则、来源元数据、抽样片段及 `sourceComplete` 标志，输出带理由的 `included`、`excluded` 或 `needs_more_context`。排除会跳过抽取；材料不足会暂停论文，不当作排除。纳入论文再发送不重复范围规则的逐题证据批次。

证据回答只包含来源片段索引、获批问题索引、单一陈述、逐字摘录及六分区之一。工作流校验精简 JSON，将未提供的分区属性映射为 `not_extracted`，并把精确来源匹配及卡片身份生成交给证据库。模型不能生成证据身份，也不能把无来源支持的引文变成记录。

现有 `academic/evidence-request` 和 `academic/evidence-result` 事件以 `phase` 字段记录两类调用。没有该字段的历史记录仍表示合并请求。结果记录包含尝试耗时、首段内容延迟及粗粒度失败阶段，不保存凭据，也不推断故障发生在哪一段网络链路。

证据请求触及本地时限后不会原样重复完整输入。`maxAttempts` 大于一时，生成器把该批次替换为两个更小的有序输入，不再次拆分子批次。多片段批次在片段之间拆分；单片段在 Unicode 字符边界拆分，并可保留有界重叠。范围判断及模型提供方报告的瞬时故障保持原有重试策略。每次尝试仍持久记录；一个子批次失败时，另一个子批次的合格证据仍会保留。

## Alternatives considered

**仅提高超时或重试次数。** 被否决，因为长时间推理却没有最终 JSON 时再次重试仍会耗尽一次调用，且无法把选文与证据生成分开。

**所有批次固定使用更少片段。** 被否决，因为相同模型路由的四片段请求仍分别耗时 114 秒和 132 秒，并且会让每篇长论文即使原本能成功也发起更多调用。只对超时批次缩小输入。

**要求模型在证据调用中填写所有卡片属性。** 被否决，因为缺失属性可以保守表示为 `not_extracted`，而记录与卡片分区仍可追溯到准确引文；属性补全可单独评估。

**抽样范围材料不足时直接排除论文。** 被否决，因为缺少文本不能证明获批规则不成立。

## Consequences

普通论文增加一次简短范围判断，但被排除论文不再调用证据模型，纳入论文也不再按批次重复判定。逐字引文拒收仍是权威规则。首批文本不完整时，无法证明未读文本满足全部规则；`needs_more_context` 会暂停论文，自动定向补取与复筛尚未实现。卡片特有属性在后续补全前保留 `not_extracted`。Web 控制器每次抽取允许 150 秒；超时拆分可能增加两次请求和可见批次数，因此改善的是恢复能力，而非保证单篇论文更快完成。本机耗时字段可区分准备、首段内容前及首段内容后失败；间歇性上游连接中断仍需网关日志定位。
