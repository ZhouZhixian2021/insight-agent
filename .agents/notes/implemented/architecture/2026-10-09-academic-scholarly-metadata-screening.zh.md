# Agent Note：属于指定版本的学术元数据初筛

状态：已实施

[English](2026-10-09-academic-scholarly-metadata-screening.md) | 中文

## 问题

提供方规范化丢弃了区分相关论文与偶然查询命中所需的摘要和关键词。把发现查询数量或匹配问题广度当作主题相关性，会惩罚专门研究某个问题的论文。把预印本文字混入发表版本，还会掩盖判断所依据的内容来源。

## 决策

Academic Source 记录在成果／版本对旁携带可选的摘要与关键词可用状态。支持这些字段的提供方从学术 API 数据或官方论文页摘要块填充它们。摄取库按版本保留元数据，同版本重复记录保留首份可用摘要，并合并可用关键词。缺失字段保持未知；其他版本的摘要和 Web 发现摘要均不能补充它们。

Academic Retrieval 通过 `assessPlannedCandidates()` 使用明确审核过的概念组、多语言别名、贡献信号、参考年份和时效窗口。默认初筛只从规范标题和学术摘要生成词项线索；关键词仅用于表层命中。研究问题的完整命中必须落在同一段原文引文中。已批准查询与问题的精确关联只承担发现路由，不证明问题得到支持。调用方可按成果提供外部审核结果，取代词项线索；`parseCandidateScreening()` 校验完整 JSON、原文引文和已批准问题。主题相关性取主题或单个问题的最高命中比例，使专门研究某个问题的论文保留主题分。方法与证据潜力使用独立的带引文线索，不依赖全文解析。来源质量记录书目信息完整度，不代表科学价值。未解决的自然语言范围判断保持未知；附有引文且经过审核的 `off_topic` 判断会排除该成果。

[共享排序策略](2026-09-29-academic-query-planning-candidate-ranking-contract.zh.md)仍是权重与优先级的唯一依据。Controller 提供已审核词项及按版本 ID 索引的明确全文事实，再把生成的判断交给现有排序器。Controller 接入与 Session 记录仍由消费方负责；纯初筛器不发起模型或网络调用。

Session 已审核的第 5 版学术计划携带每个研究问题的准确概念组、方法和证据线索，以及可选的贡献信号。Controller 随计划校验这些线索；旧计划不会凭空补充线索，首轮与证据缺口补检使用相同的审核结果。可读中文计划先解释线索含义，再给出结构化交接；线索只用于确定全文优先级，不确认论文已经纳入。

## 考虑过的替代方案

**把查询来源当作论文内容的证明。** 查询关联说明如何发现论文，不说明论文内容；问题覆盖广度与主题相关性也相互独立。获批查询关联在主题元数据命中后提供批次路由，不增加问题匹配分。

**在成果层合并所有可用摘要。** 预印本与发表版本可能提出不同声明；汇总文字会把声明错误归到规范版本。

**在检索库内嵌模型分类器。** 这会把传输、持久模型调用记录与纯排序逻辑混在一起。调用方可以提供审核结果，检索库负责校验引文并计算确定性结果。

## 影响

`matchedQuestions` 只保留附有引文的完整词项匹配，或附有引文的外部审核问题判断。排序器为这些匹配计分，并用规范元数据核验引文；Q5 调度器则单独读取已审核查询来源，决定证据缺口批次的先后。现有 `discoveredBy` 标识足以承担路由，不必新增公共字段或更改 Session 格式。

消费方无需更改已发布 Session 格式，即可获得可解释比例与缺失数据理由。中文研究问题可以保留其审核过的英文发现路径，也可以由单独审核的线索关联英文摘要与原问题。词项线索不理解否定表述、不验证方法，也不证明问题覆盖；审核过的主题或问题概念必须包含主题词。引文证明来源，不证明语义判断正确。稀疏目录记录在官方核验提供元数据前仍保持稀疏。[可执行交接样例](../../../../packages/academic/retrieval/tests/rank.spec.ts)覆盖专门研究、无关、多语言、外部审核及不完整记录；摄取测试保证版本隔离。
