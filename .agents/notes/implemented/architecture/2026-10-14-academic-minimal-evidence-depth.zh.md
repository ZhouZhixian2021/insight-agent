# Agent Note: 一级证据与完整抽取共用来源核验

Status: implemented

[English](2026-10-14-academic-minimal-evidence-depth.md) | 中文

## 问题

生成可追溯草稿不要求每篇论文填满完整证据卡。单次调用的记录上限无法约束多片段处理的整篇论文，没有问题关联的摘录也不能证明已批准问题得到覆盖。

## 决策

证据库在现有抽取输入上接受 `depth: 'minimal'`。一级抽取要求已批准的关注问题，逐条独立核验草稿的问题序号和逐字摘录，最多保留五条记录。完整抽取仍通过同一组入口提供。两种深度均返回现有记录、定位、问题关联与六分区卡片；空分区不表示完整审核通过。

分片抽取在来源重叠去重之后、调用方的已核验结果接收端之前，执行整篇论文的上限。保留的证据身份同时决定定位、问题关联与卡片引用。达到上限时停止派发，并把未处理范围返回为不完整项，与模型失败分别表达。可恢复的片段失败保留已核验的其他片段；取消、未分类失败和持久化失败使操作失败。

预期的草稿校验失败直接返回拒绝值，不捕获其他异常。模型提供的片段和问题序号仍须校验。私有片段序号来自已校验来源的打包器及其拆分；这些查找与非空提交依赖自身构造，不接收伪造的同进程范围。逐字摘录定位修复也只在确认恰好一个匹配后使用该匹配。

[准入与抽取分离](2026-10-11-academic-paper-screening-evidence-phases.zh.md)仍具有独立价值：准入、模型路由、持久请求与报告资格由工作流负责。[围绕问题阅读证据的决策](2026-10-12-academic-question-evidence-reading.zh.md)继续负责语义分析与独立审核。选择一级抽取不取代这两项决策。不修改共享 Academic Model 或 Session 数据格式。

## 考虑过的替代方案

**建立独立的一级证据记录或抽取器。** 拒绝，因为现有来源定位、记录与问题关联能够表达所需事实；第二套核验器会重复来源与摘录校验。

**只裁剪最终合并结果。** 拒绝，因为已核验结果接收端可能已持久化超过五条记录，并保留返回结果中不存在的卡片引用。

**要求完整卡片或从证据条数推断覆盖。** 拒绝，因为有效摘录可能只回答多个批准问题中的一个。调用方从缺少的问题关联推导未覆盖问题，并决定是否允许有限草稿。

## 后果

库的显式一级路径限制保留证据数，并在达到上限时避免继续调用。它保留局部证据，不认证语义支持或正式交付。[片段优先级与恢复](2026-10-14-academic-fragment-priority-recovery.zh.md)负责一级阅读顺序与缩小输入恢复；增强处理与真实模型性能校准属于独立工作。Academic 工作流在其负责人接入前不会选择一级深度。

## 验证

包内测试覆盖问题关联拒绝、摘录拒绝、单次与整篇上限、接收端保留身份、未派发的重试片段及固定 A-PE1 超时交接。现有抽取与分片测试覆盖取消、接收端失败和完整抽取。不宣称真实模型耗时改善。
