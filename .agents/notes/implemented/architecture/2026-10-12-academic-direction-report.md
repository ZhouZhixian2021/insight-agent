# Agent Note: The formal report follows the preset direction hierarchy

Status: implemented

English | [中文](2026-10-12-academic-direction-report.zh.md)

## Problem

The preset's report-format reference describes direction-level insight, but auxiliary synthesis receives a different prompt and reports are arranged by question. Skill loading during planning does not transfer those instructions into the later model request. Section names alone cannot supply direction structure or complete bibliography.

## Decision

The analysis package ships an exact projection of the preset reference, with an owner-local drift test, and includes it in full, compact and structural-repair requests. The existing model pass proposes bounded direction components referencing already cited statements. Labels organize approved questions; they cannot carry independent uncited claims. Each component needs references or an explicit missing-evidence reason. Themes are bounded at four and fewer than two require a shortage explanation. Quantitative components require full-text supporting records. Quarantined paragraphs also lose their direction references and themes.

The report renderer places scope, date window, date, source/version policies and executive insight before the direction map. Each direction renders themes, cited representative works, mechanism, result, judgment and audience-specific implications. Missing components are collected in methodology coverage limits. Cross-direction synthesis and final question answers reuse existing paragraphs. Canonical and actual evidence versions remain separate; dates retain source precision and missing metadata remains explicit. Stable identifier or safe source links accompany the bibliography. Numerical tables preserve separate conditions, while absent verified figures are disclosed rather than invented.

The optional direction field is analysis-owned output; existing inputs, shared paper/Claim types, Remote fields and model transport are unchanged. Existing question-only drafts remain readable with explicit incomplete-format issues. Direction reports still require independent review and cannot become final deliverables merely by matching the layout.

## Alternatives considered

**Read the preset file from a repository path at runtime.** Rejected because installed analysis packages and Web bundles do not own that filesystem path. The packaged projection works in both environments; the drift test requires review when the preset changes.

**Generate headings around question answers without adding validated direction components.** Rejected because it does not establish themes, mechanisms or coverage limitations for a direction.

**Generate a second free-form report or fill empty components.** Rejected because it introduces another model stage or untraceable prose. Existing statements and missing reasons supply the layout.

## Consequences

A and B keep their supplied materials and execution interfaces. The structural parser preserves old outputs but does not certify the semantics of labels, claimed numbers or implications; trusted content review remains necessary. The format and structured layout increase prompt/output size without changing owner-configured budgets. Package tests and the existing SDK snapshots pin new and existing output paths without a live-source smoke.
