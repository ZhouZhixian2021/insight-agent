# Agent Note：经审核的学术查询检索

状态：已实施

[English](2026-09-30-academic-reviewed-query-retrieval.md) | 中文

## 问题

共享检索计划定义了按渠道区分的查询与候选来源关系，但现有草稿工作流向学术源和 Web 渠道发送同一个表达式，无法按这些查询身份产生已核验候选。未经提供方核验的 Web 发现文字不能进入学术证据链。

## 决策

`dsh-academic-retrieval` 库根据已批准的 Brief、明确的提供方和结果上限、Brief 别名，以及调用方审核过的同义词或方法名生成首轮计划。它分别输出带 `SearchQueryId` 的学术源、Web 和指定站点查询。同一 Brief 版本的覆盖结果可在未使用的轮次追加数量受限的证据缺口查询。本库不从自由文本推断方法名，也不改变共享 Brief 格式。

单轮执行器按查询指定的渠道派发。Web 结果只有经过引用识别和获准学术提供方核验后才成为成果。每条查询分别报告发现、识别、核验、失败与上限事实。摄取库执行精确标识符去重和版本合并；可选的 `IngestRecord.discoveredBy` 查询 ID 在重复版本合并后仍保留，因此返回的成果到查询映射包含每条贡献记录。

Academic Controller 负责计划审核、Session 事件、运行时适配器、候选排序与后续批次决定。本库不调用模型，也不发布 Session 事件。

## 考虑过的替代方案

**把规划放入 Academic Source。** 这会使提供方选择服务承担 ResearchBrief 语义与摄取决定。

**把识别出的 Web 引用直接视为成果。** 识别只能从不可信 Web 内容抽取标识符，无法确定官方元数据或版本身份。

**从自由文本规则推断扩展词。** Brief 没有结构化方法术语字段；启发式推断可能未经审核就缩小或扩大检索范围。

## 影响

Controller 可以通过普通库接口集成 Q2/Q3，同时保留自身的审核与记录职责。调用方必须提供经审核的扩展词、执行适配器与预算。引文种子执行和持久化进度属于独立工作。聚焦测试覆盖查询上限与渠道分配、覆盖身份、未核验 Web 排除、部分失败、去重及合并后的查询来源关系。
