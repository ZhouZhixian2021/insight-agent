# Agent Note：经审核的事实驱动学术候选排序

Status: implemented

[English](2026-09-30-academic-candidate-ranking.md) | 中文

## 问题

Q3 产出已核验、去重的成果，但共享模型的 P0/P1/P2 策略还需要候选分类、硬条件判断、加权评分和多样化队列。提供方元数据缺少可靠的摘要、关键词、方法判断以及 Brief 自然语言规则的判定。仅凭标题或来源猜测这些事实，会悄悄把缺失数据变成准入决定。

## 决策

`rankPlannedCandidates()` 接收已批准的 Brief 与 Q2 计划、Q3 单轮结果，以及每项成果恰好一份经审核的 `CandidateAssessment`。判断记录提供摘要和关键词文本、语义比例、贡献信号、匹配问题、规则判定、全文可用性、多样性标签及解释事实。本库计算时间、文献类型、撤稿和词项硬过滤，不解析自然语言规则。缺少规则判定时拒绝排序调用。

排序器将零到一的语义比例换算为计划中的八项加权分数，使用共享的分数和优先级辅助函数，并保留各项分数及理由。它根据贡献信号分类，把每项成果放入 P0、P1、P2 或 excluded。每个非排除队列由最高分成果开头；后续位置优先选择此前未出现的来源、第一作者团队、匹配问题、分类及经审核的主题标签，再按分数决定同分顺序。多样性只改变次序，不暗中丢弃候选，也不改变其优先级。

## 考虑过的替代方案

**从稀疏的提供方元数据推断语义判断。** 标题和来源无法证明方法相关性、评估质量、全文可用性或自然语言排除规则。

**让模型直接给出最终分数和队列。** 这会绕过批准的权重，并隐藏优先级决定的理由。

**对每个标签施加固定配额。** Brief 没有批准多样性配额；隐藏上限可能丢弃合格成果。

## 结果

Academic Controller 可以提供经审核的判断，并把完整队列用于 Q5 分批，同时继续负责模型调用和 Session 记录。缺失或过期的判断会在调度前失败。这个纯库不增加运行时服务或模型可见输入；Controller 必须记录以后进入模型或用户视图的判断。
