# Agent Note：对话中的学术研究

Status: implemented

[English](2026-10-28-academic-chat-research.md) | 中文

## 问题

独立的最新研究弹窗使研究脱离原始问题，也难以区分后续批准计划与历史结果。

## 决策

C 客户端通过既有 Conversation 注册机制，为每次明确批准的原生或 PTC 计划调用贡献一个 academic-research 对话节点。普通计划、待审核和被拒审批不授权执行。渲染器使用 Controller 的 Session／批准调用 Brief 标识，读取当前批准及已保存任务，等待原始轮次正常完成且框架会话空闲后，再在调用既有后台 Remote 前核对批准。不会替换输入框、Agent Loop、来源或工作流。

卡片声明 groupTree: turn 并使用所属轮次的结束序号，避免过程折叠隐藏状态或结果。每张卡保留自己的 Brief 筛选、进度、证据、原报告和取消操作。持久后台状态将计划调用关联到准确任务 ID，因此恢复不依赖最近任务列表覆盖。返回历史卡读取同一任务。卸载只停止监听，只有明确取消才终止研究。卡片不会用新计划或其他运行的报告替代原结果。

## 考虑过的替代方案

共享最新结果面板会丢失逐请求归属。替换消息提交会重复 A 的计划和审批流程。标准 Chat 节点扩展保留官方输入框与已批准的后端操作。

## 影响

当前批准计划没有已保存任务时，每次挂载的卡自动尝试一次准入。响应丢失先重新发现，跨客户端仍以服务端准入为准。其他任务运行时禁止开始，等待卡提供刷新，不虚构排队机制。中断任务不会自动重新执行。前端准入要求卡片已经挂载，本次不增加服务端批准触发器。

定向回放和 DOM 测试覆盖两轮研究、原生／PTC 批准、拒绝计划、独立报告、StrictMode、最近列表之外的历史恢复、取消和监听释放。生产 Client Loader 启动正式 Web 依赖组合。固定材料检查不覆盖真实模型端到端运行或浏览器视觉录制。
