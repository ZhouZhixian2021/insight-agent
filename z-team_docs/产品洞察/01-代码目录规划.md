# 产品洞察代码目录规划

[返回产品洞察资料目录](00-目录.md)

本文用于回答“产品洞察代码写到哪里”。以下路径均相对 `insight-agent` 仓库根目录。产品洞察依赖现有 DSH 基座，通过插件、服务和组合包接入；业务实现集中在 `packages/product-insight/`，与学术洞察并列。当前七个目录仅有 `.gitkeep` 占位文件，尚无功能实现；目录职责是开发约定，不代表功能已经交付。

| 代码目录 | 负责的内容 | 不放在这里的内容 |
| --- | --- | --- |
| [`packages/product-insight/model/`](../../packages/product-insight/model/) | 产品、版本、来源、证据、结论及任务状态的领域类型与纯规则；定义跨模块交换的契约 | 网络请求、模型调用、界面逻辑 |
| [`packages/product-insight/source/`](../../packages/product-insight/source/) | 产品官网、技术文档等来源的访问、身份核验和数据标准化；按来源扩展适配器 | 跨来源研究编排、报告写作 |
| [`packages/product-insight/workflow/`](../../packages/product-insight/workflow/) | 根据获批任务组织检索、证据核验、分析与报告生成；记录进度、停止条件和部分失败 | 具体来源协议、页面交互 |
| [`packages/product-insight/report/`](../../packages/product-insight/report/) | 产品洞察报告结构、引用与限制披露、渲染和交付检查 | 获取原始来源、启动后台任务 |
| [`packages/product-insight/controller/`](../../packages/product-insight/controller/) | 对接 DSH 的会话、审批、后台运行和查询接口；把页面请求交给工作流 | 产品证据算法、报告正文规则 |
| [`packages/product-insight/ui-research/`](../../packages/product-insight/ui-research/) | 产品洞察的计划、进度、证据和报告页面；按需接入 DSH Web | 后端审批与研究执行 |
| [`packages/product-insight/bundle/`](../../packages/product-insight/bundle/) | 产品预设、技能及配置补丁；装配 DSH 基座、产品后端和页面 | 业务算法及持久数据模型 |

## 依赖边界

- `model` 是产品业务的底层契约；`source`、`workflow` 和 `report` 依赖它，`controller` 调用工作流，页面通过公开接口读取后端结果，`bundle` 只负责装配。
- DSH 的模型、工具、会话、存储、Web 等通用能力沿用基座的公开服务和插件扩展点。产品专用行为写在本目录，避免修改上游的 agent loop 或公共页面来承载产品规则。
- 学术洞察可供参考方法和接口设计，但产品代码不直接导入其内部源码路径。跨业务证据复用需要稳定、明确的共享契约；现阶段不把规划中的共享证据库当作已实现依赖。
- 新增功能先确认上述目录的所有权；确有独立构建或依赖边界时再拆新包。各目录开始实现时分别补充包清单、源码、测试和使用说明。

本文件只确定代码落位。需求范围、接口字段、成员分工和验收标准将在后续文档中确定。
