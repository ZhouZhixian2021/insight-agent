# 故障对照表

[返回部署运维目录](00-目录.md)

症状 → 病因。遇到问题先查这里，多数情况不需要改代码。

## 启动与配置

| 症状 | 病因 | 处理 |
|---|---|---|
| 模式列表里没有「产品洞察」 | bundle 的 preset 行装载失败，整个预设被标记 broken，前端会过滤掉坏预设 | 见下方专条 |
| 模式列表里其它模式也没有 | profile 的 `dsh.profile.bundles` 没写对应的 bundle | 检查 `.dsh-runtime/profiles/web/package.json` |
| 启动报 `Cannot find module .../apps/cli/lib/bin.js` | 没有构建 | `pnpm run build:artifacts` |
| 启动报端口被占用 | 另一个实例还在跑 | 换端口，或先停掉旧实例 |
| 网页打开后立刻被拒 | 没带 token | 用终端打印的完整地址（含 `?token=`）打开 |
| GUI 起不来、报临时目录相关错误 | `TEMP` 落在工作区里 | 把 `TEMP` 设到工作区外（如 `D:\tmp`） |

### 专条：产品洞察模式消失

判定依据：打开的页面里，`conversation.chat.node` 仍注册着 `product-insight-run`，说明客户端加载正常；但模式下拉框里没有条目。

成因：预设里的某一行插件解析不到，例如 bundle 的 `dependencies` 里缺了 `@deepseek-ai/dsh-product-insight-workflow`。该行报 `never started`，预设被判为 broken，前端只显示健康预设。

处理：

1. 先确认依赖声明在 `dependencies` 而不是只在 `devDependencies`
2. 重新构建并重启
3. 若仍出现，去设置页的预设管理区查看标红的失败原因，那行会写明是哪个模块、什么错误

## 运行结果异常

| 症状 | 病因 | 处理 |
|---|---|---|
| 0 证据、几十秒就结束 | `maxTokens` 配成了与 `contextWindow` 相同或接近 | 输出预留必须明显小于窗口，见[配置参考](03-配置参考.md) |
| 报告是「草稿」，只有已核对要点 | 报告合成被输出上限截断，或整段输入塞不进窗口 | 降低推理档位，或调大 `maxTokens` |
| 单轮耗时 30 分钟以上 | 推理档位为 `max` | 改为 `high` 或默认档 |
| 证据很少（< 40 条） | 抓取失败率高，或候选池太小 | 看下一节 |
| `verifications` 恒为 0 | 跨源核验功能尚未接线，不是配置问题 | 已知遗留，无需排查 |

## 抓取与来源

| 症状 | 病因 | 处理 |
|---|---|---|
| 一半页面抓不到，日志有 403 | 站点反爬，已重试一次浏览器 UA 后仍被拒 | 无法处理，属对方站点行为 |
| 页面报 `cross-origin redirect` | 搜索结果是跳转链接，传输层默认不跨源 | 已默认开启，若仍然出现说明是配置被改动 |
| 候选里混进无关页面 | 相关性判定被关闭，或查询过长 | 检查引擎配置与查询长度（上限 60 字符） |
| 搜索诊断出现「冷却中跳过：xxx」 | 该引擎连续失败触发熔断 | 正常行为，冷却结束会自动恢复 |
| 全部搜索都失败 | 三个引擎同时不可用 | 官方订阅源与新闻源仍会工作，检查网络是否能访问外网 |

## 语义与审核

| 症状 | 病因 | 处理 |
|---|---|---|
| 日志大量 `invalid_start_hint` | 模型给出的摘录定位不准确，属模型输出质量问题 | 已知问题，影响的是单条证据，不影响整轮 |
| 结论数远少于证据数 | 部分证据没有构成可审核的结论 | 正常，一条结论可覆盖多条证据 |

## 排查顺序建议

1. **先看结算状态**（`final` / `draft` / `blocked`），它决定问题性质
2. **再看证据条数**，0 条基本是配置问题
3. **最后看抓取失败明细**，那是站点问题不是代码问题

会话记录里能直接看到这些字段，不需要读源码。
