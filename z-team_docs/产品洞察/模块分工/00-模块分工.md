# 产品洞察模块分工

[返回产品洞察资料目录](../00-目录.md) · [代码目录规划](../01-代码目录规划.md) · [首版共享字段方案](../接口约定/00-首版共享字段方案.md)

本页记录产品洞察的开发分工，负责人为 A（周玉萍）和 C（赵金昊）。首阶段面向软件和 AI 服务类产品，回答单个产品的功能与现状；以下是开发安排，不表示功能已经实现。业务代码按现有 `packages/product-insight/` 的七个目录组织。

## 负责人及代码范围

| 负责人 | 代码范围 | 主要交付 |
| --- | --- | --- |
| A | `model/`；`source/` 的网页发现、来源核对与候选筛选；`workflow/`、`controller/`、`bundle/` | 统一字段和计划，找到并筛出适合调查的网页，组织审批、后台运行、失败恢复、补充资料及整体接入 |
| C | `source/` 的正文获取、解析与证据提取；`report/`、`ui-research/` | 从入选网页提取可定位的原文依据，分析功能与使用条件，检查结论质量，生成报告并完成页面展示 |

`source/` 由两人按文件范围协作：A 负责网页发现和初筛，C 负责正文与证据；A 负责汇合该包的公开入口。具体子目录在代码迁入时确定，不增加代码包。

## 工作交接

1. A 先确定 `model/` 的共享字段，包括产品身份、获批计划、候选网页、资料快照、证据、结论、证据缺口及报告状态；写清标识符、必填项、时间与版本口径和状态含义。C 核对证据提取、分析、报告和页面所需字段，A 汇总意见并确定首版接口。完成这一步后再分别迁移代码。
2. A 向 C 交付候选网页清单，包括产品身份、网址、来源类型、标题、与调查问题的关系及入选或排除理由。A 不负责逐页提取功能证据。
3. C 从入选网页获取正文，记录证据原文、所在位置、资料版本或获取时间，以及对应的调查问题。
4. C 将证据、结论和证据缺口交给 A 的工作流；A 根据缺口安排补查，保留已有成果。C 负责结论检查、报告和页面，A 负责将各步骤接成完整流程。

首版字段范围见[共享字段方案](../接口约定/00-首版共享字段方案.md)，正式类型以 `model/` 的公开接口为准。迁移时借鉴学术洞察已有实现，并把论文专用的来源、版本和报告规则改为产品语义；分工不以学术洞察现有包数为准。
