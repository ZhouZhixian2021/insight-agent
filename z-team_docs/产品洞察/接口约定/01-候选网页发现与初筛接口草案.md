# 候选网页发现与初筛接口草案

[返回产品洞察资料目录](../00-目录.md) · [共享字段方案](00-首版共享字段方案.md) · [A、C 分工](../模块分工/00-模块分工.md)

本页供 A、C 核对 `packages/product-insight/source/` 中 A 负责的接口。网页发现与初筛入口已实现，C 的正文与证据部分尚未接入。接口从已获批的产品调查计划发现网页，交付逐条说明筛选决定的候选清单，并保留各次搜索的结果与失败。

## 输入

公开入口为 `discoverCandidatePages(input, adapters, signal?)`。`input` 包含现有 `Product`、`ProductPlan`，以及部署配置的单次搜索结果上限；`adapters.web.search(request, signal)` 由接入层连接 DSH `ctx.web.search()`。调用方持有计划与产品，`source` 不读取会话或自行批准计划。

| 输入 | 要求 |
| --- | --- |
| `product` | `productId` 与计划一致，包含名称、官网及可选别名。 |
| `plan` | `isExecutableProductPlan(plan)` 为真；按计划当前版本的 `questions`、`scope` 和 `limits` 执行。 |
| `maxResultsPerQuery` | 部署明确给出的正整数上限；实际请求取它与计划候选总量上限的较小值。 |
| `adapters.web.search` | 接受 DSH `WebSearchRequest` 并返回 `WebSearchResult`；允许替换搜索提供方和定向验证。 |
| `adapters.now` | 提供本次运行的记录时间。 |
| `signal` | 可选取消信号，传递给每次 Web 搜索。 |

首版每个调查问题生成一条搜索请求，搜索词由产品名称、该问题和已批准的范围组成。调用方无需为手机、软件等品类提供专用字段。查询文本、对应问题及执行结果必须记入返回的搜索记录；后续证据缺口补查由工作流发起另一轮，不暗中增加本轮查询。

## 输出

`ProductDiscoveryResult` 包含 `candidates: ProductBatchResult<CandidatePage>`、`searches: ProductSearchAttempt[]` 和 `cancelled`。`candidates.items` 保留本轮记录的选中、排除和待核对网页；C 只处理其中 `screening.status === 'selected'` 的网页。`candidates.failures` 保留搜索失败，`searches` 还记录成功但结果为零的搜索。

| `ProductSearchAttempt` 字段 | 含义 |
| --- | --- |
| `questionId`、`query` | 本次实际搜索的问题及完整查询文本。 |
| `status` | `success`、`failed`、`cancelled` 或 `skipped`；成功且没有网页仍是 `success`。 |
| `returnedCount`、`recordedCount` | 提供方返回数量与实际写入候选清单数量；失败时不伪造数量。 |
| `truncated` | DSH 或候选总量上限是否使结果未被完整记录。 |
| `failureId?` | 失败时指向 `candidates.failures` 中的 `ProductFailure`。 |

候选网页沿用 `CandidatePage`：稳定网页 ID、计划及产品 ID、URL、标题（如来源提供）、来源类型、发现时间、关联的问题 ID，以及 `selected`／`excluded`／`needs_review` 决定、理由和时间。同一 URL 被多个查询找到时只保留一条候选记录，合并关联的问题；`ProductSearchAttempt` 仍分别记录每次搜索。

## 筛选与来源规则

1. 检查 URL 是否为合法 HTTP(S) 地址，识别相同页面；去重只移除片段和明确的跟踪参数，不随意删除可能改变页面内容的查询参数。实际网页访问由后续获取模块进行安全校验。
2. 根据产品身份、网页标题与搜索摘要做初筛。无效网址标为 `excluded`；无法判断发布方或关联性的网页标为 `needs_review`，不能猜测其内容。
3. `sourceType` 表示网页用途，不能单独证明发布方可靠。只有经核对的官方站点才标注官方来源；其他站点记录实际发布方和核对理由。官方域名判断使用解析后的主机名，不使用字符串包含判断。
4. 筛选理由说明与哪个问题相关、选择或排除的具体原因。搜索摘要只用于初筛，不成为 `ProductEvidence`；C 获取网页正文后再建立资料快照和可定位证据。

## 失败、上限与取消

- 每条查询独立结算。某次搜索失败时生成 `ProductFailure(stage: 'discovery')` 和对应 `ProductSearchAttempt`，保留其他查询已得到的候选网页；结果状态由现有 `createProductBatchResult` 按实际候选与失败计算。
- 某条搜索结果的网址无效时只将该网页排除，不丢弃同次搜索的其他网页。没有可用搜索提供方时如实记录失败，不生成空的成功清单。
- 候选数量或时间达到已批准的上限时停止继续派发；搜索记录注明截断或未执行原因。取消时停止新请求，保留已结算的记录，由工作流标记运行取消，不能把取消伪装成完整成功。
- `WebSearchResult.content` 是提供方可能生成的回答，不进入候选网页或证据；`sources[]` 中缺失的标题、日期和发布方不能推断补齐。

## 与现有 `model` 的差异（待核对）

`CandidatePage.title` 已改为可选，以匹配 DSH 搜索结果；页面没有标题时展示层使用 URL 作标签，不把 URL 假装成原始标题。`ProductSearchAttempt` 和 `ProductDiscoveryResult` 由 `source` 定义；工作流需要恢复时保存返回值。现有 `CandidatePage.questionIds` 足以记录一页关联的多个问题，不增加产品品类字段。

## 交接与验收

A 交给 C 的是选中网页及完整筛选清单、每条搜索的状态和失败原因。C 不必重新搜索，即可按 URL 读取入选页面；若正文与搜索摘要不符，C 记录获取或证据问题并交回工作流补查。

定向验收覆盖：未获批计划拒绝执行；同页多问题合并且保留关联；缺标题不伪造；无结果搜索如实记录；一条搜索失败后其他成功网页仍在清单中；达到上限时说明截断。不做冒烟测试。
