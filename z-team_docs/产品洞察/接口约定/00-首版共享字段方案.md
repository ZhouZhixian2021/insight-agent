# 产品洞察首版共享字段方案

[返回产品洞察资料目录](../00-目录.md) · [A、C 模块分工](../模块分工/00-模块分工.md)

本方案由 A 确定，供 A、C 迁移产品洞察代码时使用。首阶段调查单个软件或 AI 服务类产品的功能与现状。首版字段已在 [`packages/product-insight/model/`](../../../packages/product-insight/model/README.zh.md) 中落地；C 仍需按证据提取、分析、报告和页面的实际使用核对这些字段。

## 共享对象

| 对象 | 必需内容 | 可选内容 | 产生方 |
| --- | --- | --- | --- |
| 产品 | 稳定产品 ID、名称、开发方、官网 | 别名、类别 | A |
| 调查计划 | 计划 ID、版本、产品 ID、调查问题及其 ID、调查范围、审批状态 | 资料数量与运行时间上限 | A |
| 候选网页 | 网页 ID、所属计划、网址、来源类型、发现时间、关联问题 ID、入选或排除决定及理由 | 标题、发布方、发现渠道 | A |
| 资料快照 | 快照 ID、候选网页 ID、获取时间、获取结果；成功时的正文存储位置和内容校验值，失败时的失败记录 | 网页发布日期、更新日期、产品版本号 | C |
| 证据 | 证据 ID、资料快照 ID、原文、来源陈述、原文位置、关联问题 ID、提取方式 | 质量说明 | C |
| 结论 | 结论 ID、内容、适用范围、证据关联、可信等级及理由 | 不确定性、相反证据 | C |
| 证据缺口 | 缺口 ID、关联问题 ID、缺少的内容、原因、处理状态 | 建议补查的资料类型 | C 提出，A 安排补查 |
| 运行与报告结果 | 运行 ID、计划 ID、运行状态与失败记录；报告 ID、核对日期、交付状态、结论与限制 | 导出文件位置 | A 记录运行，C 产出报告 |

候选网页是 A 交给 C 的处理清单。C 从入选网页形成资料快照与证据，并将证据、缺口和报告结果交回 A 的工作流。正文在存储位置保存；进度与会话记录通过引用和内容校验值识别它，避免重复保存整页内容。

## 首版判断规则

1. 审批记录指向计划的具体版本。只有获批版本与准备执行的计划版本一致，工作流才能启动。
2. A 核对网页是否属于目标产品及其发布方，记录来源类型和筛选理由。首版以产品官网、官方文档和官方发布记录为主要来源。
3. 资料获取失败时保留失败记录，不伪造正文或内容校验值；其他已取得的资料和证据继续保留。
4. 产品版本号可缺省。资料的发布日期、网页更新日期和本次获取时间分别记录；报告的核对日期以本次实际处理的资料为准。
5. 每条证据指向具体资料快照和原文位置。结论记录支持、反对或仅作背景的证据关系，并说明适用条件；资料更新后重新检查旧结论是否仍可用。
6. 运行状态区分完整成功、部分成功、失败和取消；报告交付状态另行区分可交付、注明不足的草稿和无法形成结论。没有有效证据时不生成确定结论。
7. C 对未回答的问题给出具体证据缺口。A 根据缺口安排补查时保留已有证据与报告草稿。

具体状态值和字段类型见 [`model/` 的公开接口](../../../packages/product-insight/model/src/index.ts)；不可信输入的校验由接收该输入的模块负责。A 修改共享字段时先与 C 核对其证据、报告和页面的使用方式。
