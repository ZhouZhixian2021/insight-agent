# 搜索结果导航页过滤

成员 A，分支 dev/zhouzhixian2021-new。本地开发，未提交或推送。

## 问题

上一轮的 30 个候选里有 5 个站点导航页：`www.apple.com/`、`www.apple.com/store`、`account.apple.com/`、`account.apple.com/sign-in`、`www.apple.com/mac/`。前四个一共消耗 4 次抓取、产出 0 条证据，其中 `apple.com/store` 抓到了 88,504 字符的商店首页。

上一轮的计划链接过滤只挡住“计划里写的链接”，挡不住搜索引擎带回来的导航页。

## 修改

`source/src/index.ts` 在发现结束、进入抓取前对候选池做一次排除：

- 账户、购物车与搜索页（`account.`、`login.`、`signin.`、`cart.`、`checkout.` 主机，`/account`、`/login`、`/signin`、`/cart`、`/checkout`、`/bag`、`/search` 路径）在任何主机、任何深度都排除；
- 站点根路径、纯地区前缀（`/zh/`、`/en-us/`）与商店索引（`/store`、`/shop` 根）只在同一主机还有更深页面时排除；
- 商店索引之下的配置页（`/shop/buy-mac/m6-chip-12-core`）保留，支持主机下的文章页（`support.../zh-cn/128108`）保留。

最初的实现只做“先占名额、后排除”：实测一轮后导航页确实被排除，但它们占掉的 4 个名额没有被候补页面填补，抓取从 25 页降到 16 页、证据从 124 条降到 78 条。因此改为在名额分配前排序，入口页排在最后，内容页先占名额。

判定复用现有的 `screening.status` 与 `screening.reason`，不新增字段，也不改变会话记录结构。

## 验证

- 新增 6 个用例：账户与购物车页排除；根路径作为唯一页面时保留；根路径与地区前缀在有更深页面时排除；商店索引排除而配置页保留；支持主机文章页保留；名额不足时内容页优先占位。
- `vitest run packages/product-insight`：138 项通过（新增 6 项）；`pnpm run typecheck`、`pnpm run build:artifacts` 通过。
- 用上一轮真实的 30 个网址回放：排除 4 个（`www.apple.com/`、`www.apple.com/store`、`account.apple.com/`、`account.apple.com/sign-in`），这 4 个原本产出 0 条证据。
- 名额 26、返回 30 个网址回放：记录 26 个，全部为内容页，排除 0 个，入口页没有占用任何名额。

## 限制

- `www.apple.com/mac/` 这类产品目录页没有排除：它同样是 0 证据，但与内容页难以区分，强行排除可能误伤小站的产品分类页。
- 单页产品（首页即全部内容）只在没有更深页面时保留首页；一旦搜索引擎同时返回一个子页，首页会被排除。
- 规则只看网址，不看标题和正文，站点改版后可能失效。
- 效果需要在不同产品上多跑几轮才能确认；若误伤明显，删除 `dropRedundantNavigation` 的调用即可回到原行为。
