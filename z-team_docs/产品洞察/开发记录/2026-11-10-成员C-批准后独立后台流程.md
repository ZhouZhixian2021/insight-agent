# 产品洞察批准后独立后台流程

- 负责人：成员 C（ykxy11）
- 状态：本地开发，未提交、未推送。

## 问题与改动

原产品预设要求聊天模型启动任务、等待通知并读取结果；通用任务完成通知会唤醒模型，导致正式保存的报告之外又搜索、撰写一次。

复用现有计划组件的 concludeOnApprove：明确批准后结束聊天轮次。产品工作流监听成功批准及随后 idle 边界，重新读取并核对持久化批准，再启动现有调查。保留计划身份、已完成结果与活动任务去重检查；失败启动写入既有后台状态，页面显示原因。

产品模式自行注册任务控制器，移除本模式的通用 job 工具及完成通知，不修改其他模式或通用 Agent Loop。原始后台取证、分析、审核、报告生成流程保持使用。run_product_investigation 用于明确续跑；新增 cancel_product_investigation 用于取消。结果读取和续跑工具结束当轮，避免自动重写。新用户研究请求仍重新生成并审批计划。

## 验证

正式 Web 装配用例验证预设工具、自动交接、报告成功、失败草稿及同会话连续研究；检查批准与任务完成后没有额外聊天模型调用。采用固定网页与模型响应，不运行付费真实调查。最终检查结果见本次交付说明。

## 使用与限制

重启 pnpm run insight:web，新建产品洞察会话。批准后直接观察对话卡，报告保存后下载 HTML/Markdown。历史未完成计划需明确要求续跑；新机制不自动重启旧任务。没有增加新的 Session 事件类型。真实网页质量和模型取证质量仍受搜索与证据材料影响。
