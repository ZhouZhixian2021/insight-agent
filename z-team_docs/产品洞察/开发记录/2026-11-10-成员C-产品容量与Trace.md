# 产品调查容量与 Trace 开发记录

## 目标

减少固定字符数和证据数量配额造成的信息损失，提前排除未批准的来源域名，并在产品调查卡提供可下载的运行追踪。

## 实现

- 新计划候选网页上限 30；不默认填写 20 分钟总时限和页面正文字符限额。历史计划的明确额度继续履行。
- 多源查询合并返回上限调整为 60；模型辅助识别搜索页的观察上限调整为 20,000 字符、100 个链接。这些是上限，不保证搜索引擎返回对应数量。
- 外部域名须匹配批准来源后才抓取；版本、地区、日期等依赖实际正文的条件仍在读取后核对，不能提前保证其合格。
- 新计划使用清理后的完整正文；按已配置的模型上下文和输出预留容量判断是否分段。取消 PDF 的旧业务大小/页数门槛，保留传输、解析、取消与网址安全保护。
- 取消每页八条、摘录 1500 字符、陈述 600 字符、每题两条综合证据、报告 64 KB 等内容配额；所有合格关联证据可以进入综合。正文相同引用链接去重，证据记录保留。
- 调用遵循模型路由配置的输出容量，不再额外压到 4096 token 或单次 60 秒；网络层超时仍有效。
- 产品卡支持追踪条目展开、状态筛选及 JSON 下载；记录真实事件时间、模型输入输出规模、失败与阶段事实，不生成虚构百分比。下载的是运行摘要，完整模型内容仍以 Session 记录为准。
- 写作提示强调机制、条件、差异与结论，避免每句话重复“某来源称”，同时保持官方宣传、测试结果和未知项的区别。

## 验证

- 五个相关测试文件：73 项通过。
- 单个已装配产品预设集成用例通过；没有运行全套端到端测试。
- 完整构建 9 项门禁通过；产品目录静态检查通过。
- 升级说明校验、持久化字段兼容记录及 git diff --check 通过。
- 未运行付费模型或整轮真实联网调查；浏览器实测由后续本地试用确认。

## 已知限制与使用方式

需要重启服务并批准新计划才能使用新默认值。历史明确批准的上限不会被静默解除。
模型上下文未配置时，无法提前精确判断容量，最终由模型服务校验；分段及增加证据可能提高 token 和运行耗时。传输仍保留 64 MiB 响应、16,777,216 字符正文等工程保护；不是无限下载。
来源预筛选只检查已批准域名，不能替代正文事实、版本与语义核验。历史缺少 planId 的模型事件不会猜测挂到当前 Trace。
