# 搜索结果来源引擎标注

成员 A，分支 dev/zhouzhixian2021-new。本地开发，未提交或推送。

## 问题

发现流程把 DuckDuckGo、Bing、Yahoo 的结果合并去重后只保留网址和标题，丢失了“哪个引擎返回的”这一信息。评测里能看到每轮有若干条零产出页，但无法判断是某个引擎的解析把热门推荐卡片当成了搜索结果，还是搜索词本身召回了噪声，也就无法决定该修哪里。

## 修改

`source/src/multi-search.ts` 在合并时为每条来源带上 `engine`，保留去重后的首个引擎。`source/src/index.ts` 的候选页把来源写进已有的 `discoveryChannel`：有引擎写 `web:<engine>`，计划阶段带入的链接仍写 `web`。评测脚本增加“垃圾来源”一列，按引擎统计零产出页。

## 验证

- 新增两个用例：合并后的来源逐条带引擎；候选页按来源写成 `web:yahoo` 或 `web`。快照同步更新。
- `pnpm exec vitest run packages/product-insight`：109 项通过；`pnpm run typecheck`、`oxlint`、`pnpm run build:artifacts` 全部通过。
- 实跑一轮：引擎分布为 DuckDuckGo 9、Bing 9、Yahoo 4、计划链接 8；3 条零产出页分别为 DuckDuckGo 1、Bing 1、计划链接 1。

## 限制

- 结论是“没有单一引擎问题源”，垃圾页是分散噪声，原先“修某个引擎的热门卡片选择器”的假设不再成立。
- `web` 只表示计划阶段的链接，无法再细分到具体来源。
- 标注只增加可观测性，不改变筛选和排序行为。
