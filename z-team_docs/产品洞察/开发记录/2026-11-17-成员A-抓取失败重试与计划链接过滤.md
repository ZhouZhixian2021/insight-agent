# 抓取失败重试与计划链接过滤

成员 A，分支 dev/zhouzhixian2021-new。本地开发，未提交或推送。

## 问题

30 个候选页里有 12 个抓取失败，其中 8 次是 HTTP 403，集中在知乎（5 次）和百度百科（1 次）；这些站点对非浏览器 UA 直接拒绝，导致页面正文根本进不了提取环节。另一类浪费在计划阶段：模型规划时带入的站点根路径和支持页（`www.apple.com/`、`support.google.com`）照样占用候选名额、被抓取、被送进提取，最后一条证据都没有。上一轮 7 个零产出页里有 4 个属于这一类。

## 修改

`source/src/web-provider.ts` 的公开网页读取遇到 403、405、429、503 时，用同一个受控传输、换浏览器式 User-Agent 重试一次；重试仍失败则返回原始状态，行为与改动前一致。传输限制（超时、大小上限、重定向次数、公网地址解析）全部沿用，浏览器不直接联网。

`source/src/index.ts` 在候选入池前过滤计划链接：站点根路径、`support.` / `help.` / `account.` / `login.` / `signin.` 开头的域名，以及以 `/support`、`/help`、`/login`、`/account`、`/cart`、`/shop`、`/store`、`/search` 开头的路径都不再作为计划链接入池。规则只作用于计划链接，搜索引擎返回的结果不受影响。

## 验证

- 403 重试：新增用例覆盖“重试成功”和“重试仍被拦”两种结果，确认第二次请求只发一次且失败时保留原状态。
- 计划链接过滤：新增用例确认支持页和根路径被丢弃、内容子页保留。
- `pnpm exec vitest run packages/product-insight`：110 项通过；`pnpm run typecheck` 5 个 gate、`pnpm run test:docs` 21 个 gate、`pnpm run build:artifacts` 7 个 gate 全部通过。
- 实测一轮：403 从 8 次降到 2 次，失败从 14 次降到 10 次，抓取成功从 18/30 升到 20/30，耗时从 32.25 分降到 24.55 分。

## 限制

- Cloudflare 一类需要执行 JS 才能通过的挑战页仍会失败；需要登录的页面换 UA 也拿不到正文。
- 计划链接过滤可能误伤只有根路径的小站，目前尚未实跑验证过滤后的效果。
- 失败分类仍是 `parse_failed`，403 与解析失败混在一起，统计时需要按消息里的状态码区分。
- 还有 2 次 `URL exceeds the maximum length of 2048` 的畸形链接，属于另一个待处理问题。
- 本轮有效页率从 83% 降到 65%，原因是搜索结果构成变化（多出 7 个官网支持页），不是这两处改动造成的回归；需要更多轮次确认。
