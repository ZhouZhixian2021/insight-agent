# 候选初筛顺序调整

## 问题与处理

用户指出，全局候选数量限制先于日期、版本状态和全文地址初筛，会让不合格论文占用名额，排在后面的合格论文没有机会进入处理流程。

在 [workflow 流水线](../../packages/academic/workflow/src/pipeline.ts)中移除跨查询去重后的提前截断。所有已返回的去重论文先交给选择器，按日期、版本、撤稿、预印本许可和来源提供的全文地址筛选，再保留有效候选上限内的合格论文。选择器接收的有效上限取已批准计划与请求上限的较小值；选文结果仍在下载前完整校验。

`coverageSummary.deduplicatedWorks` 继续统计初筛前的实际去重论文数；`academicWorkIds` 记录初筛后通过校验的候选。在选文前取消的运行不会记录尚未选中的论文 ID。

## 边界

每条查询的搜索结果上限、Web 发现和引用核验预算保持不变，因此未被来源返回的论文不会自动补回。全文地址初筛不下载全部论文，也不保证地址可访问或全文能够解析。下载、解析、模型范围审查、证据核验和最终纳入上限继续执行原有规则；论文处理并发不变。

本次没有调整模型范围判断、报告合成或用户已经批准的研究问题，也没有重新运行真实研究。增加合格候选的机会不等于保证最终报告成功。

- 工作流与 Controller 测试共 13 个文件、290 项通过。

- 无密钥 SDK Loader 会话快照更新并独立回放通过，确认第一篇日期不符时，第二篇合格论文仍获得唯一候选名额。
- Host 类型构建通过，文档快速检查 15/15、完整文档同步检查 33/33 通过。全量 lint 发现本次新增测试的格式与类型标注问题，修正后变更范围 lint 通过。
