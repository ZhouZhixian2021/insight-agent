成员 B 在实现来源检索与摄取事实时，需要确认 Provider 活动粒度、摄取统计含义、论文身份字段及证据分段职责。本次由 A 补齐共享进度接口和团队分工说明，使 B、C 可以按同一组字段继续开发。

## 已完成

1. 进度计数新增 `mergedWorkIdentities`、`mergedVersionRecords`、`retainedWorkVersions` 和 `suspectedDuplicateRecords`，不再把不同摄取审计决定压成一个“去重数”。
2. `mergedWorkIdentities` 表示 `merged_work` 审计条目数；`mergedVersionRecords` 表示 `merged_version` 条目数；`retainedWorkVersions` 表示当前摄取结果最终保留的 `outcome.versions.length`；`suspectedDuplicateRecords` 表示 `suspected_duplicate` 条目数。
3. 论文活动同时携带 `AcademicWorkId` 与 `WorkVersionId`，便于 C 将进度行与论文、版本和后续证据关联。
4. 共享活动类型新增直接学术 Provider 活动，包含 Provider、查询序号、运行或终态、结果数、失败分类以及开始和完成时间。
5. 工作流在摄取完成后填写四类摄取计数；固定 JSON 样例增加 Provider 运行活动、四类计数和论文双 ID。
6. 明确 B 的 Provider 观察者只发布无时间戳的来源事实，A 在接收时记录时间并投影到进度快照。
7. 明确 Web 发现、引用识别和逐条核验的实时事实由 A 的混合检索编排层发布，B 不扩展 `verifyReference()`。
8. 明确证据分段与重试进度由 A 的工作流模型适配层映射，B 保持现有 `EvidenceGenerator` 接口。
9. 补齐 A-P3 的 `AcademicResearchRunFrame` 文档类型链接，使 Cordis 服务目录能够定位实时流返回类型。
10. 拉取 C 的实时进度页面后重新生成配置与持久化目录，更新其源文件行号，恢复完整文档门禁。
11. C 的页面已在 A 开发期间合并到 master；A 同步补充 `provider_updated` 中英文文案、Provider 当前活动与最近事件展示，保证共享进度联合类型的新增分支被客户端完整消费。

## B 的接口约定

- `AcademicSourceRuntime.searchAll()` 和 `searchProviders()` 接受可选 Provider 观察者。
- 每个实际启动的 Provider 先发布一次 `started`，再恰好发布一次 `success`、`failed` 或 `cancelled`；零结果属于成功。
- 观察者异常被隔离，不能改变搜索结果；整轮取消时，在途 Provider 发布 `cancelled`。
- `summarizeIngestAudit(outcome)` 应返回四项统计，并采用本记录中的字段名。`mergedWorkRecords` 容易误解为输入记录数，不采用该名称。
