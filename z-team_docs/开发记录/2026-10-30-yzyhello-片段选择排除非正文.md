## 结论

上一次运行里 23 篇进入全文阶段的论文中，10 篇以 `scope_needs_more_context` 暂停、6 篇主题排除，只有 7 篇产出证据。暂停的主要原因不是论文不相关，而是范围审核读到的片段落在参考文献区，模型无法据此判断纳入规则，只能回答「信息不足」。

同一个问题也存在于证据抽取：`packSourceRanges()` 把全部段落按字符预算打包，参考文献照样送给模型，既占派发次数与推理耗时，也可能让模型把别人的论文标题当成本文结论抽出证据。

本次让两条路径共用同一套非正文判定：参考文献、致谢、附录不参与范围审核选窗，也不进入抽取打包。没有改变「`needs_more_context` 就暂停」的现有策略，也没有给暂停的论文增加重试机会。

## 触发与实测

被排查的运行：Session `session-a4d2b9aa`、RetrievalRun `6babe2c9`。该轮 23 篇进入全文阶段的论文分布为 7 篇 `partially_extracted`、6 篇 `excluded`、10 篇 `paused`。

### 一篇具体论文的轨迹

「Enforcement of In-Kernel Stateful Security Policies via eBPF」（arXiv 2609.13930v1，WorkVersion `5e8e28c7`）按标题明显属于「内核中 eBPF 安全策略」主题，实际被暂停：

| 阶段 | 结果 |
|---|---|
| 元数据筛选 | 命中问题 1、问题 2 的词面匹配，`fulltextAvailability: resolvable` |
| 语义复核 | `not_selected / not_selected_budget`，是预算未轮到，不是排除 |
| 全文获取 | 成功，已产生 contentHash |
| 范围审核 | 3 次派发（`scopeScreeningMaximumDispatches` 默认 3）全部返回 `needs_more_context` |
| 结果 | [paper.ts](../../packages/academic/workflow/src/paper.ts) 第 79 行暂停，该轮不再重试 |

模型在第 3 次派发返回的原文为：

> `{"status":"needs_more_context","reason":"The supplied segment only contains references and an AI-usage acknowledgment, so it cannot establish the paper's research object, publication date, system design/implementation, or evaluation results; unseen sections could change the decision."}`

即送入的窗口只含参考文献和 AI 使用声明。这次暂停发生在逐篇抽取内部，早于证据产出，因此该篇不会出现在报告的参考文献和证据附录里。

### 暂停论文的共同特征

10 篇暂停论文全部停在同一步，且集中在目标主题上：`xTier`、`CXLMemUring`、`ScalePool`、`CCCL`、`Composable CXL Memory as a Kubernetes-Native Shared Memory for LLM Serving`、`ReFlux`、`CMM-MP`、`SINLK`、`Extending eBPF observability`、`Enforcement of In-Kernel Stateful Security Policies via eBPF`。这解释了同一轮里 CXL 方向的问题只关联到 4 篇证据。

6 篇排除则是主题判定，例如 CXL 存储与近存 ANNS、PCIe SSD、Wi-Fi 速率控制、多卡 LLM 调度，均不属于「通用或服务器操作系统内核与系统软件机制」。排除理由成立，不是本次要改的部分。

### 片段落在参考文献的原因

[screening-fragments.ts](../../packages/academic/evidence/src/screening-fragments.ts) 原先对每个条件词做字面首次匹配，参考文献是条件词最密集的区域，同一段文字可以同时命中多个条件词，于是窗口优先落在那里；随后 `maximumFragments` 与 `maximumCharacters` 的预算被这些窗口占满，正文没有被读到。

[fragments.ts](../../packages/academic/evidence/src/fragments.ts) 的 `packSourceRanges()` 则完全没有过滤，按顺序把全部段落打包，参考文献通常占满一到两个 4,000 字符片段。

## 改动内容

### 共享判定

新增 [section-kinds.ts](../../packages/academic/evidence/src/section-kinds.ts)，把「这一段是不是非正文」收敛为一处判定：

| 导出 | 作用 |
|---|---|
| `isBackMatterSection()` | 标题是否属于参考文献、致谢、附录类 |
| `segmentSectionTitle()` | 读取片段定位里携带的标题，没有则为 `null` |
| `bodySegmentIndexes()` | 返回正文片段的原始索引；全部片段都是非正文时退回全部索引 |

标题判定覆盖 `References`、`7 References`、`Bibliography`、`Works Cited`、`Literature Cited`、`Acknowledgments`、`Funding`、`Author Contributions`、`Conflicts of Interest`、`Data Availability`、`Appendix`、`A. Appendix`、`Supplementary Material`、`Supporting Information`，以及 `参考文献`、`引用文献`、`致谢`、`鸣谢`、`附录`、`补充材料`。

### 范围审核

[screening-fragments.ts](../../packages/academic/evidence/src/screening-fragments.ts)：

1. 命中收集只在正文片段上进行；命中项与原始片段索引绑定，后续窗口计算仍使用原始索引。
2. `sourceComplete` 改为只统计正文片段：非正文从未被选中，不能让它把来源判为不完整，否则提示词会收到与事实不符的「来源不完整」信号。
3. 兜底抽样只在正文片段之间展开。

### 证据抽取

[fragments.ts](../../packages/academic/evidence/src/fragments.ts) 的 `packSourceRanges()` 改为按 `bodySegmentIndexes()` 迭代：参考文献不再占用派发次数与推理时长，也不会被当作证据来源。片段仍引用原始 `segmentIndex`，后续 `fragmentSource()`、重叠拆分与 `incompleteFragments` 的索引语义不变。

## 设计取舍

- 只按 `sectionTitle` 判定，不加正文/非正文的分词启发式：解析器在遇到标题时更新 `sectionTitle` 并沿用到后续段落，标题是已有且可靠的信息。
- 判定只覆盖「重复源词项但不陈述结论」的区域。`Related Work`、`Background` 属于正文，仍然参与选窗与打包。
- 两条路径共用同一判定。若只改范围审核，抽取阶段仍会把参考文献送给模型，暂停问题解决一半，另一类假证据继续存在。
- 本次没有增加「`needs_more_context` 时先补读摘要与引言再判」以及「暂停后在后续批次重试」。按要求只先排除非正文，观察暂停是否减少再决定下一步。

## 风险与下一步

1. 本次改动只影响片段选择，未验证真实运行中暂停数量是否下降，也未验证证据质量与耗时变化；节省一次派发的估算（单次约 50 秒）不是实测值。
2. PDF 兜底路径的片段标题固定为 `PDF page N`，没有章节结构，非正文判定对其无效；这类论文仍会读到参考文献。
3. 若参考文献没有 `<h*>` 标题，`sectionTitle` 会沿用上一个正文标题，排除失效；这种情况需要解析器提供更强的区段标记。
4. 下一步的候选改动按收益排序：`needs_more_context` 时补读摘要与引言、暂停论文在后续批次重试、为 PDF 路径提供页内区段标记。
