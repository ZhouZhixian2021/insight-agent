# 2026-09-30 成员 B：Q2 渠道查询与 Q3 统一候选

## 交付结果

- 新增 `@deepseek-ai/dsh-academic-retrieval` 纯库，使用 Q1 的共享类型生成按渠道区分的查询计划并执行已批准的一轮；不修改 Harness 基础能力，也不接入 Controller、Session 或 Web 界面。
- `planHybridSearch(input, options)` 从当前版本已批准的 ResearchBrief 生成学术源、Web 和用户指定站点查询，使用 Brief 别名与调用方审核过的同义词、方法名，合并重复查询并执行显式数量上限；超出上限的可选扩展返回警告。
- `extendPlanForEvidenceGaps(plan, coverage, roundIndex, options)` 只接受相同 Brief ID/版本的覆盖结果，在未使用且未超限的轮次添加 `evidence_gap` 学术查询，保留原查询 ID。
- `executePlannedSearchRound(plan, roundIndex, limits, adapters, signal)` 根据查询 `kind` 使用不同渠道。学术源结果来自已有 `searchProviders()`；Web 结果经 `identifyAcademicReferences()` 与学术 Provider 核验后才进入摄取。单个 Web 或引用核验失败保留其他成功记录。
- 统一结果包含 `IngestOutcome` 的成果、版本、已核验 Web URL 与去重审计，以及逐成果 `SearchQueryId[]` 来源关系和逐查询的识别、核验、失败、限制事实。重复版本合并时，`IngestRecord.discoveredBy` 会合并查询 ID。

## 交给 A 的接口

| 阶段 | A 提供 | B 库返回 |
|---|---|---|
| 计划确认前 | `HybridSearchPlanningInput` 与 `QueryPlanningOptions`，其中扩展词必须已经审核 | `HybridSearchPlanningOutput.plan`、`warnings` |
| 执行已批准轮次 | 已批准的 `HybridSearchPlan`、轮次、`PlannedSearchLimits`、`PlannedSearchAdapters`、取消信号 | `PlannedSearchRoundResult.ingested`、`discoveredBy`、`queries` |
| Q5 缺口补检 | 与计划同版本的 `ResearchQuestionCoverageResult`、未使用轮次 | 保留旧查询 ID 的扩展计划与警告 |

适配器可直接连接当前服务：`searchAcademic` 调用 `academicSource.searchProviders({ query, maxResults }, providers, signal)`；`searchWeb` 调用 `web.search({ query, maxResults }, signal)` 并把 `sources` 映射为 `candidates`；`identifyReferences` 使用 `identifyAcademicReferences`；`verifyReference` 调用 `academicSource.verifyReference(reference, [provider], signal)`。新库不持有这些服务，也不记录 Session 事件。

当前 `executeHybridSearch()` 把同一表达式发往学术源和 Web，`runResearchDraft()` 对文本表达式去重且单次最多执行三条。A 接入新计划时需改为按 `SearchQueryId` 和 `kind` 派发，并决定已批准计划、逐查询结果与进度事件的 Session 记录方式。B 的返回值提供这些原始事实，不替 A 实现 Controller 或工作流调度。

## 边界与后续

Q2/Q3 不做候选硬过滤、分类、分项评分或 P0/P1/P2 队列；这些属于 B 的 Q4。A 的 Q5 分批调度依赖 Q4 的队列，但 A 可以先进行 Q2/Q3 的接线设计与测试。引文扩展种子已有 Q1 类型，本次没有可用的引文 API 执行入口；该部分留待 Provider 能力明确后接入。自然语言规则中没有结构化方法词字段，因此本库不自行猜测方法名。
