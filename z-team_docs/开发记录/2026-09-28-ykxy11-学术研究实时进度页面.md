## 基线与交付

## 功能

1. 页面改用 `ctx.remote.academicResearch.runStream`。一次提交只启动一条流，传入当前 Session、已批准 Brief 身份、真实数据标记及同一个 AbortSignal。
2. 顶部展示固定六阶段：检索、筛选与去重、全文、证据、分析、报告。显示服务端状态、已完成数量、已知总量和最新快照耗时；没有整体百分比或剩余时间估计。
3. 并发论文分别展示标题、版本、当前操作、证据分段、尝试次数、最近失败代码、已验证证据及被拒草稿。未知值显示“未提供”，不会把未提供的次数填零。当前查询与研究问题直接取自活动列表。
4. 匹配 Session 和运行 ID，同一运行仅接受递增序号；最近进展最多 20 条，不把完整快照当作需要累加的增量。
5. 唯一结果帧进入已有报告、覆盖与失败明细；保留最近进度。取消、关闭和切换 Session 中止同一次请求，迟到响应不能更新新页面。
6. 空结束或传输异常显示结果未确认，保留已观察进度，不自动重连或重启。明确的服务器拒绝与用户取消分别提示；通用 `gateway/internal` 无法区分传输和宿主内部错误，不能据此宣称研究失败。

## 必需的类型入口隔离修复（请 A 审核）

正式 Controller 类型通过 workflow 总入口导入进度类型，会将宿主 Session 扩展带入客户端类型程序，导致 ClientSessions 与 SessionStore 冲突。本次仅作三处集成修复：

- `packages/academic/workflow/package.json`：增加仅类型的 `./progress` 导出。
- `packages/api/academic-research-controller/src/types.ts`：进度类型导入改为该独立入口。
- `tsconfig.base.json`：登记相同入口的源码路径，供 Typert 生成器识别相同类型身份。

未改变任何共享字段、Controller 执行逻辑或 workflow 编排。对应 workflow 双语 README 说明该入口。没有修改锁文件或新增依赖。
