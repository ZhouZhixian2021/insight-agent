# 2026-09-28 学术研究工作流实时进度

## 范围

本次完成负责人 A 的 A-P2 与 A-P3：`academic-workflow` 按真实执行顺序生产进度快照，Academic Controller 使用一次性 Remote 流传输快照和最终结果。Web 展示仍由 C 后续接入。

## 已完成

1. 将六阶段、状态、计数、活动和最新事件的共用类型下沉到 `academic-workflow`，Controller 继续导出原有浏览器类型名称，依赖方向保持由 Controller 指向 workflow。
2. `DraftPipelineAdapters` 新增可选同步观察者 `onProgress`。每次通知都是同一 `RetrievalRunId` 下序号单调递增的完整快照。
3. 检索按每条已批准查询发布开始、活动、累计结果和结算；筛选在候选选择与完整版本校验后结算。
4. 全文与证据阶段按论文分别记录活动。并发论文可以同时出现在快照中，单篇失败不会清空其他论文、已取得全文或已验证证据。
5. 洞察分析与报告生成在真实模型合成和报告渲染调用前后结算；证据阻塞、模型失败和空洞察分别保留已完成的上游事实。
6. 取消快照把运行中阶段标记为取消、未开始阶段标记为未运行，并保留此前已经提交的查询、论文、全文和证据计数。
7. 进度观察者抛出的异常被隔离，不会改变研究结果或中断其他观察者之前已经收到的快照。
8. 工作流不知道的模型内部分段号和重试次数保持 `null`，等待所属模型适配器后续提供，不使用推测值。
9. 新增 `academicResearch.runStream`。同一数据流只启动一次 `runMaintenance()`，同步进度观察者通过有序队列传给异步 Remote 消费方。
10. 每个数据流先发送零到多个 `progress` 帧，正常完成后只发送一个 `result` 帧；准入或工作流异常直接作为流错误返回，不伪造结果帧。
11. 页面关闭、切换会话、用户取消或消费者主动结束时，取消信号传入同一工作流；第一版不自动重连，也不在断线后重新启动研究。
12. 保留原有一元 `academicResearch.run` 作为 C 接线期间的兼容入口，两个入口共用同一执行函数，避免研究规则和最终投影分叉。
