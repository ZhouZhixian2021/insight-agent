# 2026-09-29 Q1 检索计划与候选排序共享模型

## 本次目标

完成《学术洞察新检索词流程与候选排序模块分工计划》的 Q1，由成员 A 冻结 B、C 后续开发共用的数据结构、排序规则和固定样例。此次只建立共享基础，不提前实现查询生成、候选语义分类、运行时调度或 Web 页面。

## 已完成内容

### 1. 查询计划契约

- 新增稳定的 `SearchQueryId` 及创建函数；
- 定义学术源查询、通用 Web 发现查询和用户指定站点查询；
- 将引文扩展单独表示为已核验成果版本种子；
- 用 `HybridSearchPlan` 绑定准确的 ResearchBrief ID、版本、约束、纳入目标、排序策略、查询集合和最大检索轮次；
- 查询直接引用 Brief 中的原始研究问题，不在 Q1 扩大 ResearchBrief 结构。

### 2. 候选评估与排序规则

- 定义候选硬过滤、八项评分、分类、P0/P1/P2/排除优先级、匹配问题、多样性标签和决定理由；
- 集中固定第一版百分制权重：主题相关 30、问题匹配 20、证据潜力 15、方法匹配 10、成果类型 8、来源质量 7、时效 5、全文可用性 5；
- 集中固定优先级阈值：P0 不低于 80、P1 不低于 65、P2 不低于 50，低于 50 或硬过滤失败时排除；
- 公共辅助函数校验权重总和、分项范围、阈值顺序，并计算公开总分，不隐藏第二套评分规则。

### 3. 覆盖、轮次和停止契约

- 将最低纳入、目标纳入和绝对最大纳入数量分开表示并校验顺序；
- 为每个原始研究问题记录未覆盖、部分覆盖或已覆盖，以及支撑成果、证据和缺口；
- 定义检索轮次状态和目标／覆盖满足、饱和、候选耗尽、达到各种上限、取消及需要审核等停止原因；
- 继续执行时不允许携带终止原因，停止时必须明确原因。

### 4. 进度事件草案与固定样例

- 定义从查询规划、检索、去重、硬过滤、分类、排序、全文批次、覆盖判断、缺口补检到结算的阶段；
- 进度事件记录序号、阶段、轮次、查询、批次、论文、候选漏斗和问题覆盖的实际计数，不估算百分比；
- 新增合成固定 JSON，包含检索计划、P0/P1/排除候选、逐题覆盖、部分成功轮次、候选耗尽停止和三条进度事件；
- 固定样例同时作为 B 的查询／排序开发输入和 C 的解释／进度界面输入。
