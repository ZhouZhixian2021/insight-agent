## 完成内容

1. [混合执行器](../../packages/academic/workflow/src/hybrid-search.ts)把已核验论文的 `fullTextFailure` 单独转换为 `resolve_fulltext` 失败；引用仍为核验成功，不增加核验失败数。Controller 在引用说明中展示分类，全文阶段包含该失败，原始上游诊断不会进入页面或报告。
2. [Controller 适配器](../../packages/api/academic-research-controller/src/search.ts)按本轮核验 Provider 与来源记录身份保留全文解析结果。选文复用成功候选和明确无全文结果；仅核验的 Provider 无需开启目录检索，已失败的解析不再调用一次。其他来源记录继续通过来源服务解析。不跨运行缓存。
3. [工作流](../../packages/academic/workflow/src/pipeline.ts)在论文抽取结算时独立复制通过原文核对的证据，再把工作记录交给分析。报告调用将原始批次作为 `admittedEvidence`。改写或新增的引用记录无法通过 C 的准入检查；不从待评测结果临时复制比对清单。部分抽取仅保存合格证据，排除或暂停论文不加入。
4. [后端披露适配](../../packages/academic/workflow/src/report-disclosure.ts)根据实际运行生成 `retrievalDisclosure`，包含渠道阶段、实际来源、各类计数、逐查询批准预算、候选及纳入上限、失败和限制。未完成查询的统计不伪造；通用网页和摘要不进入参考文献。
5. report 返回可选 `retrievalDisclosureIncluded: true`，Controller 保留该字段，Web 预览和下载原样使用已有附录的 Markdown；旧结果缺少标记时继续使用 C 的客户端披露。
6. 更新团队计划的实际合并状态、相关中英文 README、子系统说明、原有决策记录及生成 API 目录。
7. 修复范围审核与论文身份信息的衔接：模型请求携带程序已确认的来源 Provider 和来源 URL，可据此判断官方来源或稳定标识，不再因正文片段没有重复 DOI 或 arXiv ID 而误排除；这些元数据不能用作研究结论证据。
