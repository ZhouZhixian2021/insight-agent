# 长论文分段证据抽取与单次调用超时

## 范围与归属

本次由 A 修改 Academic 工作流的模型调用组织方式。B 的全文解析输出、EvidenceGenerationRequest 和逐字来源核验保持不变；C 的 EvidenceCard、报告与 Web 返回字段保持不变。

## 实现

- [模型抽取适配器](../../packages/academic/workflow/src/model.ts)按完整提示词的估算输入 token 将单篇论文拆成有序批次。Web 默认每批最多 12,000 输入 token。
- 单个来源片段仍然过大时继续切分，相邻片段默认重复 512 个字符。模型返回的批内 `segmentIndex` 在证据核验前映射回原始解析片段，逐字引文仍针对原全文校验。
- 每批顺序调用模型并分别记录 `academic/evidence-request` 与 `academic/evidence-result`。成功批次的证据按来源顺序合并、去重，并继续遵守每篇最多六条证据的既有上限。
- 某批连接失败、超时或输出失败时继续处理后续批次；至少一个批次成功时保留其证据，并把论文标为 `partially_extracted`。全部批次失败时仍判整篇抽取失败，不生成空报告。
- [模型调用器](../../packages/academic/workflow/src/model-call.ts)支持每次尝试独立超时。Web 默认 120 秒；超时持久记录为 `EVIDENCE_MODEL_TIMEOUT` 与 Provider-neutral `TIMEOUT`，可使用既有瞬时故障策略再试。用户取消仍按取消处理。
- [Controller](../../packages/api/academic-research-controller/src/index.ts)公开批次输入上限、重叠字符数和单次尝试超时三个部署配置，并由 Web 组合写入默认值。

## 验证

- Academic workflow 与 Controller 测试共 263/263 通过。
- 新增覆盖验证批内索引回映、一个批次失败后保留其他批次证据、悬挂模型流按时结算为超时。
- Host 构建与类型检查通过；Academic workflow 和 Controller lint 通过。
- 配置目录、双语配对、Markdown 段落、Agent Note 格式、README 限制区和导出 JSDoc 检查通过。
- DSH Web 已使用最新 Host 构建重启。真实长论文运行仍需在 Web 中重新发起，旧运行不会自动复用新批次策略。

## 边界

论文之间的 `paperConcurrency` 与论文内部批次是两层限制；当前本地 Web 仍将论文并发设为 1，单篇内部批次也按顺序发送，避免再次同时压满模型网关。分批不改变来源检索、全文获取或最终报告合成。跨运行续跑和实时进度仍未实现。
