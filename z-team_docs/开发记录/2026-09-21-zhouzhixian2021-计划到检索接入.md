# 从已批准计划启动检索

## 本次范围

接通“普通问题 → 中文计划及检索方案 → 人工审核 → 按计划开始研究”。不再要求用户另填英文检索词，保留开始按钮，不在批准后自动消耗模型或来源调用。

## 实现

- [计划模板](../../packages/preset/agent-presets/presets/academic/skills/academic-insight-report/references/research-brief.md)在同一轮生成检索方案，每条包含表达、中文用途与所服务的研究问题。可读计划解释方向，技术表达仍在折叠执行信息中。
- [计划解析](../../packages/api/academic-research-controller/src/research-brief-plan.ts)支持第 2 版交接格式，缺少 `searchPlan` 时在审核前拒绝。检查问题归属和完整覆盖，去重后遵守三条查询与批准轮次上限。交接格式升级不改变领域 ResearchBrief 的第 1 版结构。
- [研究入口](../../packages/api/academic-research-controller/src/index.ts)增加只读预览；启动请求传递预览的批准身份，查询只从已批准计划读取。身份变化时要求重新预览，缺少方案的旧计划要求系统补齐并重新审核。
- [Web 入口](../../packages/client/ui-academic-research/src/client/ResearchEntry.tsx)显示主题、问题、中文检索方向和“按计划开始研究”，删除必填查询框。保留取消、关闭和切换会话时的处理。
- 保留原有来源检索、去重、选文、全文解析、证据抽取及报告流水线。实际执行表达仍记入 `RetrievalRun.queries`，通过 Brief 身份关联审核记录。

## 验证与边界

- Controller 与 Web 定向测试共 74 项通过，覆盖预览不调用来源、保存查询执行、旧计划修复、身份变化、数量限制、问题覆盖、预览失败、迟到预览响应和取消。
- 全项目类型检查通过；后续补充格式校验后，Host 与 Client 增量类型检查通过。
- [中文计划快照](../../snapshots/sdk/academic-plan-chinese/snapshot.yml)使用预编写模型回答，不调用真实模型；记录当前模板与新增检索方案，不改写历史会话。
- 中文计划和旧版校验场景只读回放 2/2 通过，快照语料检查 3/3 通过。代码规范、UI 文案本地化与差异空白检查通过。文档完整检查首次 31 项通过；修正配置目录定位与决策记录标题后，两项失败门禁分别复验通过，更新的双语配对也通过。
- 学术研究网页、计划审核网页及 Remote 浏览器模块均已构建。
- 真实模型生成的查询质量与端到端检索效果仍需人工 Web 验收，不能把离线测试当作真实报告验收。

## 人工验收

服务加载新代码后，新建学术洞察会话，用普通中文描述问题。审核中文计划中的研究范围与检索方向，批准后打开“学术研究”。无需填写查询即可看到计划摘要，点击“按计划开始研究”，核对返回的实际查询与计划一致。旧计划缺少检索方案时，回到聊天让系统补齐并重新审核。

本次未提交或推送。用户确认下一步后，已重启本地 60103 端口的 Web 服务并打开页面，保留现有会话记录。浏览器确认学术研究入口不再展示查询输入框；当前会话没有成功的计划审核记录，显示“请先在当前会话完成研究计划审核”。重启前尚未完成的计划审核调用在恢复后显示中断，未代用户批准计划或发起真实研究。下一步需生成带检索方案的新计划，由用户审核后验收计划预览与实际运行。后续自适应补充检索继续单独推进。
