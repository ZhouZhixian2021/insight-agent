## 1. 验收课题与环境

真实课题为“我想了解 RAG 是否真的能减少大模型幻觉，以及它还有哪些局限。请帮我做一次学术研究。”研究计划由当前 Session 的模型生成并经人工批准，包含 3 个研究问题、3 条混合检索方向，学术来源为 OpenAlex 与 arXiv，Web 仅用于候选发现，引用必须回到学术来源核验。计划要求至少 4 篇、目标 8 篇、最多 10 篇，至少 3 篇具备全文。

本记录不保存模型密钥、Web 访问令牌、原始全文或模型原始回答。运行使用当前 DSH Web 配置的模型与来源服务。

## 2. Q7.1：真实完整运行

### 2.1 启动前发现的本地构建问题

第一次运行在检索返回后出现 `Cannot read properties of undefined (reading 'sessionId')`。源码协议已经支持 `q6` 流式帧，但本地 `packages/client/ui-academic-research/lib/client.js` 仍是旧构建产物，把 `q6` 帧误当作最终结果读取。重新构建 `@deepseek-ai/dsh-client-ui-academic-research` 并重启 Web 后恢复。这是本地生成物陈旧，不需要提交产品源码绕过。

### 2.2 候选未进入批次的根因和修复

重建客户端后，混合检索能够返回候选，但多次运行均没有安排全文批次。原因是已批准的研究问题为中文，论文标题和摘要主要为英文；初筛器要求中文问题概念在英文元数据中完整逐字命中，导致相关论文的 `matchedQuestions` 为空并被排除。

修复位于 `packages/academic/retrieval/src/assess.ts`：

- 分数仍只由规范版本的标题、摘要和关键词计算；
- 完整词项命中仍可直接关联研究问题；
- 候选元数据已经命中主题时，允许该候选的已批准发现查询所绑定的研究问题承担路由；
- 查询来源不增加语义分数，不证明证据支持或科学质量；
- 同一查询返回但没有主题元数据命中的无关论文仍不会获得问题关联。

`packages/academic/retrieval/tests/rank.spec.ts` 新增中文研究问题、英文候选和批准查询关联的测试，并保留无关查询命中不得放行的反例。

### 2.4 仍未通过的原因

已批准计划把“至少覆盖 RAGTruth、HaluEval 或 GaRAGe 等权威基准”写成了每篇论文都必须满足的纳入条件。该要求本应更适合作为整组文献的组合覆盖目标；作为逐篇硬条件时，会排除可以回答部分研究问题的实证论文。两篇成功完成范围判断的论文均因此或因未直接评估幻觉／忠实性被排除。

另外 6 篇抽取失败表明真实模型通道的完成率仍不足。后续应分别处理计划规则粒度和抽取稳定性，不能通过放宽证据核验或编造报告来绕过。

## 3. Q7.2：中断恢复

已有工作流测试能够在首批检查点后模拟进程退出，并验证恢复后不重复检索和筛选。本次补充 Controller 入口验收：

1. 从已批准计划启动真实工作流夹具；
2. 在待处理批次检查点持久化后模拟进程退出；
3. 由同一 Session 使用 `resumeRetrievalRunId` 发起恢复；
4. Controller 从 Session 的搜索计划、批次决定和恢复检查点重建输入；
5. 恢复沿用原 `retrievalRunId`，继续处理未结算批次；
6. 学术检索和 Web 发现调用次数保持不变；
7. 运行最终结算并生成夹具报告。

涉及测试：

- `packages/api/academic-research-controller/tests/controller.host.spec.ts`
- `packages/academic/workflow/tests/replenishment.spec.ts`
- `packages/academic/workflow/tests/recovery.spec.ts`

三组测试共 95 项通过。该验收覆盖显式恢复入口；Web 页面尚未提供自动发现中断运行和一键恢复的交互。
