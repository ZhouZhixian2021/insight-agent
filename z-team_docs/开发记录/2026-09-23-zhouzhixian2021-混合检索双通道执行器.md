## 目标

完成 A-H3a：在不修改学术 Provider、Web 通用能力或 Controller 运行保护的前提下，为一条已批准查询建立可测试的双通道执行器，固定计划策略如何约束学术源直接搜索、Web 发现、引用识别和权威核验。

## 实际完成

- 新增 `executeHybridSearch()`，同一查询的 Academic 与 Web 发现同时启动。
- 通过显式适配器传入按白名单直接检索、通用 Web 发现、B-H1 纯引用识别和后续权威核验，不在 workflow 中定位具体 Provider 或创建网络客户端。
- Web 标题、摘要和生成式内容不进入标准论文批次；只有核验成功的引用产生论文记录。
- DOI、arXiv 与带来源命名空间的 ACL/PMLR/CVF 记录按规范标识精确去重，发现 URL 不参与论文身份判断。
- 先过滤未获批准的核验 Provider，再应用独立核验次数上限；引用类型扩展不会放宽预算。
- 学术源或 Web 单边失败时保留另一边成功结果；逐条核验失败不丢弃已核验的同批引用；取消不会转成来源失败。
- 返回标准 `AcademicSourceSearchBatchResult` 供现有 ingestion 使用，同时返回分开的渠道阶段、URL、引用、重复和核验观察值，为 A-H4 Remote 投影保留输入。
- 保留 Controller 对第 3 版计划的执行保护，避免 B-H2 尚未交付时把识别结果当作已核验论文。
