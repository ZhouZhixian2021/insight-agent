# 正式分片证据抽取接入与有限报告核对

日期：2026-10-12。成员 A 在 B 的分片提取器已合入后，完成正式工作流接线与合成夹具核对。

## 已做

- 正式 `runModelResearchDraft` 保留原有论文范围审核，纳入后改用 B 的 `extractEvidenceInFragments`。旧 `createModelEvidenceGenerator` 仍供既有独立接口使用；正式证据分片每次模型调用只尝试一次，避免与旧的整篇分批重试相乘。
- 首轮分片先以 4,000 字、最小恢复范围 1,000 字、重叠 256 字、最多三次尝试、输出 4,096 token、传输失败首次退避一秒接入。下述固定论文回归表明 4,096 输出额度不足，随后只把分片默认输出上限改为 16,384，与 Controller 原有的证据抽取默认上限一致。可通过 `EvidenceExtractionModelPolicy.fragmentPolicy` 整体覆盖，模型配置中更低的输出上限仍生效。范围审核继续使用原有的首批 token 预算。
- 每次模型请求、结果写入原始片段编号、字符范围、尝试次数及额度。成功片段的已核验证据写入 `academic/evidence-fragment-verified`，并在下一段发起前从 Session 存储读回核对。持久化失败停止全轮，不作为可恢复模型失败；取消不自动合成。
- 传输、超时、解析及不完整输出交由分片提取器处理；原有模型日志保留流与 Provider 返回的请求 ID（若有）。已成功片段不会因后续片段失败被清空，论文以部分抽取状态继续进入有限报告路径。
- 增加合成联调测试：第一段先保存、下一段遇传输错误、只重试该范围；同时验证 Plan 至少要求两篇而仅一篇有有效证据时仍生成明确限制的草稿。零证据停止与取消不合成由既有测试覆盖。

## 边界与待验证

- 先进行了下述真实模型样本回归及固定单段的正式研究入口验收；随后又完成同篇论文整篇的受控运行，结果见文末。4,000 字等参数仍是保守首轮值，需要在多篇固定论文上继续比较有效证据数、失败范围、耗时与模型调用量。
- 尚未实现连续超时或传输错误时动态降低论文并发，也未以原运行的“12 条证据、4/4 问题覆盖、2 篇部分可用”完成真实报告复验。
- 分片成功记录已经持久化；服务重启后从单个片段继续执行仍不是本轮能力，A-S3 的批次级恢复机制保持原口径。

## 固定真实论文的分片输出额度回归

从本机已有 Session 中取同一篇 FAIR-RAG 论文的原文证据请求（事件 701），不再请求学术源；固定输入共 58 段、4 个研究问题，本次使用前 8 段（约 8,135 字）及其中第 2 段（1,752 字）做受控抽取。运行使用当前 DSH `wowei/deepseek-v4-pro` 路由、临时 Session，保留正式范围审核、分片模型接线、逐字定位核验和持久化读回；没有修改全局模型配置，也没有打印密钥、论文正文或模型回答。为隔离抽取，范围规则设为空，因而不能将 `extracted` 解释为满足原研究 Plan 的纳入标准。

| 输入与额度 | 观察结果 |
|---|---|
| 前 8 段、每片段 4,096 输出 token | 范围审核通过；首片段首试正好用满 4,096 且输出不完整，缩小范围后通过但证据为 0。第 2 片段连续三次用满 4,096 仍未完成；进入第 3 片段后再次用满上限。此时主动终止，避免继续产生确定性截断调用。未得到整篇最终结果。 |
| 单独第 2 段、8,192 输出 token | 一次完成，约 63.6 秒，3 条可定位证据、0 条拒绝草稿，并保存 1 个已核验片段。 |
| 前 8 段、8,192 输出 token | 第 1 片段一次完成但未提取出相关证据；第 2 片段首试仍正好用满 8,192 而未完成。为限制调用量，此时主动终止。说明 8,192 对同片段也不是稳定保证。 |
| 单独第 2 段、16,384 输出 token | 一次完成，约 88.2 秒，4 条可定位证据、0 条拒绝草稿，并保存 1 个已核验片段。 |

额外尝试把此路由的推理强度指定为 `low`，DSH 在请求准备阶段返回 `UNSUPPORTED_REASONING_EFFORT`，未产生模型调用。因此当前路由不能靠请求中的 `low` 参数调节推理消耗。两次单片段成功只能证明真实来源文本可以走通新接线；它们不是同一时段多次重复试验，不能推算成功率提升，也不能说明 16,384 可以稳定跑完整篇。与旧的“前 8 段一次整批请求、约 151.7 秒获得 6 条证据”结果相比，新路径本次未完成前 8 段，不能做吞吐量胜负结论。正式报告合成也未在本回归中执行。

因为 Controller 默认抽取上限已是 16,384，而新分片默认值曾额外压到 4,096，本次仅移除这层过低的默认压缩；若会话选定模型明确设置了更低 `maxTokens`，仍遵从该配置。随后进行的整篇运行记录见文末；仍需更多固定论文才能判断参数和模型路由的普适效果。

## 固定单段的正式研究入口验收

另用同一篇论文的第 2 段真实原文构建受控 HTML 响应，配同一组四个研究问题，通过正式 `runModelResearchDraft` 入口执行候选、全文解析、范围审核、分片证据、洞察综合及 Markdown 报告。学术候选元数据和 HTTP 响应由临时适配器固定提供，没有访问实时检索源，也没有经过 Web/Controller 的人工 Plan 审批；模型调用使用当前 DSH 路由。测试 Plan 明确要求至少两篇纳入论文，但只提供一篇，并允许证据不足时继续生成带限制草稿。临时测试及其 Session 已清理。

单次结果：约 211.1 秒；论文状态 `extracted`，一次分片证据模型调用通过并保存 3 条可定位证据，失败操作为 0；洞察综合 `partial_success`；生成约 5,056 字的 Markdown 报告，评估状态 `blocked`。这证明真实原文片段经过正式新接线后可以到达报告生成，而不能把该报告视为满足已批准 Plan 的可交付成果。`blocked` 与测试中刻意未达到的两篇最低纳入要求相容；本次未留存逐项评估明细，不能断言只有这一项阻止交付。整篇结果见下节；多个候选、实时来源、Web 审批和用户可见质量展示仍需单独验收。

## 整篇固定真实论文验收与片段组织

同一 FAIR-RAG 原文请求有 58 段、49,283 字、4 个研究问题。原分片策略逐原文段落请求，至少需要 58 次模型调用；本次把相邻短段落打包到 4,000 字上限，首轮为 14 组。每组保留所有原文段落及其定位；打包失败时沿原段落边界缩小范围，单个超长段落仍按字符和重叠区拆分。事件的 `sourceRanges` 记录打包内各原始范围，证据草稿的局部 `segmentIndex` 仍指向对应的原文定位。新增测试覆盖打包定位、失败拆分及成功证据保留。

验收使用保存的 58 段原文和章节标题重建受控 HTML，固定提供一篇候选和 HTTP 响应，经正式 `runModelResearchDraft` 进行全文解析、范围审核、证据抽取、洞察综合和报告生成；模型仍为当前 DSH `wowei/deepseek-v4-pro` 路由。测试 Plan 要求至少一篇全文论文，允许证据不足时生成带限制草稿。此测试不访问实时学术源，也不经过 Web/Controller 人工 Plan 审批；临时测试文件与 Session 运行后已清理。

单次运行约 1,109 秒（18.5 分钟）：共 20 次分片模型请求，含 6 次失败尝试；其中 3 次达到 150 秒单次超时，另 3 次底层为 `TRANSPORT` 连接失败。14 个片段核验结果已写入 Session，保存 7 条可定位证据，覆盖 4 个研究问题中的 2 个。首组耗尽三次尝试后仍缺失；其余组继续，论文状态为 `partially_extracted`。研究运行和洞察综合均完成，并生成约 6,760 字符的 Markdown 报告。报告评估为 `needs_review`，问题包含来源陈述与研究问题需复核，以及未满足的 Plan 条件；不能把该报告当作充分核验的交付稿。

本次证明整篇固定输入可以走通到有限报告，并显示打包使首轮请求基数从至少 58 降到 14；实际请求因失败恢复增至 20。没有同篇未打包整篇基线，不能据此声称总耗时或证据质量已提升。报告正文未作为验收产物留存，因此本次只核对了生成、状态、证据数量及评估代码，没有逐段审读报告观点。下一轮应先处理超时和连接失败，以及 2/4 问题覆盖不足，再用多篇固定样本复验；实时来源、人工 Plan 审批和 Web 呈现仍需端到端验收。
