# 开发记录：批准后研究卡交接

## 目标与实现

成员 C 接入 A 在 PR #123 实现的批准后结束轮次机制。研究卡继续使用现有批准元数据、正常轮次结束和会话空闲事实，支持没有普通聊天回答的工具审批轮次；未新增 Remote、审批类型或模型调用，也未修改 A 的计划、工作流和 B 的来源代码。页面区分等待轮次交接与启动后台研究，结果仍归属于原始批准 Brief。

启动响应丢失时，先查找同一批准 Brief 的已保存任务，再通过原任务 ID 接回进度和结果。不会仅因请求异常另建研究，也不会把其他计划的结果作为本轮结果。刷新恢复和取消职责保持不变；关闭研究卡只停止观察。重新发现任务的请求仍由当前操作持有，关闭页面后迟到结果不会创建新监听。

## 验证

定向回归覆盖真实 Conversation 装配出的工具审批卡、批准后无聊天正文、等待会话空闲、StrictMode 去重、刷新恢复、连续两轮结果隔离、被中止轮次不自动执行，以及启动响应丢失后的原任务监听与报告读取。复用 A 的真实 Agent Loop 交接测试，不模拟另一套批准机制。四个文件合计 28 项通过；首次新增夹具的结果 Brief 身份未同步，修正后复验通过。Client Loader 装配首次在默认五秒内超时，原命令定向复验通过，未扩大超时或禁用测试。新增交接状态使用精简界面输出快照。

## 限制

这是现有 A 机制的 C 端衔接与恢复修复，不将任务启动迁到服务端。批准后前端尚未完成启动时关闭页面，不能保证后台任务已建立；其他研究运行时仍需显式刷新后续卡，不新增队列。尚未执行真实模型端到端研究或浏览器视觉验收。
