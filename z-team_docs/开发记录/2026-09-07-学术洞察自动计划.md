## 目标

用户在新建学术洞察会话后直接输入研究需求，系统自动进入计划模式，生成结构固定的 Research Brief 和研究执行计划。只有用户通过计划审核后，Agent 才开始正式检索、分析并输出报告；用户无需输入 `/plan`。

## 实际完成

| 改动 | 作用 |
|---|---|
| 为 `@deepseek-ai/dsh-plan-mode` 增加可选配置 `initialActive`，默认值为 `false` | 允许指定预设在新会话首个模型请求前自动进入计划模式，同时保持标准、PTC 和 Cordis 等现有预设行为不变。 |
| 在 `plan` 会话投影中增加内部 `hasSelection` 状态，并将投影版本从 3 升至 4 | 区分“从未选择模式”与“明确选择关闭”，避免恢复会话、已退出计划模式的会话或已有请求头的会话自动重入。客户端公开投影仍为 `{ active, pending }`。 |
| 在系统提示词组装阶段排队初始计划状态，并沿用 pre-step 边界写入 `plan/mode` | 让首个请求立即获得计划提示词，同时保证模型看到的状态在 `request/header` 前进入会话日志，不增加伪造的用户切换通知。 |
| 在 Academic 预设中加入隔离的 plan-mode 组并设置 `initialActive: true` | 用户选择“学术洞察”后可直接输入请求，无需先输入 `/plan`。 |
| 增加学术专用计划提示词 | 规定批准前只形成 Research Brief、允许少量预检索、禁止提前做完整综述或输出最终报告，并通过 `exit_plan_mode` 进入人工审核。 |
| 为 Plan Mode 增加 `missingExitRetries`，Academic 配置为 `1` | 模型未调用 `exit_plan_mode` 就结束时，在同一轮追加一次已记录提醒并重新请求；本轮已经调用过评审工具则不触发，次数上限防止无限循环。 |
| 强化 Academic 计划提示词与 Skill | 明确完整 Research Brief 必须放入 `exit_plan_mode.plan`，禁止只发送“计划如下”等普通文本预告。 |
| 新增 `references/research-brief.md`，并更新 `academic-insight-report` Skill | 固定研究目标、证据范围、分析与交付、执行步骤、完成标准等字段，降低不同请求措辞造成的不稳定性。 |
| 新增计划模式单元与全循环测试，并扩展预设及真实 Loader 组合测试 | 覆盖默认值、配置校验、首请求自动激活、显式关闭不覆盖、旧会话不初始化、日志顺序、无切换通知、首请求前用户退出可阻止重入、Academic 工具组合等行为。 |
| 更新 Plan Mode、Academic 使用说明、架构计划、配置目录和两份 Agent Note 的中英文文档与 sidecar | 让用户、维护者和团队计划都反映当前行为，并保留可审核的设计决定。 |

## 2026-09-08 首次真实体验问题与诊断

| 现象 | 会话证据 | 结论与处理 |
|---|---|---|
| 回复停在“以下为完整研究简报与执行计划。”，未出现审核卡 | 对应轮次只有普通 `assistant/message`，没有 `exit_plan_mode` 的 `tool/call` | 模型把计划留在推理内容并提前停止，不是 Web 丢失正文。已增加一次有界补交，并强化提示词和 Skill。 |
| Academic 会话的 `web_search` 是否可请求 | 多批 RAG 查询成功返回 RAGBench、RAGAS、ARES、ConsJudge 等来源 | Search Provider 已正确挂载且可用；个别请求仍可能出现 Provider 超时。 |
| 同一 Academic 会话四个 arXiv `web_fetch` 全部失败 | 四个结果均为 `Network error ... fetch failed`；另一会话的 arXiv 抓取成功，现场用同一 Provider 并发复测两个地址也均为 HTTP 200 | 工具与 HTTP Provider 均已挂载，失败是当时的瞬时网络/代理链路故障，不是固定禁用或 URL 策略拒绝。现有日志压平了底层 Undici cause，无法从该次历史事件进一步区分 DNS、TLS 或连接复位。 |
| 模型请求反复重试并最终失败 | `wowei/deepseek-v4-pro` 连续返回 `TRANSPORT: Connection error`，默认策略最多重试 5 次，最终 `turn/end` 为 error | 与 Web 工具调用无关；根因位于自定义火山 AI 网关或到该网关的连接。应优先切换稳定模型路由或检查该网关，再决定是否调整重试上限。 |

## 风险与限制

- Plan Mode 通过提示词约束行为，不是强制只读沙箱；学术预设仍依赖既有工具权限和人工审核边界。
- 自动计划只作用于新会话的首个请求。同一会话完成报告后的新课题不会自动重入，第一版应新建学术洞察会话。
- 当前只有确定性生命周期、预设组合和既有审核 UI 覆盖；发布或提交 PR 前仍应补齐真实模型快照与 GIF。
