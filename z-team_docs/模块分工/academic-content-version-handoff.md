# 全文内容与论文版本交接规则

## 范围与状态

本页记录[调用计划](member-a-academic-workflow-call-plan.md)第一项的最小接入规则，基线为 88cde0f。由 A 使用现有 B、C 接口整理数据，不新增取证版本体系，不要求 B、C 为首次哈希补全修改接口。[extractPaperEvidence](../../packages/academic/workflow/src/index.ts)已实现单篇交接并连接现有证据抽取；完整研究工作流、暂停记录持久化及恢复尚未接入。

## 正常流程

1. 检索与去重得到版本 V1，其 contentHash 为 not_extracted，且尚无已绑定的历史内容或证据。
2. A 使用归并后的论文与版本 ID 调用 B 的全文解析，得到同一 V1 的正文片段及哈希 H1。
3. A 创建 V1 的内存副本，将 contentHash 补为 available(H1)，其他字段及 ID 保持不变；不修改原始检索对象或历史快照。
4. A 把解析结果交给证据抽取，将补全后的版本副本、证据、定位和卡片一起交给 C。同一版本只传一份当前记录，不同时传新旧两个 V1。

首次获取哈希是补充对同一内容的观察，不代表作者发布新版本。不改变 AcademicWork.workVersionIds 或 canonicalVersionId，不人为引入额外的版本选择问题。

## 必要分支

| 条件 | A 的处理 |
|---|---|
| 尚未提取哈希且没有历史内容绑定 | 用实际解析结果补齐当前内存版本，再传给下游。 |
| 已有可用哈希相同，论文及版本身份一致 | 复用原版本，不创建新版本。 |
| 已有哈希与新结果不同，原因未确认 | 暂停该篇论文的后续处理，其他论文继续；保留旧记录和本次冲突信息，不自动覆盖哈希或创建版本。核实原因后再处理该论文。 |
| 哈希缺失但已有历史内容或证据，或为其他不可用状态 | 不机械覆盖原状态；核对历史关联，不能当作首次补全。 |
| 论文或版本 ID 不符、哈希为空、获取或解析失败 | 不补齐版本，不将其作为有效全文。 |

HTML 对处理后的 article HTML 计算哈希，PDF 对原始字节计算哈希。同一论文两种格式的哈希可以不同，不能自动认定论文改版。初版沿用 fetchAcademicFullText 的候选顺序与首个成功结果，不为同一版本混合多种内容表示。哈希不证明内容属于指定论文，来源和版本仍需核对。

## 实现位置与验收

初版返回 workflow 本地 PaperPause，包含论文 ID、版本 ID、旧哈希、新哈希、来源地址、获取时间和暂停原因；获取时间使用解析输入提供的 retrievedAt，不虚构额外发现时间。它不是新的共享模型或持久化格式，调用方负责保留。后续改进见[调用计划的待改进事项](member-a-academic-workflow-call-plan.md#待改进事项)。

A 的数据整理放在全文解析之后、证据抽取之前。现有 [WorkVersion](../../packages/academic/model/src/types.ts)、[解析输入](../../packages/academic/evidence/src/types.ts)与 [C 的分析输入](../../packages/academic/analysis/src/types.ts)足以表达正常路径。

实现时验证：补齐后版本、证据、定位及快照哈希一致；原始对象不变；同哈希复用；不同哈希拒绝覆盖；错误身份拒绝交接。多来源、非正式引用版本选择和历史迁移在实际场景需要时处理，不作为本次正常路径的新增接口前置条件。

持久化如何保存补全观察并保留历史，由 A6 确定；内存副本不等于已解决保存恢复。确认来源内容发生变化时，仍遵循[字段规范](academic-model-v1-field-reference.md)的新版本规则。
