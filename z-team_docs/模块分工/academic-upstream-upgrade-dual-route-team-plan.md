## 执行顺序与检查点

### 第零轮：准备

1. A、B 核对 T0、U0 和功能清单，列出已有缺陷、待合并提交与未提交工作。
2. 分别准备独立工作目录、依赖安装、运行数据副本与端口，先记录实际工作目录和提交。
3. 保存 T0 的固定样本结果；验收条件缺少旧版证据时标为待补，不能事后推断。
4. C 从团队主线安排自己的功能开发，建立 HTML 与 Trace 两份可单独审查的交付记录。
5. C 先交付 Trace 最小统一字段、查询返回样例与旧版采集映射；A/B 分别核对 U0 对应观察点，登记支持、缺失和待查项。先完成此项交接，再展开依赖这些字段的完整采集与界面实现；不必等待整条升级路线完成。

### 第一轮：启动与审批

| A 工作项 | B 工作项 | 共同完成标准 |
| --- | --- | --- |
| A-U1：在升级分支合并 U0，处理依赖、工程配置及启动必要冲突。 | B-U1：验证 U0 基础运行，盘点学术能力，再迁入启动和审批所需最小链路。 | 正确项目的 Web 启动，模型配置可用，学术模式可选。 |
| A-U2：适配学术预设、审批、Controller 和进度。 | B-U2：迁入相同能力及其依赖、类型、事件和界面。 | 生成与修改计划、人工批准、Controller 启动、进度保存与刷新查看均可用。 |

第一轮结束比较阻塞点、工作量和基座修改范围。任一路线若存在明显不可接受的兼容成本，可由 A 决定暂停该路线，并记录原因；无需为了比较而强制两边全部做完。

### 第二轮：完整学术研究

| A 工作项 | B 工作项 | 共同完成标准 |
| --- | --- | --- |
| A-U3：适配检索、去重、候选审核、全文和证据调用。 | B-U3：迁入对应业务、模型交换、失败语义及固定测试。 | 同一固定论文和批准条件能完整跑通，保留失败原因与证据定位。 |
| A-U4：适配综合、报告、取消、检查点恢复和历史读取。 | B-U4：迁入同一功能并核对遗漏。 | 小范围研究可交付草稿；不足与失败如实显示；旧记录按支持范围读取。 |

新版 Search/Fetch 是待验证能力，不能未经测试直接替换现有全部检索来源，也不能把 Web 摘要当作全文证据。各路线分别核对凭据优先级、超时、取消、重试和会话记录要求。

### 第三轮：增量与最终选型

A-U5 与 B-U5 分别适配 T0 之后已进入团队主线的业务增量，其中包括 C 已交付的 HTML 与 Trace。Trace 的观察点与数据映射在第零轮提前核对，第三轮接入已经交付的查询、展示与测试，不到此时才首次讨论接口。尚未交付的功能明确标为未验证，不算任一路线的已完成能力。

A 汇总路线比较，确定保留路线；最终只把选中的升级路线通过正常审查流程合入 master。两条试验分支不能互相整体合并；共享修复只迁入能够独立解释和验证的提交。

## C 的独立交付要求

### C-H：HTML 报告

C 独立确定 HTML 的页面展示、下载、自包含程度和 Markdown 保留策略，并在实现前记录选择。数据继续来自结构化研究结果，不能靠重新生成一份无证据关联的正文替代。

- 展示报告章节、引用、证据关联、质量状态和研究限制，区分有限草稿与审核状态。
- 把检索内容和模型文本当作不可信输入，处理 HTML 注入、外部资源与链接行为；报告导出不包含密钥或内部调试信息。
- 验收正常报告、部分证据和无证据三类场景，并验证导出后引用与质量说明仍可理解。
- 给 A/B 提供结果字段、渲染入口、下载接口和样例，不要求 A/B 在两条路线重写报告实现。

### C-T：Trace 调试

C 独立负责统一调试数据、旧版采集适配、存储投影、查询和界面，具体接口交接遵循下一节。优先复用已有 Session、研究运行与调用记录，避免记录两套互相矛盾的事实；新增格式遵守已有持久数据版本规则。页面、筛选和耗时统计不直接解析 T0 的 Session JSONL、事件名或文件路径。

- 能按一次研究追踪阶段、论文、模型或工具调用、尝试次数、耗时和失败原因；标识关联不能只依赖显示标题。
- 区分等待、运行、重试、失败、取消和完成，说明计时口径与缺失历史数据的处理。
- 刷新或重启后可查询已保存的必要记录，能够定位慢阶段与具体失败调用。
- 对凭据、完整请求和全文等敏感内容明确访问、脱敏和保存范围，导出使用受控调试数据。
- 提供正常、重试、超时、取消与历史缺字段样例，说明诊断能力边界，不把未观测到的网络层原因写成确定结论。

C 可独立安排 C-H 与 C-T 的先后，两个交付应能分别审查、测试和合并。C 的 PR 进入团队 master 后，兼容适配归 A/B 各路线负责人。

## Trace 接口约定与跨版本职责

本节是待实现的团队约定，尚未新增 TypeScript 类型、Session 事件或 Remote API。新旧基座的具体差异由 A/B 核对记录，不预设 U0 一定使用某种日志格式，也不承诺旧数据具备全部调试字段。

### 三层拆分与责任

数据流为：基座与研究流程的可观察事实 → 各版本采集适配器 → 统一 Trace 数据 → 查询、时间线、筛选、慢调用和失败详情。统一数据的含义不依赖基座包名、文件格式或事件名。

| 层次 | C 的责任 | A 的责任 | B 的责任 |
| --- | --- | --- | --- |
| 统一数据与接口 | 主导字段含义、版本、样例、查询结果与兼容策略；维护可复用类型及无基座依赖的统计、投影和展示逻辑。 | 从合并路线核对字段是否可获得，反馈缺口；不自行改成另一套字段。 | 从迁入路线完成同样核对；不另建一套 Trace 协议。 |
| 数据采集适配 | 实现团队现有版本的采集和来源映射，明确依赖的 Session、Controller、工作流及模型观察点。 | 实现 `upgrade/merge-upstream` 的新版观察点、标识映射、持久化接线和迁移适配。 | 实现 `upgrade/port-academic` 的对应采集、映射和接线。 |
| 查询与展示 | 实现统一返回、分页约定、历史查询、详情、界面、脱敏及导出；基座相关 RPC 或存储接线与业务逻辑分开。 | 适配本路线的 RPC、存储和插件注册，复用 C 的查询语义与界面。 | 适配本路线的相同位置，复用 C 的查询语义与界面。 |
| 验收 | 交付统一样例、当前版本验收结果和共享断言。 | 用同一批样例验证本路线，补充真实观察点证据。 | 按相同条件验证迁入路线。 |

源码目录由 C 在接口交接单中提出；统一类型和纯投影不得依赖某一版 Session 实现或客户端组件。具体采集、持久化和 RPC 装配归适配器，不要求现在新建包或固定文件结构。

### 最小统一数据 v1

以下是首版字段语义，最终字段拼写、序列化格式和事件枚举由 C 在首个接口交付中列全，A/B 核对可采集性；未经交接不把此表当作已发布 API。

| 字段组 | 首版约定 | 缺失处理 |
| --- | --- | --- |
| 协议与来源 | `schemaVersion` 标识 Trace 自身格式；记录生产适配器与基座提交，另保留可核对的来源记录引用。Trace 版本不代替 Session 版本。 | 不支持的主版本明确返回不支持，不按旧版字段猜测解析。 |
| 研究身份 | `traceId`、`sessionId`、`researchRunId` 分别关联一条调试链、所属会话与一次研究运行；一次会话中的多次研究不能混为一个运行。 | 无法关联的历史记录显式说明原因，不按相同标题或时间接近强行拼接。 |
| 操作身份 | `spanId` 表示阶段、论文处理或逻辑调用；`parentSpanId` 表示父子关系；逐条观察有稳定 `eventId`。关联论文使用已有规范 Work/Version ID。 | 父项或论文身份缺失时显示未知；不得制造规范论文身份。 |
| 工作内容 | 显式记录阶段、操作类别及可选 Provider、工具、模型信息；不依赖自然语言标题推导状态。 | 未观测字段为未知，不把模型或来源默认成当前设置。 |
| 状态与尝试 | 至少可表达等待、运行、重试等待、成功、失败、取消和未知；每个实际调用尝试有自己的标识与尝试序号，同一逻辑调用可关联多个尝试。 | 超时、输出截断和解析失败有独立失败代码；局部证据成功沿用原业务结果，不由 Trace 重新判定。 |
| 时间与耗时 | 保存有依据的发生时间；在途和结算耗时注明测量来源，区分排队、模型/工具执行与总耗时。 | 历史未记录或跨进程无法可靠计算时返回未知；不能写成 0，也不能把父子或并发耗时相加当作总时长。 |
| 错误与限制 | 返回错误类别、失败阶段、净化说明和数据缺口；网络中断原因仅报告可观测层级。 | 无依据时不能断言本机、代理或上游故障；缺字段不等于成功或失败。 |

公开跨包身份在实现时沿用仓库品牌 ID 规则。C 提供一个完整的阶段—论文—调用—两次尝试样例，以及各字段是否必需、缺失值表示和枚举表；不在本次文档编辑中增加运行时数据结构。

### 查询、持久化与行为约定

- 页面通过统一查询结果工作，查询至少按会话和研究运行隔离，并能查看阶段、状态与单次操作详情。摘要和详情采用同一数据来源，不要求页面读取原始 Session 日志。
- C 明确列表、详情、分页游标和排序语义；回放、刷新和实时更新沿用稳定身份与顺序，同一 `eventId` 重复到达不能导致重复计数。不能仅按时间戳判断事件先后或同一操作。
- 同一操作的新尝试单独保留，旧尝试的失败不被覆盖成成功。只有观测到结算才能显示相应终态；重启遗留在途记录显示最后已知状态和中断/未知提示，不能推断完成。
- Trace 是业务事实的诊断投影，不改变批准范围、论文纳入、证据有效性和报告质量结论。观察与展示错误不得让已成功的研究变成业务失败，也不能静默掩盖调试数据缺失。
- 旧版与新版各自保留原始数据及原有兼容规则。可重建的投影允许按版本重建；不可重建的新增观测需按所属持久化机制记录，不能覆写已发布 Session 代际。历史可读不等于历史具备完整 Trace。
- 默认查询和导出使用脱敏摘要，不携带密钥、授权头、完整模型输入或全文；确有详情需求时由 C 明确访问与保存规则。不得为生成 Trace 再调用模型或重跑研究。

### 提前交接与验收顺序

1. **C-T0：接口先行。** C 交付最小字段与枚举、查询返回样例、脱敏规则、当前版本来源映射和实现目录建议，并标出待定项。纯样例可以先于 Web 和存储实现交付。
2. **A-T0 / B-T0：采集可行性。** A/B 各自列出 U0 中真实观察点、身份对应和缺失字段；无法确认的条目标为待查。共同语义缺口反馈给 C 调整接口，不要求 C 改成新版 Session 专用结构。
3. **C-T1：实现现有版本。** C 基于交接结果完成当前版本适配器、统一投影/查询、界面及固定样例验收；HTML 交付可独立推进。
4. **A-T1 / B-T1：实现两路线适配。** A/B 分别接入自己的新版数据采集、持久化与 RPC，复用 C 的统一接口和界面；适配修改由各自负责人维护。
5. **C-T2 / A-T2 / B-T2：共同口径验收。** 三方验证相同脱敏场景的层级、状态、计数与时间语义，记录各适配器的输入和差异；通过后再进入第三轮增量集成。

固定样例至少覆盖正常完成、失败后重试成功、超时、取消、并发调用、重复事件、重启后在途和旧记录缺字段。缺时间的样例不能出现假零耗时，重复事件不能增加调用数，取消与中断不能变成成功，历史缺字段须在查询与页面中可见。涉及新版真实采集的结果由 A/B 提供；本轮计划补充不声称这些场景已实现或通过。

## 共同验收与路线选择

两条路线使用同一版批准计划、固定论文输入和预期；模型、Provider、预算等不同会影响对比时，须在记录中注明。先用不联网固定样本检验回归，再用小范围真实研究确认集成。

| 场景 | 最低验收内容 |
| --- | --- |
| 固定一篇有全文论文 | 全文、证据定位、草稿和下载；无模型输入或身份串用。 |
| 小范围多来源主题 | 学术源与 Web 路由、身份核验、去重、候选排序、逐题覆盖及限制说明。 |
| 证据不足 | 不虚报报告达标；能保留已完成工作并说明未覆盖问题。 |
| 生命周期 | 修改计划、批准、普通追问、取消、检查点恢复和刷新后的结果查询。 |
| 历史与配置 | 支持范围内的旧会话读取、密钥来源、配置及数据隔离；不覆写原始数据。 |
| C 的功能增量 | 对已经共享的 HTML 与 Trace 按同一交付版本验收；未共享部分列为待办。 |

路线选择依据依次为关键功能完整性、数据安全与兼容、已知回归、必要基座修改量和后续升级维护成本。通过编译或“冲突更少”不能单独证明路线更优；上游提交数量也不等于缺陷数量。

各负责人按变更范围运行仓库要求的检查，记录命令和结果；共享业务基线已有缺陷单列，外部服务失败与代码回归分开举证。未完成项不标为通过。

## 运行隔离与协作规则

- A/B 使用不同工作目录、依赖与构建输出，分别设置测试 `DSH_HOME` 和端口，不共用正在使用的真实数据目录。
- 每次真实测试记录工作目录、分支、提交、实际监听端口、运行数据位置和研究 ID；打开页面前核对这些信息，避免启动到其他 dsh 副本。
- 测试使用数据副本，保留 T0 原始数据；回退时恢复代码与对应数据版本，不让旧程序读取未经验证的新版写入结果。
- C 的功能 PR 继续进入团队主线；A/B 定期登记增量，不把 T0 悄悄改为新的起点，也不要求 C 在三个版本同时修复。
- 升级分支可先创建用于协作，但不得因分支已发布就认为适合合并；分支初始状态与测试状态分别记录。
- 本方案登记不执行上游合并、业务迁入、源码修改、真实服务切换或 master 更新。
