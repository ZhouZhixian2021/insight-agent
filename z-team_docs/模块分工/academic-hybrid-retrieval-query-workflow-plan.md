# 学术洞察新检索词流程与候选排序模块分工计划

## 1. 计划目标

本计划在现有“通用 Web 搜索＋多个学术源”的混合检索能力上增加统一的检索规划、论文分类、候选排序和分批全文获取流程。新流程不替换现有 Provider、Web discovery、论文核验、全文获取和证据抽取模块，而是在 ResearchBrief 与混合检索之间增加查询计划，在去重与全文获取之间增加候选评估。

目标是提高最终候选论文与研究要求的匹配度，减少低价值论文进入全文获取和证据抽取阶段，并保留混合检索对长尾论文和用户指定学术源的发现能力。

## 2. 目标流程

```text
用户请求
  → ResearchBrief 与人工确认
  → 混合检索计划
      → 结构化学术源查询
      → 通用 Web 查询
      → 用户指定站点查询
      → 引用与相关论文扩展
  → Web 结果学术身份核验
  → AcademicWork 标准化
  → 跨来源去重与版本合并
  → 硬性条件过滤
  → 标题、摘要和元数据分类
  → 相关性、证据潜力和来源多样性排序
  → P0/P1/P2 候选队列
  → 第一批全文获取与证据抽取
  → 研究问题覆盖检查
  → 按证据缺口定向补检或补选
  → 达到目标、饱和或预算上限后结束
```

## 3. 模块划分

### 3.1 检索计划模型

职责：

- 从 ResearchBrief 派生检索约束；
- 区分核心查询、同义词扩展查询、站点限定查询和缺口补检查询；
- 为不同渠道保存不同查询；
- 保存时间范围、文献类型、必须包含项和排除项；
- 记录每轮检索目的，不把所有查询合并成一个宽泛检索词。

建议核心数据：

- `HybridSearchPlan`；
- `AcademicSearchQuery`；
- `WebDiscoveryQuery`；
- `SiteRestrictedQuery`；
- `CitationExpansionSeed`；
- `SearchRoundPurpose`。

### 3.2 混合检索执行

职责：

- 将渠道对应的查询发送给 OpenAlex、arXiv、Web discovery 和后续 Provider；
- Provider 之间独立超时、独立结算；
- 保留候选记录的发现渠道和原始标识；
- 单个 Provider 失败不能抹掉其他 Provider 的结果；
- 用户指定网站通过站点限定查询进入 Web discovery；
- Web 结果必须完成学术身份识别和核验后才能成为正式论文候选。

### 3.3 候选标准化与去重

职责：

- 将不同来源结果统一为 AcademicWork；
- 按 DOI、arXiv ID、规范化标题和作者进行去重；
- 合并预印本、会议版和期刊版的版本关系；
- 保留 `discoveredBy`、核验状态和来源追踪信息；
- 未核验网页只能作为检索线索，不能进入正式证据链。

### 3.4 候选分类与排序

职责：

- 先执行时间、文献类型和排除主题等硬过滤；
- 再根据标题、摘要、关键词和元数据分类；
- 计算相关性、证据潜力、研究质量、时效性和全文可用性；
- 将候选分为 P0、P1、P2 和 excluded；
- 为每篇候选保存入选、降级或排除原因；
- 使用来源和主题多样性约束，避免高分结果全部集中在相同方法或相同团队。

建议分类：

- 核心方法论文；
- 实证评估论文；
- Benchmark 或数据集论文；
- 综述论文；
- 应用论文；
- 邻近技术论文；
- 背景论文；
- 不相关论文。

### 3.5 分批全文获取与缺口补检

职责：

- 首批只处理排名最高且能覆盖不同研究问题的论文；
- 完成一批证据抽取后重新计算问题覆盖；
- 第二批优先补充缺失研究问题、方法路线、反面证据和来源多样性；
- 只在必要时扩大查询范围；
- 达到目标、候选饱和或预算上限后停止；
- 最低纳入数量、目标数量和最大数量使用不同字段。

- 将检索规划、混合检索、候选排序、全文批次和证据缺口补检串成工作流；
- 定义新版 Session 事件和实时进度字段；
- 保证旧 Session 数据继续可读；
- 负责跨模块集成测试和最终验收。

主要目录边界：

- `packages/academic/model/`；
- `packages/academic/workflow/`；
- `packages/api/academic-research-controller/`；

成员 A 不在成员 B 的检索实现目录中直接修改 Provider、查询生成和候选评分内部逻辑。

### 4.2 成员 B：检索智能、学术源与候选评估

负责范围：

- 根据成员 A 定义的共享类型实现渠道化查询生成；
- 实现核心查询、同义词扩展、站点限定和缺口补检查询；
- 执行 OpenAlex、arXiv、Web discovery 和用户指定站点检索；
- 实现 Web 结果的学术身份识别与核验；
- 提供 AcademicWork 标准化、去重和版本合并结果；
- 实现候选硬过滤、分类、评分和排序；
- 输出每篇候选的匹配问题、评分分项、优先级和决策理由；
- 为全文调度提供稳定的 P0/P1/P2 候选队列。

主要目录边界：

- `packages/academic/source/`；
- `packages/academic/ingestion/`；
- 后续经团队确认的新检索规划或候选评估包；
- 与检索、核验、去重和排序直接对应的测试与文档。

成员 B 不直接修改 Controller、Web 界面或最终报告生成逻辑。

### 4.3 成员 C：计划确认、候选解释与进度界面

负责范围：

- 支持用户确认、修改或批准检索范围；
- 展示候选论文分类、评分、优先级和入选原因；
- 支持用户提升、降低或排除候选论文；
- 展示“发现、核验、去重、排序、全文、抽取、纳入”的稳定进度口径；
- 展示当前研究问题覆盖和下一轮补检原因；
- 完成中文和英文界面文案以及产品交互测试。

主要目录边界：

- 学术研究 Web 客户端和 UI 组件目录；
- 客户端本地化词典；
- UI presenter、视图模型及对应测试。

成员 C 不修改 Academic Model、Provider 和候选评分实现。

交付内容：

- 候选分类；
- 分项评分；
- P0/P1/P2 队列；
- 多样性约束；
- 决策理由。

输入输出：

- 输入使用已批准 Plan、同版本 Brief、Q3 `PlannedSearchRoundResult` 及每项成果一份共享 `CandidateAssessment`；Q3 已有成果、规范版本和查询来源不得再次包装；
- 输出使用 `AcademicCandidateRankingResult`，`evaluations` 保存逐篇解释，`queues` 保存调度顺序；
- B 可在自己的候选评估包内实现分类和排序，但不得调用 Controller、Session、Web UI 或全文下载服务；
- 同一组评估和同一排序策略必须得到相同队列顺序；每个规范版本只能出现一次；
- `decisionReasons` 保存供审核者阅读的解释；硬过滤的 `reasons` 同时保存稳定代码和可选审核细节，程序过滤和 C 的本地化判断不得解析自然语言文案。

硬过滤口径：

- 成果或版本已撤回、Plan 不允许预印本、版本类型不在纳入类型中时排除；
- Plan 有日期范围时，早于范围、晚于范围或日期未知均排除；Plan 没有日期范围时，日期未知可以保留，但时间新颖性不得凭空加分；
- 已审核 `requiredTerms` 未满足或 `excludedTerms` 命中可信学术元数据时排除；
- 自然语言纳入／排除规则不允许被静默改写成另一套隐藏规则；B 使用它们时必须留下可解释决定，无法可靠判断时保留候选并记录限制；
- Web 结果只有在 Q3 完成学术身份核验并形成正式 AcademicWork 后才进入 Q4，未核验网页不以“候选论文”身份进入 excluded 队列。

评分与分类口径：

- 主题相关性、问题匹配度和方法匹配度使用题名、可信摘要、可信关键词及 Plan 中已审核术语；
- B 的纯排序包不调用模型；A 传入已审核的语义比例与规则判定，若这些判断来自模型，A 必须使用已固定的模型适配器、Session 记录和失败处理；
- 摘要或关键词不可用时允许降级评分，但不得使用 Web discovery 摘要补齐，也不得声称已完成摘要语义判断；
- 证据潜力只根据可信元数据中明确出现的实验、数据、方法或评测信号判断；
- 来源与研究质量只使用学术身份核验、标识符、版本状态和元数据完整度；第一版不推断会议等级、期刊分区、团队声望或引用影响力；
- 全文可用性只使用 A 提供的全文解析事实，B 不自行探测或下载全文；
- P0/P1/P2 阈值由 `CandidateRankingPolicy` 决定，硬过滤排除或总分低于 P2 阈值时进入 excluded。

队列与多样性口径：

- B 先按优先级分组，再在每组内生成确定性顺序；多样性调整不得把候选移到与分数不一致的另一优先级；
- 队列应优先保留不同研究问题、候选分类和方法标签的覆盖，避免相邻候选全部来自相同主题路线；
- 当前模型没有机构或团队身份，第一版只能使用规范化作者重叠作为近似信号，不能把“同作者”解释成已确认的同一研究团队；
- B 必须用固定评估样例证明重复排序顺序稳定，并证明多样性处理不会丢失候选或产生重复版本；
- 如果多个候选在 B 的多样性规则后仍无法区分，最终使用 `academicWorkId` 字典序作为稳定兜底，不依赖输入并发完成顺序。

## 7. 第一版排序规则

第一版使用可解释的分项评分，不让模型直接输出不可解释的最终排序：

| 分项 | 建议权重 |
|---|---:|
| 核心主题相关性 | 30 |
| 研究问题匹配度 | 20 |
| 实验或数据证据潜力 | 15 |
| 方法匹配度 | 10 |
| 文献类型适配度 | 8 |
| 来源与研究质量 | 7 |
| 时间新颖性 | 5 |
| 全文可用性 | 5 |

优先级建议：

- 80 至 100：P0；
- 65 至 79：P1；
- 50 至 64：P2；
- 低于 50 或违反硬条件：excluded。

权重和阈值属于可配置策略，需用真实研究数据校准，不能散落为插件内部硬编码常量。

## 8. 分批策略

第一版建议：

- 第一批：8 篇 P0，兼顾研究问题和论文类型多样性；
- 第二批：最多 4 篇，专门补充证据缺口；
- 后续批次：每批 3 至 5 篇，只在目标尚未达到时执行；
- 达到目标纳入数量并满足覆盖后停止；
- 达到最低数量但未达到目标时继续补选，直到候选耗尽、饱和或预算耗尽；
- 连续两轮没有增加有效证据时允许判定饱和。

批次数值均需进入 ResearchBrief 或部署配置，不作为不可修改的实现常量。

## 9. 验收标准

### 9.1 功能验收

- 同一个 ResearchBrief 能生成学术源、Web 和站点限定查询；
- Web 发现结果未经核验不能进入正式证据链；
- 同一论文的多个来源和版本不会重复占据候选名额；
- 每篇候选都有分类、分项评分、优先级和决策理由；
- 全文获取按批次执行，不再默认一次处理全部候选；
- 后续批次由研究问题覆盖缺口驱动；
- 用户可以在执行前审阅检索计划；
- 用户可以调整候选优先级或排除论文；
- 旧 Session 仍可读取和展示。

### 9.2 效果验收

使用同一组固定研究任务对比旧流程和新流程：

- 最终纳入论文数量不下降；
- 首批候选的最终纳入率提高；
- 为达到相同纳入数量而获取的全文数量下降；
- 为达到相同证据覆盖而执行的抽取批次数下降；
- 低相关论文进入全文阶段的比例下降；
- 用户能够解释每篇论文为什么被优先处理。

第一版不预设虚假的提升百分比，先建立基线，再确定量化门槛。
