# 学术洞察候选语义审核减负与并发优化分工

## 状态与目标

**待实施。** 本方案只调整去重后、全文获取前的候选审核，不改变已批准 Plan 的研究范围、检索与去重规则，也不把标题或摘要当作全文证据。2026-10-19 的真实运行用 8 次串行模型审核耗时 15 分 26 秒，仅 3 次得到有效审核；3 次触及 8,192-token 输出上限，1 次超时，1 次解析失败。该轮最终有 14 篇候选、9 篇实际纳入，但候选数与模型审核数不是同一口径。当前本地的“最多审核 8 篇”改动尚未提交，实施时应和本方案一并核对，不能把 8 篇误认为 Plan 的候选上限。

目标是让模型只判断论文是否明显偏题、是否真正涉及已批准的研究问题。词项命中、来源和元数据完整度由代码计算；模型不在候选阶段生成方法、证据类型、贡献或论文结论。对尚不能确定的论文保留 `unknown`，只有有学术标题或摘要原文支持的明确偏题才能排除。模型审核不是全文证据抽取，也不改变后续逐篇纳入规则。

## 审核输入与输出

| 项目 | 调整后的口径 |
| --- | --- |
| 模型输入 | 每篇只发送学术 Provider 的规范标题和可信摘要、当前批准研究问题及判断研究范围所必需的纳入／排除规则；问题只出现一次。缺摘要须明确标记。Web 摘要、完整 Plan JSON、检索路由、关键词命中列表、方法／证据／贡献概念组和由代码计算的时效参数不进入此调用。 |
| 本地输入 | A/B 仍使用同版本已批准 Brief、Plan、Q3 去重结果、来源记录及全文可用事实；用确定性代码计算标题、摘要、学术关键词的词项命中和元数据分数，保留其来源，不把词项命中解释为语义匹配。 |
| 模型输出 | 最小判断包含三态范围结论 `potentially_relevant`／`off_topic`／`unknown`、真正匹配的已批准研究问题及简短依据。每个问题最多一条判断；明确偏题必须附标题或摘要中的短原文片段，经代码逐字核对。不能确定时返回 `unknown`，不得因摘要缺失或检索词不匹配直接排除。 |
| 保留的共享数据 | A 决定是否增加内部轻量模型响应类型；正式 `CandidateScreeningDetails`、`CandidateAssessment`、Q6 和 Session 事件的兼容口径由 A 统一维护。适配层把本地词项命中与模型语义结论合成现有评估，不让模型复制 `surfaceKeywordHits`。 |

模型提示词只描述上述判断和必要的 JSON 字段，不要求模型抄写全部命中词、逐项列方法和证据类型、生成长篇理由或研究发现。简短提示词可能减少正文输出，但该轮日志的推理内容远长于最终 JSON；A 须同时测量模型路由的推理开销，不能仅以提高输出上限代替诊断。

## 评分与失败语义

1. 正式 `CandidateAssessment.matchedQuestions` 只有在成功的模型判断实际匹配研究问题后才计作语义匹配；批次路由继续从 Plan 查询关联和 Q3 `discoveredBy` 推导，不另增 `routedQuestions` 字段。代码计算的词项命中单独保存，不冒充模型判断或原文证据。
2. B 检查现有排序器对方法、证据类型和贡献线索的依赖。删去这些模型输出时，不能让“已审核”分支把确定性词项线索清零，也不能把词项线索标作已语义核实。保留既有批准 Plan 的权重和阈值；如果因此出现 P0 数学上不可达，须由 A 固定新 Plan 的评分版本和兼容策略，不能在运行中静默改批准参数。
3. 模型超时、输出截断或 JSON／引文校验失败时记录失败阶段和代码，保留论文及本地初筛信息；语义结论为未知，不把调用失败转成偏题，也不按检索路由增加语义分。未进入有限审核预算的候选同样标明“未审核”，与“审核后未知”区分。
4. 原文片段只证明审核判断有可核对来源，不构成全文证据。后续全文获取、证据抽取和 Q7.4 逐篇纳入保持独立。

## 并发与顺序

首轮只把候选模型审核改为**最多 2 个同时在途**。A 在 Controller 中统一管理队列、取消信号、单次超时和 Session 请求／结果事件；达到预算后停止发起新审核。每篇成功、失败或超时都单独结算，不能取消其他已完成候选。排序器只接收按论文身份归并后的确定结果，不能因为请求完成顺序不同而改变最终 P0／P1／P2 顺序。若 2 并发使模型网关失败率升高，恢复 1 并发并保留诊断记录；不直接扩至 3。

## 成员分工与交付顺序

| 阶段 | 负责人 | 任务与交付 |
| --- | --- | --- |
| 接口先定 | A 与 B | 用同一批真实候选固定最小语义判断的输入、输出、原文校验和未知口径；A 确认共享类型、旧 Session 读取与 Q6 投影兼容。C 同步确认评测需要的状态与原因字段。 |
| 并行开发 | B（候选评估与排序） | 在 `packages/academic/retrieval/` 本地计算 `surfaceKeywordHits`，定义最小范围与问题语义判断的解析要求；调整纯评估器和排序器，使词项线索、语义结论和失败状态不混淆。B 保留用于函数行为的少量固定样例，不代替 C 的独立质量评测。 |
| 并行开发 | C（候选质量评测） | 在 `packages/academic/eval/` 固定本轮同 Plan 的 8 篇真实候选及少量否定句、摘要缺失、只命中词项的边界样例。按学术标题和摘要独立标注“相关／明确偏题／无法判定”、实际匹配问题及可核对片段；建立不调用模型的对比入口，分别统计错误排除、问题匹配、未知、审核失败、队列去向和耗时。标注分歧保留为待复核，不强行制造标准答案。此项不依赖 A 的模型并发实现，可立即开始。 |
| 接线 | A（Controller 与模型调用） | 精简 `candidate-review-model.ts` 的请求及提示词，解析最小响应并适配现有评估数据；在 `search.ts` 实现有界并发 2、稳定归并、取消与 Session 记录。保留审核预算独立于 Plan 候选上限。 |
| 下游回归 | C（分析与报告） | 对照旧／新候选去向，核查被保留论文能否支撑批准的研究问题，以及错误排除是否让 `packages/academic/analysis/` 的问题覆盖或 `packages/academic/report/` 的报告章节失去已有证据。对相同已验证证据运行既有分析和报告夹具，记录差异与缺口；候选标题或摘要不能直接作为全文证据，也不在本任务中重写分析、报告生成器。此项在 A/B 输出可对照的候选结果后开始。 |
| 集成 | C（结果呈现与评测） | 在 A 的投影稳定后，完善 `packages/academic/eval/` 的旧／新结果对比；在 `packages/client/ui-academic-research/` 显示“已审核相关／明确偏题／未知／审核失败／未审核”数量和主要原因，将候选总数、模型调用数与实际纳入数分开呈现。页面只消费 A 的状态接口，不复制 B 的评分算法。 |
| 验收 | A、B、C | 先对保存的同一批候选做定向复验，再决定是否启动完整研究；A 负责调用成功率、并发与墙钟时间，B 负责评分逻辑与排序复现，C 独立核对误排除、问题匹配、边界样例及页面口径。C 的质量评测结论与 B 的实现测试分开记录。 |

## 固定验收要求

1. 相同批准 Plan 和去重候选重复运行时，本地词项命中、语义结果归并及最终队列顺序一致；在测试中证明同时在途调用数不超过 2，取消后不发起新请求，单篇失败不抹掉已成功结果。
2. 明确偏题有可逐字核对的学术标题或摘要原文；缺摘要、否定句、无法判定、模型失败和未审核候选不会被误报为已语义核实，也不会仅因查询路由获得问题匹配分。
3. 用 2026-10-19 同一批 8 篇候选比较输入 tokens、最终 JSON 与推理 tokens、有效审核数、各失败代码及审核阶段墙钟时间。目标是消除因候选输出格式过重造成的截断，并在成功率不下降的前提下使 2 并发阶段耗时低于本轮 15 分 26 秒；若仍大量消耗推理 tokens 或成功率下降，先核查模型路由，不以更高并发掩盖问题。
4. 复验既有评分样例，确保语义相关论文有合理高优先级路径，词项偏题论文不会因表面命中进入高优先级；任何调整批准 Plan 权重或阈值的方案单独审核，不与此次提示词改动混合。
5. C 的独立评测逐篇对照人工标注与新旧审核输出：固定样例中不允许有明确相关论文被错误排除；列出问题匹配的误判、未知与审核失败，不用一个总准确率掩盖不同错误。8 篇真实候选只用于同轮回归，不宣称能够代表所有研究主题。
6. C 用同一批已验证证据核对问题覆盖和报告内容：语义审核减负不能把已有证据从分析、引用或报告章节中无故移除；如果候选误排除造成缺口，评测明确列出对应论文、研究问题和受影响章节，而不是让报告模型补写不存在的证据。
