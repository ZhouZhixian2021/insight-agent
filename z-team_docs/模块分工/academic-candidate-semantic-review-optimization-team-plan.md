# 学术洞察候选语义审核减负与并发优化分工

## 状态与目标

**A 的正式运行接线和本批调用稳定性复验已本地完成，团队尚未完成独立质量评测及页面、下游验收。** 截至 2026-10-20，B 的纯解析器、送审选择器、评估器线索合并及固定样例已随 PR #100 合入 `master`。A 已接入精简请求、独立审核预算、版本化 Session 事件和逐篇状态投影，正式默认及本机 Web 部署并发为 1，可显式配置为 2；A 的接线、配置与已有验收材料随本次提交交付，供成员共享复核；完整评分输入包仍待整理。本方案只调整全文前的候选审核，默认 8 篇是跨轮审核预算，不是 Plan 候选上限，标题与摘要也不成为全文证据。

| --- | --- | --- | --- |
| 旧交换，Pro 串行 | 3/8 | 1／3／1 | 约 15 分 25 秒 |
| 精简交换，Pro 并发 2 | 2/8 | 6／0／0 | 600.283 秒，约 10 分钟 |

Pro／Flash 串行对比使用相同八篇、模型消息及除模型 ID 外相同的请求配置。Flash 本批耗时缩短约 51.6%，八篇范围判断相同，五篇匹配问题集合相同，三篇增加问题匹配。有效审核只表示结构及原文引文校验通过，不表示独立相关性评测通过；测量时间和模型生成长度不同，不能把耗时收益推广到所有课题或认定并发 2 触发账户限流。完整执行条件、用量与原始输出见[真实审核复验记录](../开发记录/2026-10-20-zhouzhixian2021-候选语义审核固定样本复验.md)。

目标是让模型只判断论文是否明显偏题、是否真正涉及已批准的研究问题。词项命中、来源和元数据完整度由代码计算；模型不在候选阶段生成方法、证据类型、贡献或论文结论。对尚不能确定的论文保留 `unknown`，只有有学术标题或摘要原文支持的明确偏题才能排除。模型审核不是全文证据抽取，也不改变后续逐篇纳入规则。

## 审核输入与输出

A 已固定供 B、C 核对的[最小输入、返回字段、固定样例与旧记录兼容口径](academic-candidate-semantic-review-interface-v1.md)。Controller 已在本地正式调用 B 的 `parseCandidateSemanticReview()`、`selectCandidateReviews()` 和 `screeningFromSemanticReview()`；共享 `CandidateReviewSelectionV1` 记录送审决定，`CandidateSemanticReviewStateV1` 记录逐篇审核结算。

| 项目 | 调整后的口径 |
| --- | --- |
| 模型输入 | 每篇只发送学术 Provider 的规范标题和可信摘要、当前批准研究问题及判断研究范围所必需的纳入／排除规则；问题只出现一次。缺摘要须明确标记。Web 摘要、完整 Plan JSON、检索路由、关键词命中列表、方法／证据／贡献概念组和由代码计算的时效参数不进入此调用。 |
| 本地输入 | A/B 仍使用同版本已批准 Brief、Plan、Q3 去重结果、来源记录及全文可用事实；用确定性代码计算标题、摘要、学术关键词的词项命中和元数据分数，保留其来源，不把词项命中解释为语义匹配。 |
| 模型输出 | 最小判断包含三态范围结论 `potentially_relevant`／`off_topic`／`unknown`、真正匹配的已批准研究问题及简短依据。每个问题最多一条判断；明确偏题必须附标题或摘要中的短原文片段，经代码逐字核对。不能确定时返回 `unknown`，不得因摘要缺失或检索词不匹配直接排除。 |
| 保留的共享数据 | A 已固定 `CandidateSemanticReviewRequestV1`／`CandidateSemanticReviewV1` 轻量交换类型；B 已增加 `CandidateReviewSelectionV1` 并实现纯适配函数。正式 `CandidateScreeningDetails`、`CandidateAssessment`、Q6 和 Session 事件的兼容口径由 A 接线维护。本地词项命中由代码计算，不让模型复制 `surfaceKeywordHits`。 |

模型提示词只描述上述判断和必要的 JSON 字段，不要求模型抄写全部命中词、逐项列方法和证据类型、生成长篇理由或研究发现。简短提示词可能减少正文输出，但该轮日志的推理内容远长于最终 JSON；A 须同时测量模型路由的推理开销，不能仅以提高输出上限代替诊断。

## 哪些候选进入模型审核

模型调用预算只限制**送审数量**，不改变 Plan 的候选上限，也不等于全文处理或最终纳入数量。`search.ts` 在硬筛选和全文地址检查后调用 B 的纯选择器，按以下确定性规则分配审核机会；选择结果及跳过原因写入 Session，供重放和评测：

1. 先完成 Q3 去重及已批准的日期、版本、撤稿等硬筛选。硬排除、全文地址不可解析、同一规范论文已在本轮审核或尝试过的记录不再送模型；它们分别保留原有排除或尝试原因。
2. 在其余候选中，以已批准查询的 `discoveredBy` 只做**送审覆盖路由**：按 Plan 中研究问题顺序，每个尚未覆盖且有候选的问题优先取当前词项初排最高的一篇；一篇可覆盖多个路由问题，但路由仍不算语义匹配。若预算少于可覆盖的问题数，按 Plan 顺序分配并显式记录未覆盖的问题。
3. 剩余名额再按现有词项初排顺序补齐。可信学术摘要完整的候选优先于仅有标题的同优先级候选；摘要缺失只降低送审优先次序，不能单凭此排除论文或宣称其偏题。排序同分时使用固定的规范论文身份作最终破同分键，不依赖 Provider 返回或模型完成顺序。
4. 记录每篇的 `selected`、`not_selected_budget`、硬排除或已有结果状态及对应研究问题路由。未送审的合格候选继续以本地初筛的未知语义状态参与既有排序和后续批次，不把“省略调用”伪装成模型否定结论。新一轮只从尚未尝试的合格候选中补位；预算耗尽时不重审旧候选。

A 已接入送审选择、独立审核预算与 Session 事件；C 仍需用同一 Plan 的固定候选核查问题覆盖、遗漏的相关论文和未送审状态。若该规则让重要论文系统性缺席，应先看选取名单和原因，再讨论改预算，不靠提高并发掩盖选择偏差。

## 评分与失败语义

1. 正式 `CandidateAssessment.matchedQuestions` 只有在成功的模型判断实际匹配研究问题后才计作语义匹配；批次路由继续从 Plan 查询关联和 Q3 `discoveredBy` 推导，不另增 `routedQuestions` 字段。代码计算的词项命中单独保存，不冒充模型判断或原文证据。
2. B 已调整评估器：最小审核未提供方法、证据类型或贡献线索时，回落到代码计算的词项线索；问题语义匹配仍只来自有效模型判断，词项线索不标作已语义核实。既有批准 Plan 的权重和阈值未改；正式接线后仍须检查 P0 是否可达，若需改评分版本，由 A 单独固定兼容策略，不能在运行中静默改批准参数。
3. 模型超时、输出截断或 JSON／引文校验失败时记录失败阶段和代码，保留论文及本地初筛信息；语义结论为未知，不把调用失败转成偏题，也不按检索路由增加语义分。未进入有限审核预算的候选同样标明“未审核”，与“审核后未知”区分。
4. 原文片段只证明审核判断有可核对来源，不构成全文证据。后续全文获取、证据抽取和 Q7.4 逐篇纳入保持独立。

## 并发与顺序

候选模型审核正式默认**同时在途 1 个**，部署可显式选择 2；当前路由的并发 2 复验出现较多超时，先保留并发 1。A 在 Controller 中统一管理队列、取消信号、单次超时和 Session 请求／结果事件；达到预算后停止发起新审核。每篇成功、失败或超时都单独结算，不能取消其他已完成候选。排序器只接收按论文身份归并后的确定结果，不能因为请求完成顺序不同而改变最终 P0／P1／P2 顺序。任何恢复并发 2 的决定应有当前路由的稳定性依据，不直接扩至 3。

## 交接材料与后续执行顺序

已保存的[固定研究范围与可信标题／摘要](../验收数据/2026-10-20-candidate-review/cases.json)、[Pro 并发 2／1 对照](../验收数据/2026-10-20-candidate-review/serial-eight.json)和[Flash／Pro 串行对照](../验收数据/2026-10-20-candidate-review/flash-eight.json)可直接供 C 做独立标注。三个文件中的模型结论均是待评测输出，不能当作人工标准答案。B 所需的完整批准参数、去重记录及评分／队列对象已有本机运行记录，仍由 A 整理为可共享材料后交付。

1. **A 补齐完整评分交接。** 现有接线、配置、文档和复验数据随本次提交交付；下一步补充可共享的批准参数、固定去重输入、送审名单和各模型候选评估／队列。本阶段不再重复八篇模型复验。
2. **B、C 并行核对。** B 负责评分和队列解释，C 负责独立相关性／问题匹配标注与页面状态呈现。C 先完成三篇分歧，不用重新生成八篇输出；页面可用固定数据开发，正式接入依赖 A 的共享提交。
3. **按发现的问题做局部修复。** 传输、提示词、预算、Session 与接线归 A；解析、送审选择、词项线索和排序归 B；独立评测、页面、分析及报告归 C。A/B 修改模型交换前先固定共享字段，不能让 C 单方面改调用协议。确定性问题重放现有输出验证，确需观察模型行为时只复验受影响候选，不追加泛化冒烟测试。
4. **联合收口。** 确认没有相关论文被误排除、问题匹配有内容依据、队列变化可解释、页面各数量口径一致、既有证据覆盖未退化，再由 A 组织一次完整真实研究验收。记录各阶段耗时和报告限制，分别标记调用稳定性、相关性质量及端到端结果；不以一次返回成功替代三类结论。

## 固定验收要求

1. 给定同一批准 Plan、去重候选及同一批已验证模型判断，本地词项命中、按论文归并和最终队列顺序可确定重放；不同模型或不同调用产生不同问题判断时，允许评分与队列变化，但必须可追溯。默认部署实际在途不超过 1；显式配置 2 时不超过 2，取消后不发起新请求，单篇失败不抹掉已成功结果。复用已有针对性验证，不重复运行通过的场景。
2. 明确偏题有可逐字核对的学术标题或摘要原文；缺摘要、否定句、无法判定、模型失败和未审核候选不会被误报为已语义核实，也不会仅因查询路由获得问题匹配分。
3. 用 2026-10-19 同一 Plan 和固定候选池逐篇列出送审名单与未送审原因，核对每个可覆盖研究问题是否获得送审机会；比较旧版前 8 篇与新版名单，特别记录被替换掉的相关论文。预算不变时，研究问题覆盖改善不能靠隐藏未审核候选得到。
4. 在**同一批固定送审论文**上比较单篇输入 tokens、提供方输出用量、可用的推理 tokens、最终 JSON 长度、截断次数、有效审核率（有效审核篇数／实际调用篇数）及每种失败代码的次数和分母。提供方没有单列推理或最终 JSON tokens 时记为未知，正文字符数不冒充 tokens。Pro／Flash 目前均未单列推理 tokens，不能宣布推理开销已按某个比例下降；不得只用总耗时达标宣称优化成功。
5. 审核阶段墙钟时间、单次时长、首个内容等待和流内长间隔分别记录。当前采用并发 1，历史并发 2 数据用于诊断，不因已完成复验再重复跑同批；恢复并发 2 或扩大预算须有新需求和当前路由的稳定性依据。Pro／Flash 的时段和生成内容不同，本批约 51.6% 提速不作为所有课题或整轮研究的保证。
6. 复验既有评分样例，确保语义相关论文有合理高优先级路径，词项偏题论文不会因表面命中进入高优先级；任何调整批准 Plan 权重或阈值的方案单独审核，不与此次提示词改动混合。
7. C 的独立评测逐篇对照人工标注与新旧审核输出：固定样例中不允许有明确相关论文被错误排除；列出问题匹配的误判、未知与审核失败，不用一个总准确率掩盖不同错误。8 篇真实候选只用于同轮回归，不宣称能够代表所有研究主题。
8. C 用同一批已验证证据核对问题覆盖和报告内容：语义审核减负不能把已有证据从分析、引用或报告章节中无故移除；如果候选误排除造成缺口，评测明确列出对应论文、研究问题和受影响章节，而不是让报告模型补写不存在的证据。
