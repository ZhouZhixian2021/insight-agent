## 1. 分析模块需要从证据中读取哪些字段？

建议区分论文信息和证据记录。一篇论文可以提供多条证据；每条证据应有独立标识和可用的原文定位信息，便于精确引用。

| 信息类别 | 建议字段或信息 | 分析用途及要求 |
|---|---|---|
| 稳定标识 | `paperId`、`evidenceId` | 唯一标识论文和证据，供引用、去重及结果关联使用。 |
| 论文身份 | 标题、作者、DOI/arXiv ID 等外部标识 | 确认研究对象、生成参考文献；外部标识缺失时仍需有内部 ID。 |
| 版本关系 | 同一工作的统一标识、版本 ID、前后版本关系 | 避免将预印本和正式发表版本计为两项独立研究。 |
| 时间与发表状态 | 首次公开日期、当前版本日期、发表状态、发表场所 | 支持时间分析，区分预印本、正式发表及后续修订。 |
| 研究问题 | 任务、研究对象、适用领域 | 按问题归类，避免混合不同任务的结论。 |
| 技术方法 | 方法名称、技术机制、核心假设 | 支持技术路线分类和方法比较。 |
| 研究发现 | 已提取的发现、作者陈述的局限 | 形成分析依据；每项提取结果应能指向对应原文。 |
| 实验信息 | 数据集、指标、数值、单位、指标方向、基线、实验条件 | 判断结果是否可比，支持定量比较。 |
| 证据内容 | 原文片段及其结构化提取结果 | 检查提取结果是否忠实，支持结论核验。 |
| 证据等级 | 元数据、摘要或全文 | 限定该证据能支持的结论范围。 |
| 原文位置 | 章节、页码、段落、表格或图编号等 | 定位结论依据；不同来源允许使用不同定位方式。 |
| 来源与溯源 | 来源 URL、来源提供方、抓取时间、内容版本或哈希 | 追溯分析使用的材料版本。 |
| 可用性与质量 | 缺失字段、缺失原因、提取失败或质量提示 | 区分原文未提供、尚未提取和无法访问。 |

不是所有证据都必须包含实验数值。例如，理论论文或摘要证据可能没有可用的实验表格。缺失数据应被明确表达，不能用默认值或模型推测填补。

请 A、B共同确定最小必填字段，以及缺失、未知、不适用和获取失败的统一表达方式。首次公开日期或原文位置不完整时，需要保留已知精度和缺失原因，不能补造精确日期、页码或段落。

## 2. 一项结论如何关联多个证据？

建议将分析结论和结论与证据的关联分别表示，采用多对多关系：一项结论可以由多条证据共同支持，一条证据可以用于多项结论，同一项结论也可以同时存在支持证据和反对证据。

每项结论建议包含以下信息：

| 字段或信息 | 用途 |
|---|---|
| `claimId` | 结论的稳定标识。 |
| 结论文本 | 面向用户的完整陈述。 |
| 结论类别 | 事实复述、跨论文综合判断、趋势、冲突或研究空白。 |
| 适用范围 | 任务、数据集、时间区间或其他成立条件。 |
| 证据关联列表 | 指向支持、反对或提供背景的证据。 |
| 不确定性与限制 | 说明结论不能推广到哪些范围。 |

每条关联建议包含 `claimId`、`evidenceId`、关联性质、支撑说明，以及需要进一步细化的原文位置。关联性质至少区分：

- 支持：直接或间接支持结论，支撑说明应说明推导关系。
- 反对：提供相反发现或反例。
- 背景：帮助解释问题，但不能作为证明该结论的依据。

示例：结论为“方法 A 在已检查的两个数据集上表现不同，其效果可能依赖实验条件”；证据 E1 在数据集 X 上报告提升，证据 E2 在数据集 Y 上未观察到明显提升。两条证据共同支撑效果存在条件差异，不能被改写成方法 A 普遍有效，也不能仅凭此确定差异的因果来源。

证据条数不能直接等同于支持强度。同一论文的多个版本、同一工作的多个段落，应保留依赖关系，避免重复累计。引用关系需要能够追溯到分析当时使用的证据版本；证据内容更新后，由 A 确定关联失效或重新评测的规则。

## 3. 趋势、冲突和研究空白分别需要哪些数据？

| 分析能力 | 所需数据 | 分析边界 |
|---|---|---|
| 研究趋势 | 可比较的时间字段、研究问题与方法分类、版本关系、各时间段的样本分布 | 明确采用首次公开还是正式发表日期；考虑版本重复和检索覆盖变化的影响。 |
| 共识与冲突 | 可对应的研究主张、发现、适用条件、数据集、指标、基线、实验设置、证据等级 | 先判断条件是否可比，再区分直接冲突、条件差异及信息不足。 |
| 研究空白 | `ResearchBrief` 中的问题与范围、已覆盖方向、作者明确提出的局限、检索覆盖记录 | 区分论文明确指出的不足和本次检索尚未覆盖的问题。 |

除单条证据外，还需要工作流或证据模块提供检索覆盖摘要，至少说明：

- 检索的数据源、查询主题、时间范围和筛选条件。
- 获取了哪些材料，哪些来源或全文访问失败。
- 是否存在截断、数量限制或其他覆盖限制。

如果缺少覆盖信息，趋势只能表述为本次材料中观察到的变化；研究空白只能表述为在本次范围内尚未找到充分证据，不能断言整个领域没有相关研究。基于检索结果数量的增长也不能直接作为整个领域热度增长的结论。

## 4. 报告需要哪些引用和置信度字段？

报告应使用分析结果中的结论与证据关联，保留引用和适用范围。引用部分需要：

| 数据 | 用途 |
|---|---|
| `claimId`、`evidenceId`、`paperId` | 将报告陈述连接到分析结果、证据和论文。 |
| 论文书目信息 | 标题、作者、年份、发表场所、发表状态等。 |
| DOI 或稳定来源链接 | 支持用户访问和核对原始材料。 |
| 原文位置 | 定位到支撑结论的片段、表格或章节。 |
| 材料版本及访问时间 | 说明分析使用的是哪个版本。 |
| 引用编号映射 | 由报告模块生成 `[1]` 等展示编号，底层仍使用稳定 ID。 |

建议将证据等级与结论置信度分开。读取到全文并不自动意味着结论可靠；多条摘要也不一定能够支撑实验细节。

结论置信度建议包含：

- 等级：例如高、中、低、无法判断，具体枚举由 A 统一确定。
- 判断依据：直接支持程度、独立研究数量、实验可比性、研究之间的一致性。
- 反对证据：是否存在尚未解释的反例或矛盾。
- 覆盖与质量限制：缺少全文、检索覆盖不足、提取质量问题等。
- 适用范围：在哪些任务或条件下成立。

第一版建议使用可解释的分级和理由。除非已有明确标注、校准和验证方法，不将模型自行给出的“90%”等数字作为概率展示。置信度分级规则和评审依据应可识别，以便报告与评测使用同一解释。

## 5. 评测如何判断结论是否有证据支持？

建议分两层评测：程序检查结构与引用是否完整，人工审核结论与原文之间的语义关系。模型辅助评审可以作为补充，不能单独视为正确性的证明。

| 检查维度 | 判断方式 |
|---|---|
| 引用存在性 | 引用的证据、论文和原文位置是否存在。 |
| 支撑覆盖 | 一句话中的关键事实是否都有依据；复合结论必要时拆分检查。 |
| 语义一致性 | 原文是否支持报告中的陈述，是否出现过度概括或含义改变。 |
| 数值一致性 | 数值、单位、指标方向、比较对象和实验条件是否对应原文。 |
| 证据等级适配 | 是否使用元数据或摘要推断只有全文才能支持的细节。 |
| 适用范围一致性 | 是否把特定数据集、特定条件下的结果推广为普遍结论。 |
| 反对证据处理 | 是否遗漏已知反例或将冲突证据当作一致支持。 |
| 去重与独立性 | 是否将同一工作的多个版本重复计算。 |
| 不确定性表达 | 证据不足时是否缩小结论范围并明确说明限制。 |

建议每项结论返回独立评测结果，状态至少能区分有支持、部分支持、受到反驳、无支持和无法判断。结果同时记录结论 ID、证据 ID、问题原因、评审方式及评审所用规则或样例版本。

“无支持”表示已检查的材料不提供所需依据；“无法判断”表示材料不可访问、信息缺失或条件不明确，无法完成判断。整体汇总规则由 A、B、C确认，存在支持与反对证据时应保留各条证据的评审结果，不能只留下一个覆盖全部差异的状态。

第一版固定测试集建议覆盖：

- 有直接原文支持的结论。
- 引用存在但内容不支持结论。
- 部分事实有支持、部分没有支持。
- 摘要证据不足以支持实验数值。
- 数字正确，但数据集或比较对象被替换。
- 两项研究实验条件不同，被误判为直接冲突。
- 同一论文多个版本被当作独立支持。
- 检索未发现相关工作，被误写为该领域尚无研究。

人工标注应提供期望判断及理由。评测除了检查报告形式，还应重点衡量无支持结论是否被识别，以及有支持结论是否被错误拒绝。第一版验收阈值及语义争议的复核方式由三方另行确认。

评测消费已交付的证据和原文定位信息；在线来源可达性由 B 提供获取状态或由 A 调度复核，不要求分析、报告或评测模块自行重新抓取来源。
