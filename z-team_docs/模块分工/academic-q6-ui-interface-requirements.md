## 2. 所需只读返回数据

### 2.1 身份、版本与可用状态

每份展示数据需要与当前 Session、`retrievalRunId`（运行期间）、`researchBriefId` 和准确的 Brief 版本关联。计划预览与运行数据的关联方式、计划是否尚未生成、候选是否尚未评估、覆盖是否尚未结算等状态由 A 明确。

运行中投影需要序号或等效的版本机制，供 C 排除旧数据。已完成的有效空结果、尚未生成的数据和加载失败必须可区分。未提供数据不能显示为零、无缺口或未运行。不同运行的数据不能拼成一张当前结果表。

### 2.2 检索计划

建议直接复用 `HybridSearchPlan` 及其已有类型，必要时由 A 提供浏览器安全投影：

| 所需内容 | 已有类型／字段 | 页面用途 |
|---|---|---|
| 研究身份与版本 | `researchBriefId`、`researchBriefVersion` | 确保当前预览对应已审核范围 |
| 时间、版本类型、纳入／排除规则、术语限制 | `constraints` | 说明研究范围及硬过滤条件 |
| 最低、目标、最大纳入数 | `inclusionTargets.minimum/target/maximum` | 分别解释交付下限、期望目标和绝对上限，不能把达到最低数显示为达到目标 |
| 查询及来源 | `queries` 中的 ID、`kind`、`expression`、`purpose`、`questions`、`roundIndex` | 按渠道和轮次展示，并关联其研究问题 |
| 学术来源、站点、Web 上限 | 各查询类型中的 `providers`、`siteHost`、`maximumResults` | 区分直接学术检索、Web 发现和指定站点检索 |
| 排序权重与阈值 | `rankingPolicy` | 解释分项分数和 P0/P1/P2 的含义，不在前端硬编码另一套规则 |
| 最大轮次及计划限制 | `maximumSearchRounds`、规划输出 `warnings` | 展示预算和已知限制 |

本轮展示只读计划。现有聊天中的计划修改与审核流程继续作为实际审批入口；如果 A 尚未暴露某类计划，不显示可执行的修改或批准按钮。引文扩展种子可以显示已批准的现有事实，但新增引用扩展执行和控制不在本轮范围内。

### 2.3 候选分类与排序

建议复用 `AcademicCandidateRankingResult`，并提供与评估准确关联的最小论文展示资料：

| 所需内容 | 已有类型／字段或补充需求 | 页面用途 |
|---|---|---|
| 论文与版本身份 | `academicWorkId`、`workVersionId` | 防止同一论文不同版本混淆 |
| 标题、作者、公开日期、版本类型、稳定学术标识 | 来自 Q3 的正式 `AcademicWork`／`WorkVersion`；A 确定最小投影 | 让用户知道被评估的是哪篇论文，不用 ID 代替标题 |
| 可信摘要与关键词的可用状态 | `CandidateAssessment.abstract/keywords`；是否投影正文由 A、B 确认 | 说明评分基于标题还是可信元数据；不以 Web 摘要补齐 |
| 分类、优先级与分项得分 | `evaluations[].classification/priority/score` | 展示实际评估结果；前端不重算总分 |
| 硬过滤与决定原因 | `hardFilter.reasons`、`decisionReasons` | 原因代码本地化，审核细节原样展示；不得解析自然语言生成另一种业务判断 |
| 匹配问题、发现查询与多样性标签 | `matchedQuestions`、`discoveredBy`、`diversityTags` | 解释为什么优先处理，以及线索由何种查询发现 |
| 全文解析事实 | `fulltextAvailability` | `unresolved` 表示尚未解析出全文入口，不显示为“论文没有全文” |
| 权威队列与限制 | `queues.p0/p1/p2/excluded`、`limitations` | 逐队列按 B 返回顺序展示；不二次排序或隐藏降级限制 |

候选“已核验”“通过硬过滤”“排名优先”“已安排全文”“已有合格证据”“最终纳入”是不同事实。评分较高不能显示为证据已支持研究结论；普通未核验网页不得作为候选论文进入列表。论文资料缺失时显示明确缺项，不编造标题、年份或身份关系。

### 2.4 进度漏斗与批次

建议复用 `CandidateFunnelCounts`、`QueryWorkflowProgressEvent` 和 Q5 批次决定／结算事实，并与已有实时阶段共用同一运行身份：

- 展示发现记录、已核验论文、去重论文、符合条件论文、P0/P1/P2 与排除数量、已安排全文和实际纳入数。
- 发现记录与论文不是同一种计数单位；按实际字段显示，不要求所有数字构成严格递减漏斗。
- `scheduledFulltextWorks` 不能显示为全文获取成功。取得全文、验证通过的证据和最终纳入继续使用其实际事实；如需有效证据论文总数，由 A 提供准确口径，C 不从版本数组或模型返回数推算。
- 展示当前轮次、批次、所选版本、批次动作及原因。Q5 持久化批次下标为零基，部分已有查询／分段编号为一基；A 应确认投影基数，C 只做明确的显示转换，不混用编号。
- 计数是当前绝对观察值，不是每次应累加的增量。重排或补检后以较新的完整结果更新；跨查询重复、跨轮次去重和已处理候选的计数定义由 A、B 明确。

### 2.5 逐题覆盖、补检与停止

建议复用 `ResearchQuestionCoverageResult` 和 `SearchStopDecision`：

- 每个准确研究问题的 `uncovered/partial/covered`、支撑论文 ID、证据 ID 和 `gaps`。
- `evidenceRequirementsMet` 与 `allQuestionsCovered` 分别展示，不把纳入数量达标等同于问题覆盖。
- 当前缺口触发的补选／补检动作、关联问题和解释；未提供时显示未知，而不是“无需补检”。
- 停止决定及 `SearchStopReason`：达标、饱和、候选耗尽、轮次／数量／时间预算耗尽、取消和需要重新审核，按正式代码分别解释。
- 覆盖不是候选 `matchedQuestions` 的汇总。只有生产方根据获准证据计算的覆盖才可显示为证据覆盖；候选匹配仅表示潜在相关。

## 3. 本轮需要的接口能力

以下是能力需求，不冻结方法名或请求结构。A 可扩展现有返回类型，也可提供独立只读投影；C 不先自行创建另一套正式 Remote。

| 能力 | 调用目的 | 必须明确的行为 |
|---|---|---|
| 读取已批准检索计划 | 执行前展示完整渠道化范围 | 不启动研究、不重新生成查询；审批身份过期时提示重新审核 |
| 获取运行内 Q6 投影 | 展示候选、队列、覆盖、批次与停止事实 | 与既有 `runStream` 共用同一次执行；不能为了读数据再调用一次 `run` 或 `runStream` |
| 获取终态 Q6 投影 | 在报告旁保留本轮解释 | 与最终结果对应同一运行、同一计划版本，不覆盖已知失败与限制 |
| 读取已保存结果（若本轮支持） | 页面再次打开时查看已保存事实 | 仅查询不启动或恢复研究；若未实现恢复，明确暂不支持 |

A 需要确认投影采用完整快照还是增量、何时发送候选评估、批次结算与覆盖、候选分页／数量上限、截断标记，以及投影不可用时的状态。优先沿用完整快照加递增序号的现有模式。C 的搜索与筛选仅改变展示，不改变真实队列或后台调度。

## 4. 后续操作需求，不阻塞本轮只读开发

验收数据稳定后，再由 A、B、C 确认以下操作接口：

- 修改检索范围并重新提交审核：哪些字段允许改、如何生成新版本、旧批准身份如何失效。
- 提升／降低候选优先级、排除和撤销排除：允许的执行阶段、准确论文／版本标识、用户理由、并发版本校验与操作幂等性。
- 人工偏好是否是独立于 B 自动评分的调度覆盖：保留原始分数、原队列和用户操作，不直接篡改 B 的评估结果。
- 已进入全文／证据处理的候选如何处理调整；硬过滤拒绝是否可撤销、是否需修改计划并重新审批。前端不得自行允许绕过硬条件。
- 引用扩展的批准范围、种子、预算与重审规则。

实际接口未接入前，不显示“已应用到研究”的成功提示。本轮只读页面无需提供模拟提交按钮；这些操作不是 A 当前投影工作的交付前提。

## 5. 失败、缺项与安全展示

请求错误、没有已批准计划、暂无候选、投影尚未生成、有效空结果、部分成功、取消及连接中断应可区分。关闭页面与切换 Session 沿用取消生命周期；断流不自动重启研究，也不等同于服务器失败。未知数据不填零；失败后保留此前已经确认的同级事实。仅展示安全的公开来源地址，不传 Provider 凭据、原始网页回答或内部诊断。

## 6. 交接与验收

1. C 使用现有固定 JSON 完成只读页面和中英文测试；A 审核本文并确定最小正式投影；B 确认元数据、评分、顺序与原因口径。
2. A 接入 B 的真实评估并提供运行投影；C 用正式数据替换固定输入，确认生产入口无样例回退。
3. 验证最小数量达标但目标未达、摘要不可用、全文未解析、硬过滤排除、低分排除、不同队列顺序、证据覆盖缺口、预算耗尽、部分失败和取消。
4. 检查同一用户提交只执行一次研究，旧快照不能覆盖新运行；后台补检不能偷偷改变批准范围；投影缺失明确展示。
5. 联合 Q7 验收，核对页面队列、批次、证据与 Session 记录的一致性，并录制实际 Web 演示。人工调整与引用扩展随后单独立项。

请 A 优先确认：正式投影的读取方式、候选展示资料关联、队列与覆盖的更新时间和版本、漏斗与批次的计数口径，以及本轮明确不支持的能力。C 在这些决定确认前仍可推进固定数据只读页面。
