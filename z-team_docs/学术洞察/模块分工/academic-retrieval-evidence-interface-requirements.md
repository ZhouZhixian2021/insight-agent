## 1. 一篇论文如何唯一标识？

建议系统为每篇论文生成稳定的内部 `paperId`。它是系统内关联、去重和引用论文记录的统一编号，不直接代替 DOI 等对外引用标识。

采用内部 ID 的原因是：部分论文没有 DOI，同一篇论文也可能同时出现在 arXiv、Crossref、OpenAlex 等来源中。系统用同一个 `paperId` 关联这些来源记录，避免把它们重复计为多篇论文。

DOI、arXiv ID、OpenAlex ID 等保存在可扩展的外部标识列表中。每项至少记录标识类型、规范化后的值和来源。新增 Semantic Scholar、PubMed 等 Provider 时，可以增加新的外部标识类型，不需要改变 `paperId` 或下游分析接口。

## 2. DOI、arXiv 与正式出版版如何关联？

同一研究工作的预印本、修订版和正式出版版归入同一个 `paperId`，每个具体版本保留独立的 `versionId`、外部标识、发布日期和来源。

对外展示和一般分析默认使用正式出版版；没有正式出版版时使用当前最新版本。旧版本不作为另一篇独立论文重复计数，但保留必要的版本和来源信息，以便核对分析实际使用的内容。

版本合并优先使用明确的 DOI、arXiv ID 或来源关系。仅通过标题、作者和年份判断相似时，应标记为疑似重复，不能直接自动合并。默认版本选择和人工确认方式由 A、B 共同确定。

## 3. 元数据、摘要和全文分别提供哪些信息？

| 可用材料 | 建议信息 |
|---|---|
| 元数据 | `paperId`、版本信息、标题、作者、日期、发表场所、发表状态、外部标识、来源链接、Provider 和抓取时间。 |
| 摘要 | 元数据，加摘要文本、语言和摘要来源。 |
| 全文 | 元数据和摘要，加正文或章节、页码或段落等原文位置、内容版本或哈希及提取状态。 |

不是所有来源都能提供全部字段。缺失值需要区分来源未提供、尚未提取、不适用和获取失败，不能用默认值或模型推测补齐。

证据等级表示系统实际获取到的材料范围，不评价论文质量：

- `metadata`：只获得论文元数据。
- `abstract`：已获得摘要，但没有可定位的全文内容。
- `fulltext`：已获取并解析正文，证据可以定位到章节、页码、段落、表格或图。

## 4. Evidence Record 应该包含什么？

第一版 Evidence Record 建议至少包含：

- `evidenceId`、`paperId` 和实际使用的 `versionId`。
- 证据内容或结构化陈述。
- `metadata`、`abstract` 或 `fulltext` 证据等级。
- 章节、页码、段落、表格或图等原文位置；无法定位时说明原因。
- 来源 URL、Provider、抓取时间和内容版本或哈希。
- 缺失字段、提取失败或质量提示。

一篇论文可以产生多条 Evidence Record。方法、数据集、指标、结果和局限等论文级汇总可以由 Evidence Card 表达，并通过 `evidenceId` 回指具体证据。请 C 审核第一版需要哪些结构化字段，避免证据模块提供的数据无法支持论文比较、趋势、冲突和报告引用。

## 5. 搜索和抓取失败如何表达？

检索和抓取结果建议明确区分成功、部分成功和失败。“没有搜索结果”属于成功但结果为空，不能用来表示请求失败。

失败信息至少记录 Provider、操作类型、错误类别、简要原因、是否可重试和建议重试时间。第一版错误类别建议覆盖参数错误、鉴权失败、限流、超时、网络错误、上游错误、未找到、解析失败和正文不可访问。

批量处理允许返回已成功的记录，同时逐项说明失败来源和原因，避免单条失败丢弃整批结果。程序配置错误和数据源运行失败的具体处理方式由 A、B 在服务接口中统一确定。

## 6. 如何支持以后新增数据源？

共享论文、证据和失败类型不绑定具体 Provider。每个 Provider 只负责把来源数据转换成统一字段，同时保留自己的来源名称、来源记录 ID、原始链接和抓取时间。

新增数据源时，主要增加对应 Provider 和字段转换规则；论文去重、Evidence Record 及下游分析继续消费统一类型，不需要为每个来源分别修改。
