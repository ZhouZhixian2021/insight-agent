# upgrade-kit

> 历史原稿：数量、路径、命令和实施状态保留当时背景。当前使用请从 [上游合并资料](../../00-目录.md) 进入，勿用历史工具覆盖仓库现行实现。

上游升级解耦方案的落地件，配套设计文档：[../upgrade-strategy-b.md](../upgrade-strategy-b.md)。

## 内容

| 文件 | 作用 |
|---|---|
| `verify-upstream-overrides.mjs` | 白名单门禁：未登记的上游文件修改 / 过期登记 / 预算超限 / 字段未填 |
| `upstream-overrides.json` | 白名单，按当前差异自动生成（157 fork + 12 generated + 6 wiring） |

脚本零依赖，只需 Node 20+ 与 git。所有 git 调用的输出写入临时文件而不是管道，因此在受限 shell 里也能跑。

## 安装

```sh
mkdir -p scripts/upgrade
cp upgrade-kit/verify-upstream-overrides.mjs scripts/upgrade/
cp upgrade-kit/upstream-overrides.json scripts/upgrade/
```

`package.json` 增加：

```json
"upgrade:check": "node scripts/upgrade/verify-upstream-overrides.mjs",
"upgrade:check:strict": "node scripts/upgrade/verify-upstream-overrides.mjs --strict"
```

## 用法

```sh
pnpm run upgrade:check                 # PR 门禁：只拦"新增未登记的上游文件修改"
pnpm run upgrade:check:strict          # owner/reason 填完后切这个
node scripts/upgrade/verify-upstream-overrides.mjs --list-generated   # 升级第 3 步用
node scripts/upgrade/verify-upstream-overrides.mjs --json             # 机器可读报告
```

退出码：`0` 一致、`1` 有违规、`2` 环境或参数错误（不是对代码的判断）。

## 首次启用要做的事

1. 把 175 条的 `owner` 填成负责人，`reason` 写成"为什么不能走生成器/接线层"；
2. 按设计文档 P1 先把 12 个 `generated` 条目降级（升级时取上游 + 重跑生成器），随后删除这些条目；
3. `reason` 填完再把 CI 切到 `--strict`。

## 校验过的行为

- 对当前仓库：`modified 175 / registered 175 / fork 157`，退出码 0；
- 删掉一条登记后：`VIOLATION unregistered-modification: packages/plan/plan-mode/src/index.ts`，退出码 1；
- 恢复后：重新退出码 0。
