## 实际实现

一级草稿完成后，用户可从保留有效一级证据的已抽取论文中选择一篇，使用真实 Session、检索运行和论文版本身份调用 `academicResearch.enhanceEvidence`。请求前读取已有选择；同步点击锁防止双击，已有持久选择不允许重复启动。

页面区分本地处理中、完成、部分成功、失败、取消和未确认终态，展示服务器返回的新增数量与未完成片段。原报告、质量状态和 Markdown 下载保持不变；增强不自动重新生成报告或授予审核通过。

新增证据通过既有 Session `follow` 快照及 `page` 分页读取。投影限定当前运行的选择与结算序号、论文版本及 `purpose: enhancement`，展示实际保存的证据 ID、陈述、摘录、等级和定位，不根据计数生成内容。失败结算记录零新增时，也保留可读取的先前已提交片段。

重新打开页面恢复持久选择与结算；没有结算的选择显示未确认，不能推断正在执行或允许重试。关闭页面取消本次增强 RPC，并忽略迟到响应；与独立后台研究关闭后继续的生命周期不同，界面明确提示。

## 修改范围与限制

业务改动仅涉及 C 的学术客户端、对应测试、文档及演示，不修改 Academic Model、Provider、Controller、Workflow、根配置或锁文件。

最新 master 的两个增强类型缺少目录链接，两个增强事件未进入生成的已知事件表；完整文档检查因此有三项失败，冷启动读取也会受事件表影响。本次补充文档类型链接并通过生成器刷新目录、模型可查的 API 目录和已知事件表。这是机械登记修复，单独列出便于 A 集成审核，不改变核心业务或事件格式。

增强接口不是独立后台任务；关闭会取消 RPC，已保存证据与原草稿保留。界面不自动轮询或伪造进度，使用显式读取确认新事实。Session 全量历史通过既有分页读取，长会话可能增加初始读取时间。

重点结论、关键数字与冲突的独立审核、增强后报告重生成以及真实模型的一篇论文联合验收仍按团队分工推进，本次不扩大后端接口。
