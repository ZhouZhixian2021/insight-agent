# Academic 证据抽取恢复与阶段状态

## 背景

真实网页验收已经证明多来源检索与两篇论文全文获取成功，但逐篇模型抽取仍出现两类失败：回答达到 16,384 token 输出上限，以及逐字引文内容存在但模型填错片段序号。原页面只显示整轮 `retrievalRun.status`，把后续抽取失败呈现成“检索结果失败”。

## 本次完成

1. A 的模型调用增加显式有界尝试策略。Web 组合默认每篇最多两次，只有 `max-tokens` 结束会重试一次；其他错误、取消及持久化失败不重试。
2. 每次模型尝试分别保存请求和结果，并记录当前尝试序号及总上限。
3. B 的逐字证据核验保持严格匹配。模型给出的有效片段序号指错位置时，只在原引文于全部片段中恰好唯一逐字出现时纠正；歧义、Unicode/公式规范化和 OCR 差异继续拒绝。
4. Controller 返回来源检索、全文获取、证据抽取三个由生产方结算的状态。
5. C 的 Web 页面分别显示三个阶段，并把原“检索结果”改为“研究处理结果”，避免把证据抽取失败误解为来源检索失败。

## 边界

- 没有提高默认 16,384 token 输出上限。
- 没有加入模糊引文匹配或 OCR 自动修正。
- 没有实现长论文分段、跨运行续跑、自动追加查询或自动发布。
- 没有修改 Academic Model A1–A5 的业务字段语义；新增字段属于浏览器安全 Remote 投影。

## 验证

- 受影响包完整测试：15 个文件、231 个测试通过。
- TypeScript 类型检查通过；GUI 测试 295 个文件、4,040 个测试通过，1 个跳过。
- Academic 证据快照刷新并回放通过；文档快速门禁 15/15、工作区约束、配置目录、Cordis 目录、类型等价、双语配对、Agent Note 格式与分类和导出 JSDoc 均通过。
- 完整无密钥 Web 回放因本机缺少 Playwright 自带 Chromium 无法启动浏览器；改用本机 Edge 定向回放 Academic Web，1 个文件、1 个测试通过。这是测试环境限制，没有修改产品代码绕过。

## 真实 Web 复验

- 重启正式 DSH Web 后，先按旧交接文档输入两条宽泛关键词。两个来源共返回 20 条记录、跨查询去重 10 篇，但前 5 个候选均未通过基于 `first_public_release` 的严格范围筛选，因此来源检索显示成功，全文获取和证据抽取显示未运行。这验证了新增阶段状态不会把候选筛选为空误写成检索失败。
- 随后按团队已经确认的第一版规则输入精确 arXiv 编号 `1706.03762` 与 `1810.04805`。本轮两个来源对两条查询均在各自两次传输尝试后返回 `network_error`；页面如实显示来源检索失败、全文和抽取未运行，并保留 4 条失败记录。
- 在工作流之外直接检查同一网络出口：连接 `export.arxiv.org:443` 在约 21 秒后失败，OpenAlex 在 30 秒后连接超时，均未建立 HTTP 连接。当前真实复验阻塞于本机到外部学术 API 的网络可达性，不是查询解析、全文获取或模型抽取错误。代码不增加无界重试或平台绕过；网络恢复后仍使用两个精确编号复验模型恢复逻辑。
