# 开发记录：A-PE4 跨模块固定验收

## 范围

成员 A 在已合并 B-PE1～B-PE3、C 的审批／报告消费和二级增强页面、A-PE3 正式接线的基础上，固定三题跨模块验收输入。三题为 RAG 与幻觉、Transformer 与 BERT、Agent 研究现状与未来发展。第三题中的未来判断必须与已观察事实区分；本次夹具不产生任何真实学术结论。

## 本轮完成

- 新增工作流级合成矩阵：每题走过检索结果摄取、HTML 全文解析、逐字证据核验、问题关联、分析合成和草稿评测。一篇有有效证据、另一篇抽取失败时，已核验证据和有限草稿保留，未获证据的问题保持未回答。
- 零有效证据场景确认不会调用报告合成，也不会生成报告。
- 核对 Controller 的一级最小深度接线及所选论文二级增强契约，并与 C 的 Web 增强恢复测试一起运行聚焦回归。
- 更新正式双语交付计划和子系统说明，记录当前已经接通的路径及尚未完成的真实验收。

## 本地检查

- 工作流、Controller、一级交接与 Web 增强四个聚焦测试文件共 92 项通过；三题矩阵和零证据用例在其中占 4 项。
- 工作流包 TypeScript 构建、变更测试文件 lint、双语配对、Agent Note 格式与分类、Markdown 链接与换行、文档预算及 `git diff --check` 通过。
- 本轮没有运行真实模型、学术源检索或 Web 全程研究，也没有测量调用量与耗时。

## 验收边界与后续

上述三题是脚本化来源与模型响应，不是三轮真实审批、真实检索和真实模型研究。固定测试只能证明模块交接和失败处理；不能证明论文筛选质量、结论语义正确、用户审批计划与执行数据一致，或二级增强在真实论文上的效果。团队仍需以三题分别完成真实运行，逐题核对批准问题、可定位证据、缺口、报告正文和增强结果。B-PE4 尚无同论文的一级／完整深度调用量、token、耗时和有效证据基线，因此不填写提速结论。
