# 开发记录：聊天研究来源异常排查

## 范围

对照本机修改前的 Mixup／CutMix 成功研究、修改后的两次失败研究及当前调用代码，检查 C 是否改变请求、重复启动或取消后台任务。真实 Session、响应正文和诊断脚本保留在 Git 忽略的私有目录，不纳入源码。

## 已确认事实

- 两次失败研究分别对应两次批准的计划，每个计划只有一个后台任务；阶段快照不是重复启动。每轮按既定三条查询分别访问三个渠道，保留九项失败记录。
- 聊天卡与旧弹窗使用相同 startBackgroundRun 入口及 Session、批准 Brief、synthetic: false 请求。C 没有修改来源实现、查询改写、Controller、代理安装器或搜索密钥。
- 旧成功研究也有三次 Web 发现失败，依靠学术来源继续生成了报告；不能把生成过报告等同于全部来源成功。
- 新记录中 Web 在计划阶段已经返回官方接口 HTTP 401，提示当前搜索密钥无效，早于聊天卡发起后台研究。聊天模型所选接口与内置 Web 搜索的认证和端点相互独立。
- 不带密钥的同一最小 OpenAlex 查询，直连返回 HTTP 429，响应明确指出出口 IP 的共享日预算耗尽；通过本机现有代理返回 HTTP 200。
- 使用 Harness 自身 installProxyFromEnvironment 和实际 OpenAlexProvider／ArxivProvider，各执行一次有界最小查询，两者均成功返回一条记录；不是仅根据浏览器或 curl 推断来源恢复。

## 本地处理

在 Git 忽略的项目私有 Harness-home 环境文件中补充 HTTP_PROXY 和 HTTPS_PROXY，使用已经验证的本机代理。保留原有配置，不更改操作系统代理、其他来源实现或账号凭据。使用正式启动环境加载器验证配置来自 user-env，策略无诊断错误；启动器自动保留本地回环地址直连。

该配置需要重启 Harness 后生效。已结束的空结果任务保持原样，不伪造成成功，也不自动重跑。Web 的 HTTP 401 尚未修复，需要有效的搜索凭据或受支持的正确端点；没有复制聊天模型密钥去尝试其他未知服务。学术来源最小查询通过不等于完整报告已通过端到端验收，本次没有再次调用模型或运行整轮研究。
