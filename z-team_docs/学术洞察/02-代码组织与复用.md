# 学术洞察代码组织与复用

[返回目录](00-目录.md) · [完整代码导航](01-代码导航.md)

学术洞察的业务逻辑、后台接口、页面和接入配置统一放在 [packages/academic](../../packages/academic/) 下，共 19 个独立代码包。团队维护时从这个目录进入，完整接入时使用其中的 `bundle`，单项能力仍可按包复用。

```text
packages/academic/
├── bundle/               接入配置、研究指令和技能模板
├── research-controller/  后台接口、计划审批和任务管理
├── client-remote/        浏览器学术接口注册
├── ui-research/          页面、进度、证据和报告展示
├── workflow/             研究流程、补证据与恢复
├── model/                公共字段和数据规则
├── source/、source-*/    来源管理与各学术来源
├── ingestion/、retrieval/ 论文整理、检索和筛选
└── evidence/、analysis/、eval/、report/ 证据、分析、评测和报告
```

## 1. 修改功能时去哪里

| 层次 | 代码位置 | 负责什么 |
| --- | --- | --- |
| 业务逻辑 | [packages/academic](../../packages/academic/) | 检索、论文处理、证据、分析、报告、领域勘察和循环补证据等逻辑；共享字段在 model，主流程在 workflow。 |
| 后台接口 | [academic-research-controller](../../packages/academic/research-controller/) | 接收页面操作，连接会话、任务状态和业务流程。 |
| 页面 | [ui-academic-research](../../packages/academic/ui-research/) | 研究计划、审批正文、模式文案、运行进度、报告、证据和追踪信息展示。 |
| 浏览器接口注册 | [client-remote](../../packages/academic/client-remote/README.zh.md) | 将学术接口挂载到公共 Remote 传输，不再从公共 Remotes 包导入学术业务。 |
| 统一接入 | [academic bundle](../../packages/academic/bundle/README.zh.md) | 声明加载哪些来源、后台和页面，以及使用什么默认配置、研究指令和技能。 |

目录集中后，各包仍保留自己的依赖、构建和测试。页面使用公共浏览器构建配置，后台使用 Host 构建；原有包名和接口名称不变，具体文件见代码导航。

## 2. 这次集中整理了什么

- 后台、页面和接入包分别归入 `research-controller`、`ui-research` 和 `bundle`，对应源码、测试、说明与资源一起移动。
- 同步更新工作区依赖、类型引用、浏览器构建入口、实验脚本和代码导航；页面检查继续覆盖迁移后的目录。
- 学术来源和研究控制器的默认配置移至 [cordis.patch.yml](../../packages/academic/bundle/cordis.patch.yml)。
- 学术页面注册移至 [web.patch.yml](../../packages/academic/bundle/web.patch.yml)。
- 学术预设、计划指令和技能模板移至 [presets](../../packages/academic/bundle/presets/)。领域勘察的现有本地内容随文件保留。
- [package.json](../../packages/academic/bundle/package.json)统一声明学术接入所需依赖和随包发布的资料。
- 公共 Web 包移除了对应学术注册与直接依赖；默认 Web 配置组合单独加载学术包，现有 `pnpm run insight:web` 命令保留。

目录迁移保留业务算法、接口名称、配置行标识和历史会话格式。架构图由另一个会话维护，本次没有修改。

## 3. 如何复用

在版本匹配的 Harness 项目中，以整个 `packages/academic` 目录及其工作区声明作为源码复用范围，并保留各包声明的公共框架依赖。接入时在 `dsh.profile.bundles` 中按顺序组合公共基座、Web、学术三个包。具体字段和启动核对方法见[接入包说明](../../packages/academic/bundle/README.zh.md)。单独复制目录到空项目仍不能直接运行，需要匹配框架、构建工具和依赖。

如果只复用某项算法，应从对应业务包的公开入口调用。脱离 Harness 复用完整研究流程，还需适配模型调用、来源服务、会话保存及任务状态；此次没有完成独立于框架的运行环境。

旧的默认 Web 组合在加载时自动加入学术包。含自定义层的配置列表不会自动改写，按[迁移说明](../../docs/upgrade-guide/v0.2.1-rc.2/academic-bundle/guide.zh.md)加入学术包，并把本地覆盖层保留在它后面。

## 4. 更新上游时重点检查哪里

运行接入集中在 [CLI 依赖](../../apps/cli/package.json)和 [Web 配置组合及旧默认组合迁移](../../packages/boot/app-boot/src/profile.ts)。项目引用、依赖锁文件和文档规则仍需认识新增包。以后新增学术来源、调整研究额度或提示词，优先修改学术接入包，避免重新写入公共 Web 配置。

公共问答模块保留通用正文插槽，公共模式模块保留文案登记接口，Gateway 保留 Remote 传输；三处均不再包含学术格式判断或学术文案。历史学术事件以及既有基础服务适配仍有跨包连接，因此不能承诺上游更新完全没有冲突。上游差异登记继续由 [scripts/upgrade](../../scripts/upgrade/README.zh.md)管理；新功能合入前还需核对记录与实际差异。

## 5. 验证入口

[组合测试](../../packages/academic/bundle/tests/composition.spec.ts)检查默认启用、纯 Web 不加载学术功能、旧默认配置迁移及自定义配置保护。[Web 预设端到端测试](../../apps/cli/tests/web-agent-presets.e2e.ts)通过真实 Loader 检查学术技能读取与计划审批。构建、文档检查和针对性测试的实际结果以本次开发记录为准。
